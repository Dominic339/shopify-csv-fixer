## CSV のインポートが失敗する理由

どの EC プラットフォームも、CSV を受け付ける前に一連の検証にかけます。構造（見出し、列数）、データ型（数値、はい/いいえの値、必須項目）、ビジネスルール（有効なカテゴリコード、価格の範囲）、文字コードを確認します。どれか 1 つでも通らないと、インポートは完全に止まるか、一部の行だけを取り込んで残りを飛ばします。

エラーメッセージを理解することが、きれいなインポートへの近道です。このガイドでは、よくあるものを解説します。

---

## 構造のエラー

これらのエラーは、プラットフォームがデータを見る前の段階で、ファイルの形が間違っていることを示します。

### 「Missing required column」/「Column not found」

プラットフォームが求める列名が、見出し行にありません。よくある原因：

- 必須の列名を変えてしまった（`Title` ではなく `product_title` など）
- 見出しの先頭や末尾にスペースがある（`Title` ではなく ` Title`）
- ファイルに BOM があり、最初の列名の前に見えないバイトが付いている
- 別のプラットフォームのテンプレートを使っている

**対処法**：見出し行をそのプラットフォームの公式テンプレートと比べます。大文字・小文字、つづり、スペースまで完全に一致している必要があります。

### 「Column count mismatch」/「Wrong number of columns」

データ行の項目数が、見出し行より多いか少ない状態です。よくある原因：

- 値に引用符なしのカンマがある：`Wallet, Brown` は `"Wallet, Brown"` にする必要があります
- 引用符で囲んでいない HTML の説明にカンマがある（`style` 属性の中など）
- 一部の行の末尾に余分なカンマがある（存在しない列ができてしまう）

**対処法**：ファイルをテキストエディタで開き、問題の行を見ます。引用符で囲んだ値の中のカンマは列を区切らないことに注意して、項目を数えます。カンマを含む値はすべて二重引用符で囲みます。

### 「Unexpected header」/「Unrecognized column」

プラットフォームが認識できない列がファイルにあります。プラットフォームは余分な列を無視するので、たいていはインポートを止めない警告です。ただし、より厳しいインポート機能は知らない列を拒否することがあるので、はっきりした理由なく失敗するときはプラットフォームのテンプレートを確認します。

**対処法**：公式テンプレートにない列を削除するか、列名のつづりを変える必要がないか確認します。

## 必須項目のエラー

### 「Required field is blank」/「Field cannot be empty」

必須の列は見出しにありますが、1 行以上で値が空です。空になりがちな必須項目：

- **Shopify**：すべての行の Handle と、各商品の最初の行の Title
- **WooCommerce**：新しい商品の Name と、バリエーションの行の Parent
- **Etsy（一括出品アプリ）**：アプリのテンプレートが必須としている項目。who_made、when_made、is_supply が多い
- **eBay**：Action と、出品を追加するときの Title、Category、StartPrice、ConditionID
- **Amazon（Inventory Loader）**：sku、product-id、product-id-type、add-delete と、出品を追加するときの price、item-condition、quantity

**対処法**：ファイルを絞り込むか並べ替えて、必須の列が空の行を見つけ、足りないデータを入れます。空欄が意図的な場合（バリエーションの行が商品の値を引き継ぐなど）は、プラットフォームのルールを確認します。たとえば Shopify では、バリエーションの行の Title は空でかまいません。

### 「SKU is required」

ファイルによっては、商品を SKU で識別します。Amazon の Inventory Loader は常にそうで、ほかのプラットフォームの更新インポートも SKU で行を対応付けることがよくあります。そうしたファイルでは、SKU のない行は失敗します。

**対処法**：SKU が必要な行にはすべて SKU を入れます。英数字のみ、スペースなし、プラットフォームの上限以内（Amazon は 40 文字）という一貫した形式にします。

## データ型と書式のエラー

### 「Invalid price」/「Price must be a number」

価格の項目に数値ではない値が入っています。よくある原因：

- 値に通貨記号が付いている：`19.99` ではなく `$19.99`
- 小数点にカンマを使っている：`19.99` ではなく `19,99`（ヨーロッパの地域設定でよく見られます）
- 数値が必要なところが空の文字列やダッシュになっている
- Excel がセルを通貨の表示形式にして、記号ごと書き出した

**対処法**：通貨記号を取り除き、小数点のカンマをピリオドに変えます。保存する前に、Excel で列の表示形式を「数値」にします。

### 「Invalid boolean」/「Must be true or false」

はい/いいえの項目に想定外の値が入っています。プラットフォームはこの形式に厳しいです。

- **Shopify**：Shopify のテンプレートどおり `true` か `false` を求めます
- **WooCommerce**：`1` / `0` を使います（`Backorders allowed?` などの項目は `notify` も使えます）
- **Amazon**：ファイルによって異なります。カテゴリテンプレートは Valid Values タブの値（多くは `true` / `false`）を使い、Inventory Loader の `will-ship-internationally` は `y` / `n` または `1` / `2` を使います

**対処法**：あらゆる書き方（Yes、yes、Y、1、true）を、各プラットフォームが求める形式に置き換えます。スプレッドシートの検索と置換を使います。

### 「Invalid date format」

日付の項目の形式が間違っています。ほとんどのプラットフォームは `YYYY-MM-DD` を求めます。Excel は日付を `2024/1/15` のような地域の形式に自動で変えることがよくあります。

**対処法**：編集する前に Excel で日付の列をテキスト形式にするか、型を変換しない Python の `csv` モジュールを使います。保存する前に日付を `YYYY-MM-DD` に変換します。

## ビジネスルールのエラー

### 「Duplicate SKU」/「Handle already exists」

一意であるべき識別子が、ファイル内に 2 回以上出てきます。Shopify では、バリエーションのために同じ Handle を意図的に繰り返しますが、関係のない 2 つの商品グループに同じ Handle があればエラーです。WooCommerce と Amazon では、SKU の重複は必ず問題を示します。

**対処法**：識別子の列でファイルを並べ替え、意図しない重複を探します。数式（`COUNTIF`）を使えば、完全な重複を自動で見つけられます。

### 「Invalid category ID」/「Category not recognized」

使ったカテゴリコードが、プラットフォームの分類に存在しません。

- **eBay**：カテゴリ ID は数字で、eBay の現在のカテゴリツリーにあるものでなければなりません
- **Amazon**：ブラウズノードと商品タイプは、セラーセントラルの現在の分類と一致しなければなりません
- **Etsy（一括出品アプリ）**：分類 ID は Etsy の API から来るもので、現在の一覧と一致しなければなりません

**対処法**：正しいカテゴリ ID を、プラットフォームの公式カテゴリ一覧や分類のダウンロードで調べます。ID は変わるので、古いテンプレートの ID は使わないでください。

## インポート結果の警告と、インポートを止めるエラー

ほとんどのプラットフォームは、**インポートを止めるエラー**（行やファイルが拒否される）と**警告**（行は取り込まれるが、印が付く）を区別しています。違いを理解すると、直す順番を決めやすくなります。

| 重大度 | 意味 | 例 |
|---|---|---|
| 停止 | 行やファイルが飛ばされる | 必須項目の欠落、列数の誤り |
| 警告 | 印付きで取り込まれる | 認識できない任意の項目、長い説明 |
| 情報 | お知らせのみ | 項目にプラットフォームの既定値が入った |

再アップロードの前に、インポートを止めるエラーはすべて直します。警告は 2 回目の作業で対応してもかまわないことがよくあります。
