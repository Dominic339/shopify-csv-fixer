## なぜ起こるのか

Excel は財務データ向けに作られています。セルの値が数値に見えると、数値の形式に変換します。これが EC 向けの CSV では 2 つの問題を起こします。

1. **指数表記**：`4006381333931` のような 13 桁の EAN（JAN）バーコードが `4.00638E+12` になります。CSV に書き出すと `4.00638E+12` と書き込まれ、バーコードとして無効になります。
2. **先頭のゼロが消える**：`00714` のような SKU が `714` に、`01234565` のような 8 桁の EAN-8 が `1234565` になります。インポート先は間違った値を受け取ります。

これらの変換は黙って行われます。インポートが失敗したり在庫数が合わなくなったりするまで、気づかないこともあります。

---

## 影響を受ける項目

長い数字の並びや先頭のゼロを含む項目は、どれも危険があります。

- **バーコード**：EAN-13（JAN）、UPC-A、EAN-8、ISBN-13、ASIN
- 先頭にゼロがある **SKU**（アパレルや工具のカタログでよく見られます）
- メーカーの品番を引き継いだ **バリエーションの SKU**
- Shopify の **Variant Barcode** 列
- **Amazon の ASIN / FNSKU**（英数字ですが、一部が数字だけのこともあります）
- WooCommerce の **SKU** 列

## 予防：データを入力する前に列を文字列にする

いちばん安全なのは、何かを入力したり貼り付けたりする前に、列を **文字列** にしておくことです。

### Excel の場合（新しいシート）

1. バーコードや SKU を入れる列全体を選択します（たとえば、列番号 `C` をクリックして C 列を選択）。
2. 右クリック → **セルの書式設定**。
3. **分類** の一覧で **文字列** を選びます。
4. **OK** をクリックします。
5. ここで値を入力するか貼り付けます。Excel はそれを文字列として扱い、そのまま残します。

> **重要**：数値を入力した*あと*でセルを文字列にしても、変換は元に戻りません。先に書式を設定し、それからデータを入力する必要があります。書式を設定済みの列に貼り付けるときは、元の数値の書式を持ち込まないよう、**値のみ** を貼り付けます（Ctrl+Shift+V、または形式を選択して貼り付け → 値）。

### Excel の場合（先頭にアポストロフィを付ける）

セル単位でのすばやい方法として、数値の前にアポストロフィ（`'`）を入力します。

```
'4006381333931
```

Excel は `'` で始まる値をすべて文字列として扱います。アポストロフィはセルの値には保存されず、数値だけが保存されます。セルごとには使えますが、大量のデータには手間がかかります。

## 既存のファイルを直す：インポートウィザードで CSV を開く

すでに Excel にバーコードを壊された CSV がある場合は、ダブルクリックで開かず、インポートウィザードを使います。

### Excel 2016 以降（取得と変換）

1. 空のブックを開きます。
2. **データ → テキストまたは CSV から** を選びます。
3. CSV ファイルを選びます。
4. プレビューが表示されます。バーコードや SKU の列を確認し、指数表記になっていれば、型が自動で「整数」と判定されています。
5. **データの変換** をクリックします（Power Query エディターが開きます）。
6. 対象の列を選択します。
7. **ホーム** タブの **データ型** の一覧で **テキスト** を選びます。Power Query に聞かれたら **現在のものを置換** をクリックします。これで、型の変更が自動の数値変換に置き換わり、元の数字が残ります。
8. 閉じて読み込みます。
9. **ファイル → 名前を付けて保存 → CSV UTF-8** で CSV に書き出し直します。

### Excel の場合（従来のテキストファイルウィザード）

従来のウィザードが使える場合：

1. **データ → テキストから** を選ぶか、ファイルの拡張子を `.csv` から `.txt` に変えてから **ファイル → 開く** で開きます。これでウィザードが始まります。
2. ウィザードの **ステップ 3** で列を選び、データ形式を **文字列** にします。
3. インポートを完了します。

## 保存済みの CSV の指数表記を直す

すでに `4.00638E+12` のような値が入った CSV ファイルがある場合：

### 方法 A：値を入力し直す（小さなファイル）

CSV ファイル自体に `4.00638E+12` と書かれてしまうと、足りない桁はもうファイルの中にないので、テキストエディタでは元に戻せません。手元の記録から正しい値を入力し直すしかなく、それが現実的なのはせいぜい数行です。

### 方法 B：元のデータから作り直す

元のデータがデータベース、PIM、仕入れ先のファイルにあるなら、Excel で開かずに書き出し直します。多くの仕入れ先ポータルは `.xlsx` でダウンロードできます。それを開いて列を文字列にしてから、CSV で保存します。

### 方法 C：数式で文字列に戻す

ブックがまだ Excel で開いている（または .xlsx で保存してある）場合、Excel はまだ `4006381333931` のような完全な数値を保持していて、指数表記で表示しているだけのことがあります。

1. 補助列を追加します。
2. `=TEXT(A2, "0")` で、数値を指数表記のない文字列に変換します。
3. 補助列をコピーし、元の列に **値** として貼り付けます。
4. 補助列を削除します。
5. CSV で保存します。

> これは Excel がまだ完全な数値を保持している場合にしか使えません。値が切り捨てられている（有効桁数が 15 桁を超える）場合、精度は完全に失われているので、元のデータを入手し直す必要があります。

## Google スプレッドシートの場合

Google スプレッドシートにも同じ数値変換の問題があります。

- **貼り付ける前に書式なしテキストにする**：列を選び、**表示形式 → 数字 → 書式なしテキスト**。
- **ファイル → インポートで取り込む**：インポートの画面で **テキストを数値、日付、数式に変換する** のチェックを外し、コードが文字列のまま残るようにします。取り込んだあと、バーコードが正しいか確認します。
- **既存の値を直す**：Excel と同じく `=TEXT(A2, "0")` を使います。

---

## Excel から CSV に安全に書き出す

列を直すか正しく書式設定したら、次のようにします。

1. **ファイル → 名前を付けて保存 → CSV UTF-8 (コンマ区切り) (.csv)**。
2. この形式では複数のシートを保存できないと警告されることがあります。**はい/現在の形式を維持** をクリックします。
3. **確認のために CSV を Excel で開き直さない**：テキストエディタ（VS Code、Notepad++ など）で、バーコードが指数表記ではなく普通の数字になっているか確認します。
