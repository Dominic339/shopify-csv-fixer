## インポート前の検証が大切な理由

CSV のインポート失敗は、無害なもの（何も変わらない）から破壊的なもの（一部だけ更新されてカタログの整合性が崩れる）まであります。Shopify では、引用符のエラーがあるとたいていインポート全体が止まり、失敗した行が示されます。WooCommerce では、列がずれた行が既存の商品に誤った値を書き込むことがあります。

アップロード前の 5 分の確認で、何時間もの後始末を防げます。

---

## インポート前のチェックリスト

### 1. エンコーディング：UTF-8

**確認すること：** ファイルは UTF-8 でエンコードされている必要があります。先頭の BOM（バイトオーダーマーク）は Shopify と WooCommerce では問題ありませんが、ツールによっては最初の列名の一部として読み込まれます。

**確認方法：**
- VS Code でファイルを開きます。右下のステータスバーに `Windows 1252` や `ISO 8859-1` ではなく、`UTF-8`（または `UTF-8 with BOM`）と表示されているはずです。
- 別の表示なら、まず文字が正しく表示されているか確認します（崩れている場合は、エンコーディング表示をクリックし、ファイル本来のエンコーディングで **エンコード付きで再度開く** を選びます）。そのあと表示をもう一度クリックし、**エンコード付きで保存 → UTF-8** を選びます。

**よくある対処：** Excel では、通常の CSV ではなく、必ず **CSV UTF-8（コンマ区切り）** で保存します。

---

### 2. ヘッダー行：正しい名前、余分なものなし

**確認すること：**
- 1 行目に、プラットフォームが求めるとおりの列名が入っている。
- 列名の前後に空白がない。
- 列名が重複していない。
- 末尾に余分な空の列がない。

**確認方法：**
テキストエディタでファイルを開き、1 行目を注意深く読みます。プラットフォームの公式テンプレートと比べます。

- Shopify：[Shopify の商品 CSV テンプレート](https://help.shopify.com/en/manual/products/import-export/import-products) を確認します。
- WooCommerce：管理画面から入手できる WooCommerce のサンプル商品 CSV と比べます。
- Amazon：セラーセントラルから在庫ファイル（Inventory Loader）またはカテゴリ別テンプレートをダウンロードします（**カタログ → アップロードによる一括商品登録**）。

**よくある問題：**
- 末尾に空白がある `"Handle "`（Excel では見えません）。
- `Handle` ではなく `handle`（小文字）。
- 必須列がまるごと欠けている。

---

### 3. 必須列：すべてそろっていて空でない

**確認すること：**
- プラットフォームの必須列がすべてヘッダーにある。
- どの行でも必須フィールドが空でない。

**プラットフォーム別の必須フィールド（最小限）：**

| プラットフォーム | 必須列 |
|---|---|
| Shopify | Title（既存商品を更新する場合は Handle も） |
| WooCommerce | Name、Type（既存商品を更新する場合は ID または SKU も） |
| eBay File Exchange | Action、Title、Category、StartPrice、ConditionID |
| Amazon Inventory Loader | sku、product-id、product-id-type、price、item-condition、quantity、add-delete |
| Etsy | CSV アップロードなし：Etsy は CSV のエクスポートのみなので、インポート用に検証するものはありません |

**Excel での確認方法：**
1. フィルタを有効にします（**データ → フィルター**）。
2. 必須列ごとに空白セルで絞り込みます。
3. 必須フィールドが空の行は、その行のインポートが失敗します。

---

### 4. 行の長さをそろえる

**確認すること：** すべての行の列数がヘッダー行と同じである必要があります。列数が違う行は、次のことを示しています。
- エスケープされていないコンマを含む説明やタイトル。
- 改行を含むフィールドが、1 行を複数行に分けている。
- コピー＆ペーストの誤りで余分な列が入った。

**Excel での確認方法（長すぎる行）：**
1. 最後のヘッダーの次の列を確認します。ヘッダーが T 列で終わっていれば U 列です。
2. 右端の空いている列（たとえば AAA 列）に `=COUNTA(U2:ZZ2)` を入力します。
3. 全行にコピーし、0 より大きい値で絞り込みます。その行には余分なフィールドがあります。

短すぎる行は Excel では見つけられません。欠けたフィールドは空のフィールドと同じに見えるからです。

**テキストエディタでの確認方法：**
Rainbow CSV 拡張機能を入れた VS Code で、**Rainbow CSV: CSVLint** コマンドを実行します。ヘッダーとフィールド数が違う行を、短い行も含めてすべて報告します。

**よくある対処：** コンマ、引用符、改行を含むフィールドはダブルクォートで囲みます。フィールド内にすでにダブルクォートがある場合は、1 つずつ 2 つ重ねてエスケープします（`""`）。

---

### 5. 引用符で囲んだフィールド：正しい囲み方とエスケープ

**確認すること：**
- コンマ、ダブルクォート、改行を含むフィールドがダブルクォートで囲まれている。
- 囲んだフィールド内のダブルクォートは、2 つ重ねてエスケープされている（`\"` ではなく `""`）。

**正しい囲み方の例：**
```
Handle,Title,Body HTML
blue-shirt,"Blue T-Shirt, Men's","<p>""Premium"" cotton.</p>"
```

**注意する点：**
- `"` で始まるフィールドは、同じ論理行のなかで `"` で終わる必要があります。
- アポストロフィはエスケープ不要です。`Men's` はそのままで構いません。重ねるのはダブルクォートだけです。

---

### 6. キーとなるフィールドに使えない文字がない

**確認すること：**
- Handle やスラッグには、小文字の英字、数字、ハイフンだけが使われている。
- 価格フィールドには数字と小数点だけが入っている（通貨記号や桁区切りなし）。
- はい/いいえのフィールド（例：Published、Featured）は、プラットフォームに応じた値（TRUE/FALSE、yes/no、1/0）を使っている。

**よくある問題：**
- 価格列の `$19.99`（`19.99` にします）。
- Handle 列に大文字と空白を含む `Blue Shirt`（`blue-shirt` にします）。
- `19.99` ではなく `19,99` のような価格（ヨーロッパ式の小数点コンマ）。

---

### 7. 画像 URL：アクセスでき、形式が正しい

**確認すること：**
- 画像 URL が `https://` で始まっている（`http://` の画像を拒否したりスキップしたりするプラットフォームもあります）。
- URL に空白が含まれていない（空白は `%20` にエンコードするか削除します）。
- Shopify の場合：1 商品あたり最大 250 件の画像 URL に対応しています。Handle ごとに最初の `Image Src` 行がメイン画像になります。
- URL が公開されている（ログインが必要な場所や localhost ではない）。

---

### 8. 末尾に空の行がない

**確認すること：** 多くの表計算ソフトは末尾に空の行を追加します。プラットフォームによっては空の行を無効な行として扱い、エラーになります。

**Excel での直し方：**
1. **Ctrl+End** を押して、最後に使われているセルに移動します。
2. 最後の行が空（すべてのセルが空）なら、その行から数行下までを選択して削除します。
3. ファイルを保存します。

## テストアップロードの進め方

最初のテストで 10,000 行のカタログ全体をアップロードしてはいけません。代わりに次のようにします。

1. CSV のコピーを作ります。
2. 代表的な 5〜10 行だけを残します（バリエーションのある商品があれば最低 1 つ含めます）。
3. サンプルをテスト環境またはステージング用ストアにアップロードします。
4. 各行が正しくインポートされたか確認します。
5. 完全なファイルのエラーを直します。
6. 完全なファイルをアップロードします。

Shopify の場合：インポートツールは確定前にプレビューを表示し、インポートが終わるとメールで知らせます。インポートが完了したように見えても、このメールを読んでください。一部の行がスキップされ、残りだけがインポートされることがあります。

## インポート前の検証に役立つツール

| ツール | 確認できること |
|---|---|
| **StriveFormats CSV Fixer** | プラットフォーム別のヘッダー、エンコーディング、必須フィールド、引用符、はい/いいえの値 |
| **Rainbow CSV 拡張機能を入れた VS Code** | 列のそろい方を視覚的に確認、ずれた行 |
| **csvkit（`csvclean`）** | フィールド数が合わない行（コマンドライン） |
| **Google スプレッドシートの ファイル → インポート** | 選んだ区切り文字で列がどう分かれるか |
| **Excel の データ → テキストまたは CSV から** | 読み込み前のエンコーディングと区切り文字のプレビュー |

検証ツールでは内容の誤り（間違った SKU、間違ったカテゴリ ID、もう表示されない画像 URL）は見つけられません。それにはテストアップロードが必要です。ただし、インポートの完了を妨げる構造上のエラーは検証ツールで見つけられます。
