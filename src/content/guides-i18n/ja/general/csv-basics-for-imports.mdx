## CSV ファイルとは

CSV（Comma-Separated Values、カンマ区切り値）ファイルは、各行が 1 件のレコードで、列がカンマで区切られたプレーンテキストのファイルです。1 行目には列名（見出し行）が入り、それ以降の各行にデータが入ります。

最小限の Shopify 商品 CSV は、テキストで見ると次のようになります。

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
red-shirt,Red T-Shirt,Acme,21.99
```

CSV は単純に見えますが、Shopify、WooCommerce、Etsy、eBay、Amazon などのプラットフォームは、スプレッドシートが知らないうちに壊してしまう書式の細部に厳しいです。このガイドでは、最初のインポートで問題なく通るよう、重要なルールをひとつずつ説明します。

---

## 見出し行

CSV の 1 行目には必ず列名（見出し）を入れます。プラットフォームはインポート時に、この名前を使ってデータを正しい項目に割り当てます。

### ルール

- **大文字・小文字も含めて正確に書く。** `Handle`、`handle`、`HANDLE` を別のものとして扱うインポート機能もあるので、見出しはプラットフォームのテンプレートからコピーします。
- **先頭や末尾にスペースを入れない。** `" Title"`（先頭にスペース）は `"Title"` と一致しません。その列のデータは何の警告もなく無視されます。
- **見出しを重複させない。** 2 つの列が同じ名前だと、ほとんどのパーサーは最後の列だけを使います。
- **列の順番が重要なプラットフォームもある。** eBay や Amazon の一部のテンプレートは、テンプレートどおりの列順を前提にしているので、ダウンロードしたテンプレートの順番を保ちます。Shopify は列をどこに追加してもかまいません。

### 確認方法

CSV をメモ帳（Windows）、テキストエディット（Mac）、VS Code などのテキストエディタで開き、1 行目を見ます。上に空行がなく、カンマで区切られた名前が並んでいるはずです。

```
Handle,Title,Body (HTML),Vendor,Type,Tags,...
```

1 行目の見出しの前に奇妙な 3 文字が付いている場合、そのファイルには BOM があります。直し方は下の文字コードのセクションを参照してください。

## UTF-8 エンコーディング

エンコーディング（文字コード）は、文字をディスク上でバイトとして保存する方法です。文字コードが合わないと文字化けします。たとえば UTF-8 で保存した曲がった引用符を Latin-1 として読むと、ごみのような 3 文字の並びに変わります。

### UTF-8 を使う理由

UTF-8 はどの EC プラットフォームでも安全な選択です。Shopify と WooCommerce は UTF-8 を前提としており、eBay の現行テンプレートは Action 見出しで UTF-8 を宣言しています（`CC=UTF-8`）。UTF-8 で保存すると、次のことが保証されます。

- 日本語やアクセント付きの文字が正しく表示される。
- 通貨記号や特殊な記号が壊れない。
- プラットフォームのインポート機能がファイルを拒否せずに読める。

### BOM あり・BOM なし

BOM 付き UTF-8 は、ファイルの先頭に隠れた 3 バイトを加えます。Windows の Excel で「名前を付けて保存 > CSV UTF-8 (コンマ区切り)」を使うと、これが書き込まれます。Shopify と WooCommerce は BOM 付きファイルを正しく読みますが、一部のツールやスクリプトはこの余分なバイトのせいで 1 列目の見出しを読み違えます。

BOM があるかどうかの確認方法：VS Code でファイルを開き、右下のステータスバーを見ます。「UTF-8 with BOM」と表示されていれば BOM があります。

**VS Code での直し方**：ステータスバーの文字コード表示をクリックし、「Save with Encoding」を選んでから「UTF-8」（BOM なし）を選びます。

**Excel での直し方**：Excel には BOM なしの UTF-8 で保存するオプションがありません。BOM を避けるために普通の「CSV (コンマ区切り)」に切り替えてはいけません。この形式はシステムの古い文字コード（日本語版では多くの場合 Shift_JIS）で保存するため、他のプラットフォームでは文字化けします。「CSV UTF-8」のまま保存し、プラットフォームが 1 列目を読み違える場合にだけ VS Code で BOM を取り除きます。

**Python での直し方**：

```python
# utf-8-sig は読み込み時に BOM を取り除き、utf-8 は BOM なしで書き込む
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

### ほかのツールでの文字コード

**Google スプレッドシート**：ファイル > ダウンロード > カンマ区切り形式 で BOM なしの UTF-8 が書き出されます。

**LibreOffice Calc**：CSV で保存するとき、ダイアログで「Unicode (UTF-8)」を選びます。

**Numbers（Mac）**：ファイル > 書き出す > CSV で、最近の macOS では BOM なしの UTF-8 が書き出されます。

## 引用符のルールと値の中のカンマ

セルの値にカンマが含まれる場合は、値全体を二重引用符で囲みます。これが CSV の標準（RFC 4180）です。

### 基本の例

```
Title,Price,Description
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships in 2 days"
```

引用符がないと、パーサーは 3 列ではなく 5 列と判断し、データを違う項目に入れてしまいます。

### 引用符で囲んだ値の中の引用符

値の中に二重引用符がある場合は、引用符を 2 つ重ねてエスケープします。

```
"She said ""this is great"""
```

これは She said "this is great" という文字列を表します。

### 引用符が必要なのはどんなとき？

値に次のものが含まれる場合は、二重引用符で囲む必要があります。

- カンマ
- 二重引用符
- 値の中の改行
- HTML タグ（引用符がないと山かっこを読み違えるパーサーもあります）

`29.99` や `Active` のような単純な値には引用符はいりません。すべてを引用符で囲んでも害はなく、多くのツールは自動でそうします。

### 引用符のよくある間違い

| 間違い | 悪い例 | 正しい例 |
|---|---|---|
| 値の中にカンマ、引用符なし | `Wallet, Brown` | `"Wallet, Brown"` |
| 引用符なしの HTML の説明 | `<p>Great item</p>` | `"<p>Great item</p>"` |
| 値の中に改行、引用符なし | 2 つの別々の行 | 1 つのセルに `"Line1\nLine2"` |
| 中の引用符のエスケープが間違っている | `"She said \"great\""` | `"She said ""great"""` |

## 改行コード

改行コードは、1 行がどこで終わり次の行がどこから始まるかをパーサーに伝えます。形式は 2 つあります。

| 形式 | バイト | 使っているもの |
|---|---|---|
| CRLF | 復帰 + 改行 | Windows、Excel |
| LF | 改行のみ | macOS、Linux、多くの Web ツール |

ほとんどのプラットフォームはどちらも受け付けます。問題になるのは、CRLF の行と LF の行が混ざっている場合です。改行コードが混ざると、パーサーが余分な空行を見つけたり、複数行の値を読み違えたりします。

### 確認と修正の方法

VS Code でファイルを開くと、ステータスバーに「CRLF」または「LF」と表示されます。クリックして切り替え、保存します。

Python の場合：

```python
with open("input.csv", newline="", encoding="utf-8") as f:
    content = f.read()
# LF にそろえる
content = content.replace("\r\n", "\n").replace("\r", "\n")
with open("output.csv", "w", newline="\n", encoding="utf-8") as f:
    f.write(content)
```

## インポートを失敗させる最もよくある間違い

**1. 余分な空行**

多くのスプレッドシートは末尾に空行を加えます。プラットフォームは空行を飛ばすか、エラーにします。書き出す前に削除してください。Excel では Ctrl+End で最後に使われたセルに移動できます。そこが空なら、データの下の空行を削除します。

**2. 集計行や合計行**

シートの下にある SUM() の数式は、CSV では商品の行として出てきます。書き出す前に集計行を削除します。

**3. 結合されたセル**

結合セルは、最初のセルに値、ほかのセルは空として書き出されます。インポート機能はその空のセルを、未入力の必須項目とみなします。書き出す前にすべてのセルの結合を解除します。

**4. 数式のセル**

Excel は CSV を保存するとき、各セルに表示されている内容を書き込みます。つまり、数式の現在の結果が、その表示形式のまま書き込まれます。通貨の表示形式にした価格の数式は `¥2,999` や `$29.99` のように、壊れた数式は `#N/A` や `#REF!` として書き込まれます。数式の列にエラーがないか確認し、CSV で保存する前に「形式を選択して貼り付け > 値」で固定の値に変えます。

**5. 見出しの末尾のスペース**

`"Title "`（末尾にスペース）は `"Title"` とは別物です。その列のデータはインポート時に警告なく無視されます。検索と置換（Ctrl+H）で見出しの末尾のスペースを取り除きます。

**6. 拡張子だけ .csv の別形式ファイル**

`.xlsx` で保存してファイル名だけ `.csv` にしても、中身は CSV ではありません。テキストエディタで開いて、バイナリの文字が見えれば本物の CSV ではありません。正しい形式で書き出し直します。

**7. ANSI や Latin-1 の文字コード**

古い Excel はファイルを ANSI（日本語版では Shift_JIS）で保存することがあります。日本語やアクセント付きの商品名はインポート時に文字化けします。保存するときは必ず明示的に UTF-8 を選びます。

## 区切り文字：カンマ、タブ、セミコロン

「CSV」という名前はカンマを意味しますが、タブ（TSV）やセミコロンを使うファイルもあります。ほとんどの EC プラットフォームは本当にカンマで区切られたファイルを前提としています。セミコロン区切りのファイルを CSV としてアップロードすると、各行が 1 つの列にまとまってしまいます。

### 区切り文字の見分け方

ファイルをテキストエディタで開き、1 行目を見ます。

- 列名が `,` で区切られていれば、カンマ区切り（標準の CSV）です
- `;` で区切られていれば、セミコロン区切りです（ヨーロッパの地域設定の Excel でよく見られます）
- 広い空白で区切られていれば、タブ区切り（TSV）です

### セミコロン区切りのファイルをカンマ区切りに変換する

**Excel の場合**：ファイル > 名前を付けて保存 > CSV UTF-8 (コンマ区切り)。それでもセミコロンで保存される場合（システムの地域設定がリストの区切り文字にセミコロンを使っているため）は、Windows の地域設定でリストの区切り文字を変更するか、下の Python の方法を使います。

**Python の場合**：

```python
import csv

with open("input.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f, delimiter=";")
    rows = list(reader)

with open("output.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f, delimiter=",")
    writer.writerows(rows)
```

## スプレッドシートの自動書式の危険

Excel や Google スプレッドシートは、CSV を開いたり編集したりすると、一部の値を黙って変えてしまいます。何も編集しないうちに、データが壊れることがあります。

### SKU や ID の先頭のゼロが消える

Excel は数値とみなした値から先頭のゼロを取り除きます。`00123` のような SKU は `123` に、`02110` のような郵便番号は `2110` になります。

**防ぎ方**：

- Excel：CSV を取り込む前にテキストのインポート（データ > テキストまたは CSV から）を使い、先頭のゼロを残すべき列の型を「テキスト」にします。
- Google スプレッドシート：取り込んだあと、編集する前に対象の列を「書式なしテキスト」にします（表示形式 > 数字 > 書式なしテキスト）。
- Python：pandas を使うなら SKU や ID の列は必ず `dtype=str` で読み込むか、型を変換しない標準の `csv` モジュールを使います。

### 数値が指数表記に変わる

長い数字の並び（13 桁のバーコード、EAN コード）は、Excel で `1.23457E+12` と表示されることがあります。CSV で保存すると、この表記がそのまま書き込まれ、インポート時のバーコード検証で失敗します。

**対処法**：Excel で対象の列を選び、表示形式を小数点以下 0 桁の「数値」（「指数」ではなく）にしてから保存します。または値の先頭にアポストロフィを付ける（文字列として扱われます）か、値を貼り付ける前に列をテキスト形式にします。

### 日付が地域の形式に変わる

`2024-01-15` という値が、地域設定によって `2024/1/15` などに自動変換されることがあります。ISO 形式（`YYYY-MM-DD`）を求めるプラットフォームは、変換された値を拒否します。

**対処法**：ファイルを開いたあと日付の列を選んでテキスト形式にするか、型を変換せずに読み書きする Python の `csv` モジュールを使います。

### 通貨記号付きの価格

Excel は通貨の表示形式にしたセルを、`19.99` ではなく `$19.99` として保存することがあります。ほとんどのプラットフォームは通貨記号のない単純な小数を求めます。

**対処法**：CSV で保存する前に、Excel で価格の列の表示形式を「数値」（「通貨」や「会計」ではなく）にします。データにすでに `$`、`EUR` などの記号が入っている場合は、検索と置換（Ctrl+H）で取り除きます。

## 空行、行末のカンマ、目に見えない問題

### 末尾の余分な空行

多くのツールは最後のデータ行のあとに空行を加えます。プラットフォームはたいてい空行を飛ばしますが、無効なレコードとして拒否するものもあります。書き出す前に、末尾の空行は必ず削除します。

Excel の場合：Ctrl+End で最後に使われたセルに移動します。そこが空（データの下の空行）なら、その行を選んで削除します（右クリック > 削除）。

### 行末のカンマ

一部の書き出しツールは、各行の末尾にカンマを書き込みます（`value1,value2,`）。これは中身のない余分な列を作ります。ほとんどのパーサーは問題なく処理しますが、厳しい検証ツールは構造の問題として指摘することがあります。

**対処法**：見出しを含むすべての行が余分なカンマで終わっている場合は、各行の末尾からカンマをちょうど 1 つだけ取り除きます。すべて取り除くと、行末にある本来の空セルまで消えてしまいます。

```python
with open("input.csv", encoding="utf-8", newline="") as f:
    lines = f.read().splitlines()
with open("output.csv", "w", encoding="utf-8", newline="") as f:
    for line in lines:
        f.write((line[:-1] if line.endswith(",") else line) + "\n")
```

### 目に見えない文字

一部のツールは、ゼロ幅スペース（U+200B）やノーブレークスペース（U+00A0）をセルの値に入れてしまいます。スプレッドシートでは見えませんが、インポート時に見出しが一致しなかったり、値が拒否されたりする原因になります。

**確認方法**：VS Code でファイルを開き、正規表現モードで検索（Ctrl+F）します。`​` や ` ` を検索すると、これらの文字が見つかります。

## プラットフォームごとのルール

各プラットフォームは、基本的な CSV の標準に加えて独自の要件を設けています。

- **Shopify**：Handle 列がバリエーションの行をまとめます。Handle がない、または無効だと、商品のまとまりが崩れます。
- **WooCommerce**：Type 列（`simple`、`variable`、`variation`）で商品の構造を決めます。
- **Etsy**：CSV アップロードがありません。出品のエクスポートは編集、バックアップ、移行のためのもので、一括出品アプリは独自の列を使います。
- **eBay**：すべての行に Action 列（`Add`、`Revise`、`Relist`、`End` など）が必要です。
- **Amazon**：列名はカテゴリのテンプレートによって異なります。セラーセントラルから自分のカテゴリのテンプレートをそのままダウンロードします。

## インポート前の簡単チェックリスト

- [ ] 1 行目が見出しで、その上に空行がない
- [ ] 見出しがプラットフォームの求める列名と、大文字・小文字も含めて完全に一致している
- [ ] 列名が重複していない
- [ ] 見出しの先頭や末尾にスペースがない
- [ ] ファイルを UTF-8 で保存している
- [ ] カンマ、引用符、改行を含む値が二重引用符で囲まれている
- [ ] 末尾に余分な空行がない
- [ ] 集計行や数式のセルがない
- [ ] 改行コードがそろっている（すべて CRLF か、すべて LF）
- [ ] 拡張子が .csv で、中身がカンマ区切りのプレーンテキストである

## 次のステップ：インポート前に検証する

ファイルの準備ができたら、CSV 修正ツールにアップロードして自動で検証しましょう。見出しを確認し、文字コードの問題を指摘し、プラットフォーム特有の問題を見つけ、安全に直せる問題はワンクリックで修正します。
