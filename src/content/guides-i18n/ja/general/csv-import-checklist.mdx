## 共通のインポート前チェックリスト

プラットフォームに関係なく、すべての CSV でこれらを確認します。

### ファイルの構造

- [ ] 拡張子が `.csv` で、中身がカンマ区切りのプレーンテキストである（`.xlsx` の名前を `.csv` に変えたものではない。テキストエディタで開いて確認）
- [ ] 1 行目が列の見出しで、その上に空行やタイトル行がない
- [ ] ファイルのどこにも空行がない（Excel で探すには、`=COUNTA(A2:Z2)` の補助列を追加して 0 で絞り込みます。「ジャンプ > セル選択 > 空白セル」は空の行だけでなくすべての空のセルを選ぶので使わないでください）
- [ ] 下に集計行、合計行、数式の行がない
- [ ] 結合セルがない（結合セルは最初のセル以外がすべて空として書き出されます）
- [ ] どの行も見出しと同じ数の項目がある（カンマではなく項目を数えます。引用符で囲んだ値の中のカンマは列を区切りません）

### 文字コード

- [ ] ファイルが **UTF-8** で保存されている（VS Code のステータスバーで確認）
- [ ] どの項目にも文字化け（â€™、Ã©、Â£）が見えない
- [ ] プラットフォームが 1 列目を認識しない場合は、テキストエディタで見出しの前に見えない BOM がないか確認する

### 見出し

- [ ] 列名がプラットフォームの表記と、大文字・小文字も含めて完全に一致している
- [ ] どの列名にも先頭や末尾のスペースがない
- [ ] 列名が重複していない
- [ ] 必須の列がそろっている（下のプラットフォーム別チェックリストを参照）

### データ型

- [ ] 価格の列に数値だけが入っている（`$`、`EUR` などの記号がない）
- [ ] はい/いいえの項目がプラットフォームの正しい形式を使っている（TRUE/FALSE、1/0、y/n）
- [ ] 必須のテキスト項目がどの行でも空になっていない
- [ ] SKU や識別子の項目がファイル全体で重複していない
- [ ] 画像 URL が絶対 URL（`https://` で始まる）で、公開されている

## Shopify のチェックリスト

- [ ] すべての行に `Handle` があり、空ではない
- [ ] バリエーションの行が商品の行と同じ `Handle` を持っている
- [ ] 各商品の最初の行に `Title` がある（バリエーションの行では空でもかまわない）
- [ ] `Variant Price` が通貨記号のない単純な数値である（空の価格は 0.00 としてインポートされる）
- [ ] はい/いいえの項目（`Published`、`Requires Shipping`、`Gift Card`）が `true` か `false` を使っている
- [ ] バリエーションのある商品は、最初の行に `Option1 Name`、各バリエーションの行に `Option1 Value` がある
- [ ] 値のない余分なオプション列がない（`Option3 Value` のない `Option3 Name` など）
- [ ] 画像 URL が、画像ファイル（JPEG、PNG、GIF、WebP）への公開された `https://` リンクである
- [ ] `Tags` 項目がタグをカンマで区切っている（あれば引用符で囲む）

## WooCommerce のチェックリスト

- [ ] `Type` 列に有効な値が入っている：`simple`、`variable`、`variation`、`grouped`、`external`
- [ ] `SKU` の値が重複していない（SKU は任意だが、重複するとエラーになる）
- [ ] `Regular price` が単純な小数である（通貨記号なし）
- [ ] `In stock?` は `1` か `0`、`Backorders allowed?` は `1`、`0`、`notify` のいずれかを使っている
- [ ] バリエーションの行に `Parent` の値がある：可変商品の SKU、または `id:` に続けてその商品 ID
- [ ] 属性の列が `Attribute 1 name` / `Attribute 1 value(s)` の命名規則に従っている
- [ ] `Tax status` が `taxable`、`shipping`、`none` のいずれかである
- [ ] 画像 URL が HTTPS の絶対 URL である

## Etsy のチェックリスト

Etsy には CSV アップロードがありません。これらは、編集したり、移行したり、一括出品アプリに渡したりする出品データのエクスポートを確認する項目です。

- [ ] `TITLE` が空ではなく、140 文字以内である
- [ ] `PRICE` が通貨記号のない正の数値である
- [ ] `QUANTITY` が 999 までの整数である
- [ ] `TAGS` がカンマ区切りで 13 個以内、各タグが 20 文字以内である
- [ ] `MATERIALS` が 13 個以内である
- [ ] 画像の列（`IMAGE1`、`IMAGE2` など）に完全な `https://` の URL が入っている
- [ ] SKU を使っている場合、`SKU` の値が重複していない
- [ ] 一括出品アプリが追加する列（`who_made`、`when_made`、`is_supply` など）が、そのアプリのテンプレートにある値を使っている

## eBay のチェックリスト

- [ ] `Action` 列のすべての行に、`Add`、`Revise`、`Relist`、`End` などの値がある
- [ ] `Category` が有効な数字の eBay カテゴリ ID である
- [ ] `Title` が 80 文字以内である
- [ ] `StartPrice` が正の小数である（通貨記号なし）
- [ ] `ConditionID` が eBay の数字の状態 ID を使っている（新品は `1000`、中古は `3000` など）
- [ ] `Duration` が使える値である（固定価格の出品は `GTC`、オークションは `Days_3`、`Days_5`、`Days_7`、`Days_10`）
- [ ] `PicURL` に、縦線 `|` で区切った HTTPS の画像 URL が入っている（24 枚まで）
- [ ] `Quantity` が正の整数である

## Amazon のチェックリスト

これらは Inventory Loader の出品情報ファイル向けの確認項目です。カテゴリテンプレートには独自の列があり、テンプレートの Data Definitions タブに載っています。

- [ ] ファイルを CSV ではなくタブ区切りのテキスト（`.txt`）で保存している
- [ ] `sku` が空ではなく、重複がなく、40 文字以内である
- [ ] `product-id` と `product-id-type` が合っている（`1` = ASIN、`2` = ISBN、`3` = UPC、`4` = EAN）
- [ ] `price` が正の小数である（通貨記号なし）
- [ ] `quantity` が整数（0 以上）で、FBA の出品では空にしている
- [ ] `item-condition` が Amazon の数字のコードを使っている（`11` = 新品、`10` = 再生品、`1`〜`8` = 中古品とコレクター商品）
- [ ] `add-delete` が `a`（追加または更新）、`d`（出品を削除）、`x`（出品と商品データを削除）のいずれかである
- [ ] `fulfillment-center-id` が、自分で発送する出品なら `DEFAULT`、FBA なら地域ごとの値（日本は `AMAZON_FE` など）である

## まず少数の行で試す

カタログ全体をアップロードする前に、3〜5 行で試します。

1. データ行を 3 行、新しいファイルにコピーします（見出し行は同じものを使います）
2. 小さなテストファイルをアップロードします
3. インポート結果を確認します。すべての項目が正しく対応付けられ、商品が正しく見えるか確かめます
4. 問題がなければ、ファイル全体をインポートします

少数の行で試すと、数百行に影響が出る前に問題を見つけやすくなります。

## それでもインポートが失敗するとき

1. エラーメッセージをよく読みます。プラットフォームのエラーレポートには、たいてい失敗した列や行が書かれています
2. エラーメッセージをそのまま、プラットフォーム名と一緒に検索し、そのプラットフォームのドキュメントを探します
3. ファイルを StriveFormats にアップロードして自動で検証します。プラットフォームのエラーメッセージではわかりにくい問題も見つけます
