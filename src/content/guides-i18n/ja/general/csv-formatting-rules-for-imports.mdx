## EC プラットフォームが従う CSV の標準

ほとんどの EC プラットフォーム（Shopify、WooCommerce、eBay、Etsy のエクスポート）は、一般的な CSV の標準である **RFC 4180** に従ったファイルを前提としています。この標準は、行、列、引用符、改行コードをどう構成するかを正確に定めています。例外は Amazon の Inventory Loader で、タブ区切りのテキスト（.txt）を使います。

このガイドでは、インポートの成否に関わるルールをすべて取り上げます。どれか 1 つでも守らないと、解析エラー、列の対応付けの誤り、気づかないうちのデータ破損が起こります。

---

## ルール 1：区切り文字はカンマ

列はカンマで区切ります。セミコロン（ヨーロッパの地域設定の Excel でよく使われます）、タブ（TSV 形式）、縦線（`|`）は使いません。

**正しい例**：

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
```

**間違った例（セミコロン）**：

```
Handle;Title;Vendor;Variant Price
blue-shirt;Blue T-Shirt;Acme;19.99
```

Excel が既定でセミコロンを使う場合（地域設定が小数点にカンマを使っているため）は、システムのリスト区切り文字をカンマに変えるか、常にカンマ区切りで書き出す Google スプレッドシートから書き出します。

---

## ルール 2：1 行目は見出しだけ

1 行目には列名だけを入れ、ほかには何も入れません。上に空行、タイトル行、結合した見出しセルを置かないでください。

**正しい例**：

```
Handle,Title,Variant Price
```

**間違った例**：

```
Product Export -- June 2026
Handle,Title,Variant Price
```

プラットフォームは 1 行目を見出しとして読みます。1 行目に見出し以外の内容があると、それが列名として扱われ、すべての見出しが一致しなくなります。

例外が 2 つあります。Amazon のカテゴリテンプレートには列名の上にテンプレート用の行があり、eBay のテンプレートは `Info` 行から始まることがあります。これらの行は、ダウンロードしたテンプレートのまま残してください。

---

## ルール 3：見出しは正確に

列名は、プラットフォームが求める名前と完全に一致しなければなりません。

- **大文字・小文字をそろえる**：`Handle`、`handle`、`HANDLE` を別の列として扱うインポート機能もあります
- **先頭や末尾にスペースを入れない**：` Title`（先頭にスペース）は `Title` と一致しません
- **見出しの中で改行しない**：見出しのセルは 1 行でなければなりません
- **見出しを重複させない**：2 つの列が同じ名前だと、ほとんどのパーサーは最後の列だけを使います

---

## ルール 4：カンマ、引用符、改行には引用符が必要

セルの値にカンマ、二重引用符、改行が含まれる場合は、値全体を二重引用符で囲みます。

**正しい例**：

```
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships free"
```

**引用符で囲んだ値の中の引用符のエスケープ**：中の引用符を 2 つ重ねます。

```
"She said ""great product"""
```

これは She said "great product" を表します。

| 状況 | 正しい書き方 |
|---|---|
| カンマを含む値 | `"value, with comma"` |
| 二重引用符を含む値 | `"value ""with"" quotes"` |
| HTML を含む値 | `"<p>Description here</p>"` |
| 改行を含む値 | `"Line one\nLine two"`（引用符の中） |
| 単純な数値 | `19.99`（引用符は不要） |

---

## ルール 5：UTF-8 エンコーディング

ファイルは **UTF-8** で保存します。Excel の「CSV UTF-8」は BOM（バイトオーダーマーク）を付けます。Shopify と WooCommerce は問題なく読みますが、プラットフォームが 1 列目を認識しない場合は BOM を取り除きます。

- UTF-8 は日本語、アクセント付きの文字、記号、あらゆる言語を扱えます
- 古い文字コード（Shift_JIS、Windows-1252、ISO 8859-1）は、インポート時にこれらの文字を化けさせます
- ANSI、Latin-1、Windows-1252 のファイルでは、アクセント付きの文字、曲がった引用符、通貨記号が文字化けします

**確認方法**：VS Code でファイルを開くと、ステータスバーに文字コードが表示されます。`Shift JIS`、`Windows 1252`、`ISO 8859-1` ではなく、`UTF-8`（または `UTF-8 with BOM`）になっているはずです。

---

## ルール 6：改行コードをそろえる

ファイル全体で CRLF（`\r\n`、Windows）か LF（`\n`、Unix/macOS）のどちらかに統一します。混ぜてはいけません。

改行コードが混ざると、データ行の間に空行があるとみなしたり、複数行の値で列数を数え間違えたりするパーサーがあります。

**VS Code での確認**：ステータスバーに `CRLF` または `LF` が表示されます。クリックして改行コードを変え、保存します。

---

## ルール 7：1 レコードにつき 1 行（複数行の商品があるプラットフォームを除く）

各行は 1 件のレコードですが、いくつかのプラットフォームでは 1 つの商品が複数の行にまたがります。

- **Shopify**：バリエーションの行や追加画像の行は、商品の `Handle` を繰り返します
- **WooCommerce**：バリエーションごとに行があり、`Parent` で親の可変商品にひも付きます
- **eBay**：バリエーション出品では、親の行の下に `Relationship` 行が加わります
- **Amazon**：親商品と子商品は別々の行で、親 SKU でひも付きます

プラットフォームのドキュメントが説明する構造に従い、それ以外のところで行をまとめたり分けたりしないでください。

---

## ルール 8：空行を入れない

データ行の間やあとにある空行は、パーサーに次のような動きをさせます。

- インポートに空のレコードを入れる
- 商品の数を数え間違える
- 最初の空行で処理を止める（一部のプラットフォーム）

保存する前に、空行はすべて削除します。Excel では `Ctrl+End` で最後に使われたセルに移動できます。そこがデータより先にあるなら、削除すべき空行があります。

---

## ルール 9：集計行や数式の行を入れない

商品データ以外の行はすべて取り除きます。

- 下にある合計行や小計行
- SUM() の数式の行
- データの下に書いたメモや注意書き
- セクションの区切り

これらの行はインポートで商品レコードとして扱われ、型のエラー（数値が必要なところに文字列、必須項目の欠落など）を起こします。

---

## ルール 10：セルを結合しない

Excel の結合セルは、左上のセルに値、ほかのセルは空の文字列として書き出されます。インポート機能は、1 行目以降のすべての行で必須項目が欠けているとみなします。

**対処法**：すべて選択 → セルの結合を解除 → CSV で保存する前に、空のセルを適切な値で埋めます。

---

## 簡単な確認チェックリスト

- [ ] カンマ区切りである（セミコロンや縦線ではない。Amazon のファイルはタブ区切り）
- [ ] 1 行目は列の見出しだけで、上に空行がない
- [ ] 見出しがプラットフォームの求める列名と完全に一致している（大文字・小文字とスペース）
- [ ] 列名が重複していない
- [ ] カンマや引用符を含む値が二重引用符で囲まれている
- [ ] 文字コードが UTF-8 である
- [ ] 改行コードがそろっている（すべて CRLF か、すべて LF）
- [ ] ファイルのどこにも空行がない
- [ ] 集計行、数式の行、結合セルがない
- [ ] 拡張子が `.csv` で、中身がプレーンテキストである（`.xlsx` の名前を `.csv` に変えたものではない）
