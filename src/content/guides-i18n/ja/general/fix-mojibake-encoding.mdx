## 文字化け（mojibake）とは

文字化けは、ある文字コードで保存したファイルを、別の文字コードで開いたり読んだりしたときに出る、意味のない文字の並びです。英語でも日本語の「文字化け」をそのまま使って mojibake と呼びます。

CSV に次のような並びがあれば、文字コードの問題です。

| 表示されている文字 | 本来の文字 |
|---|---|
| `â€™` | `’`（右シングル引用符） |
| `â€”` | `—`（ダッシュ） |
| `â€œ` | `“`（左ダブル引用符） |
| `Ã©` | `é`（アクセント付きの e） |
| 項目の先頭の `ï»¿` | BOM（見えない印） |

---

## 文字コードがずれる理由

Shopify、WooCommerce、Amazon などの最近のプラットフォームは **UTF-8** のファイルを前提としています。しかし、多くのツールは別の文字コードでファイルを作ります。

- **Microsoft Excel（Windows）** は、UTF-8 を明示的に選ばない限り、システムの言語の文字コード（日本語版では Shift_JIS、欧米では Windows-1252 や Latin-1）で `.csv` を保存します。
- **古い書き出しツール** は、既定で ISO-8859-1 / Latin-1 を使うことがあります。
- **Web サイトからのコピー＆ペースト** で、マルチバイトの UTF-8 文字として表される曲がった引用符やダッシュが入り込み、ファイルを Latin-1 として扱ったときに壊れることがあります。

UTF-8 のファイルを Latin-1 や Windows-1252 として読むと、マルチバイトの並びが 1 バイトずつの別々の文字に分かれ、文字化けになります。その文字化けしたテキストを保存すると、ごみがデータの一部になってしまいます。

## 問題を診断する

### ファイルの文字コードを確認する

**Mac/Linux の場合**：
```
file -I yourfile.csv
# 出力例: yourfile.csv: text/plain; charset=utf-8
```

**Windows（PowerShell）の場合**：
```powershell
# Windows PowerShell 5.1 の場合。PowerShell 7 では -Encoding Byte の代わりに -AsByteStream を使う
Get-Content yourfile.csv -Encoding Byte -TotalCount 3
# 先頭の 3 バイトが 239 187 191（0xEF 0xBB 0xBF）なら、UTF-8 の BOM がある
```

**目で見る簡単な確認**：ファイルを（Excel ではなく）テキストエディタで開き、最初の文字とアクセント付きの文字や日本語を見ます。最初のセルが `ï»¿` で始まっていたり、説明に `â€` が入っていたりすれば、文字コードが間違っています。

### どの文字コードを使うか見極める

- 文字化けしたファイルの多くは、**UTF-8 を Latin-1 や Windows-1252 として読んだ**もの（またはその逆）です。日本語の場合は、UTF-8 と Shift_JIS の取り違えもよくあります。
- ファイル自体は正しく、表示だけがおかしいなら、実際に保存された文字コードで開き直してから **UTF-8** で保存します。`â€™` のような並びは、たいてい UTF-8 のファイルが Windows-1252 として表示されているという意味なので、UTF-8 として開き直します。
- UTF-8 として開いてもごみが残るなら、それはデータに保存されています。文字コードを変えても消えないので、Python の `ftfy` ライブラリのような修復ツールか、検索と置換を使います。

## BOM とは

UTF-8 の BOM（バイトオーダーマーク）は、一部のツールが UTF-8 のファイルの先頭に付ける 3 バイトの並び（`EF BB BF`）です。Windows のメモ帳や Excel が自動で付けることがあります。

**なぜ問題になるか**：一部のインポートツールは BOM を 1 列目の列名の一部の文字として読み、`Handle` を `ï»¿Handle` にしてしまい、その列を認識できなくなります。Shopify と WooCommerce は BOM を扱えますが、ほかのツールやスクリプトは扱えないことがあります。

## Excel で直す

Excel は文字コードの問題の最も多い原因です。次の手順を正確に行います。

### Excel から UTF-8 で書き出す

1. Excel でスプレッドシートを開きます。
2. **ファイル → 名前を付けて保存** をクリックします。
3. 「ファイルの種類」で **CSV UTF-8 (コンマ区切り) (.csv)** を選びます。
   - この形式は、Windows と Mac の Excel 2016 以降で使えます。
   - 普通の「CSV (コンマ区切り)」は選ば**ない**でください。システムの言語の文字コードで保存されます。
4. **保存** をクリックします。

### 文字化けしたファイルを Excel で開き直す

すでに文字化けしたファイルがある場合：

1. ファイルをダブルクリックで開か**ない**でください。システムの言語の文字コードが使われます。
2. Excel で空のブックを開きます。
3. **データ → テキストまたは CSV から** を選びます。
4. ファイルを選びます。
5. インポートの画面で、**元のファイル** をファイルの本当の文字コードにします（UTF-8 のファイルなら **65001 : Unicode (UTF-8)**、Shift_JIS なら **932 : 日本語 (シフト JIS)**）。
6. インポートを終えたら、CSV UTF-8 で保存します。

## Google スプレッドシートで直す

Google スプレッドシートは、内部では常に UTF-8 で動きます。問題はダウンロードのときです。

1. **インポート**：**ファイル → インポート → アップロード** で CSV を選びます。文字コードは自動で判定されます。
2. **書き出し**：**ファイル → ダウンロード → カンマ区切り形式 (.csv)** を選びます。Google スプレッドシートは BOM なしの UTF-8 で書き出すので安全です。

受け取ったファイルがスプレッドシートで正しく表示されない場合：

1. 直接開かずに、**ファイル → インポート** で取り込みます。
2. SKU やバーコードがある場合は、インポートの画面で **テキストを数値、日付、数式に変換する** のチェックが外れていることを確認します。

## VS Code で直す（どのファイルにも使える確実な方法）

VS Code は無料で、文字コードを完全に制御できます。

1. VS Code を開き、CSV ファイルをドラッグして開きます。
2. 右下のステータスバーを見ると、判定された文字コード（`UTF-8`、`Windows 1252` など）が表示されています。
3. 文字コードの表示をクリックします。
4. **「Reopen with Encoding」** を選び、ファイルが実際に保存された文字コード（`Japanese (Shift JIS)`、`Western (Windows 1252)`、`ISO 8859-1` など）を選びます。
5. これで文字化けが正しく表示されるはずです。VS Code が `Windows 1252` と表示しているのに `â€™` のような並びが出ている場合、ファイルは実際には UTF-8 なので、**UTF-8** として開き直します。
6. もう一度表示をクリックし、**「Save with Encoding → UTF-8」** を選びます。

この 2 段階の手順（元の文字コードで開き直し、UTF-8 で保存する）は、どのツールでも使える最も確実な方法です。

## Windows のメモ帳で直す

Windows ですばやく直す場合（Windows 11 / 10 バージョン 1903 以降）：

1. 文字化けしたファイルをメモ帳で開きます。
2. **ファイル → 名前を付けて保存** を選びます。
3. **文字コード** で **UTF-8** を選びます（「UTF-8 (BOM 付き)」ではありません）。
4. 保存します。

> **注意**：古いメモ帳には BOM 付きの「UTF-8」しかなく、見えない BOM が付いてしまいます。BOM なしの「UTF-8」がない場合は、VS Code を使ってください。

## 保存し直しによる文字化けを防ぐ

ファイルがきれいになったら、次の点に気をつけます。

- **Excel では必ず「CSV UTF-8」を使い**、普通の CSV は使いません。
- **Windows で UTF-8 の CSV をダブルクリックで開き直さない。** Windows は `.csv` を Excel に関連付けているため、システムの言語の文字コードで開かれることがあります。Excel では文字コードを選べる **データ → テキストまたは CSV から** を使います。
- **書き出すたびに文字コードを確認する。** アップロードの前に、StriveFormats のようなツールやコマンドラインで確認します。
- インポート先のプラットフォームの書き出し機能がいつも Latin-1 を出すなら、ダウンロードした直後、編集する前に VS Code やスクリプトで変換します。

## 早見表：文字コードの症状と直し方

| 症状 | 考えられる原因 | 直し方 |
|---|---|---|
| テキストに `â€™` `â€”` | UTF-8 のファイルを Windows-1252 として表示 | UTF-8 で開き直す。まだ化けていれば `ftfy` で修復 |
| 1 列目の先頭に `ï»¿` | UTF-8 の BOM | BOM を取り除き、「BOM なしの UTF-8」を使う |
| `Ã©` `Ã¨` `Ã ` | UTF-8 のファイルを Latin-1 または Windows-1252 として表示 | UTF-8 で開き直す。まだ化けていれば `ftfy` で修復 |
| 特殊文字がすべて `?` になる | 変換時に文字の情報が失われた | 元のデータは失われている可能性がある。元のシステムから書き出し直す |
| スプレッドシートでは正しいのに、ダウンロードすると化ける | ダウンロード時の文字コードが違う | ファイル → ダウンロード → CSV を使う（Google は UTF-8） |
