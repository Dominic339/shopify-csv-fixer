## 什么是乱码（mojibake）？

mojibake 是指以一种字符编码保存的文件，被用另一种编码打开或解读时出现的一串看不懂的字符。这个词来自日语"文字化け"，大意是"无法辨认的字符"，也就是我们常说的乱码。

如果你的 CSV 中有下面这些字符串，就说明存在编码问题：

| 你看到的 | 本应是 |
|---|---|
| `â€™` | `’`（右单引号） |
| `â€”` | `—`（破折号） |
| `â€œ` | `“`（左双引号） |
| `Ã©` | `é`（带重音的 e） |
| 字段开头的 `ï»¿` | BOM（看不见的标记） |

## 编码为什么会不一致

Shopify、WooCommerce 和 Amazon 等现代平台都要求 **UTF-8** 编码的文件。但很多工具会生成其他编码的文件：

- **Microsoft Excel（Windows）** 除非你专门选择 UTF-8，否则会用系统语言的编码保存 `.csv`（简体中文 Windows 上通常是 GBK，西方系统上常为 Windows-1252 或 Latin-1）。
- **较旧的导出工具** 可能默认使用 ISO-8859-1 / Latin-1。
- **从网站复制粘贴** 可能会带入以多字节 UTF-8 字符编码的弯引号和破折号，当文件被当作 Latin-1 处理时，这些字符就会损坏。

当 UTF-8 文件被当作 Latin-1 或 Windows-1252 读取时，每个多字节序列都会被拆成单个的单字节字符，从而产生乱码。如果随后把这些乱码文本保存下来，乱码就成了数据的一部分。

## 诊断问题

### 检查文件的编码

**在 Mac/Linux 上**：
```
file -I yourfile.csv
# 输出示例：yourfile.csv: text/plain; charset=utf-8
```

**在 Windows（PowerShell）上**：
```powershell
# 适用于 Windows PowerShell 5.1；在 PowerShell 7 中请用 -AsByteStream 代替 -Encoding Byte
Get-Content yourfile.csv -Encoding Byte -TotalCount 3
# 如果前 3 个字节是 239 187 191（0xEF 0xBB 0xBF），说明文件带有 UTF-8 BOM
```

**快速目测**：用文本编辑器（不是 Excel）打开文件，查看第一个字符以及带重音的字母或中文。如果第一个单元格以 `ï»¿` 开头，或描述中出现 `â€`，说明编码不对。

### 确定应该使用哪种编码

- 大多数乱码文件是 **UTF-8 被当作 Latin-1 或 Windows-1252 读取**（或反过来）。对于中文，UTF-8 与 GBK 混淆也很常见。
- 如果文件本身没问题，只是显示错了，就用文件实际保存时的编码重新打开，然后另存为 **UTF-8**。`â€™` 这样的字符串通常表示 UTF-8 文件被当作 Windows-1252 显示，所以请用 UTF-8 重新打开。
- 如果用 UTF-8 打开后乱码仍然存在，说明乱码已经保存进数据中了。更改编码无法去掉它；请使用 Python 的 `ftfy` 库等修复工具，或使用查找和替换。

## 什么是 BOM？

UTF-8 BOM（字节顺序标记）是一些工具在 UTF-8 文件开头添加的三字节序列（`EF BB BF`）。Windows 记事本和 Excel 有时会自动添加它。

**为什么重要**：有些导入工具会把 BOM 读作第一个列名中的真实字符，把 `Handle` 变成 `ï»¿Handle`，从而无法识别该列。Shopify 和 WooCommerce 能处理 BOM，但其他工具和脚本未必可以。

## 在 Excel 中修复

Excel 是编码问题最常见的根源。请严格按照以下步骤操作。

### 从 Excel 以 UTF-8 导出

1. 在 Excel 中打开你的表格。
2. 点击 **文件 → 另存为**。
3. 在"保存类型"下拉列表中选择 **CSV UTF-8（逗号分隔）(.csv)**。
   - Windows 和 Mac 上的 Excel 2016 及更高版本都有这个选项。
   - **不要**选择普通的"CSV（逗号分隔）"，它会用系统语言的编码保存。
4. 点击 **保存**。

### 在 Excel 中重新打开乱码文件

如果你手上已经有乱码文件：

1. **不要**双击打开文件，那样会使用系统语言的编码。
2. 打开一个空白的 Excel 工作簿。
3. 选择 **数据 → 从文本/CSV**。
4. 选择你的文件。
5. 在导入向导中，把 **文件原始格式** 设为文件真实的编码：UTF-8 文件选 **65001: Unicode (UTF-8)**，GBK 文件选 **936: 简体中文 (GB2312)**。
6. 完成导入，然后另存为 CSV UTF-8。

## 在 Google 表格中修复

Google 表格内部始终使用 UTF-8，风险在于下载环节：

1. **导入**：选择 **文件 → 导入 → 上传**，然后选择你的 CSV。表格会自动检测编码。
2. **导出**：选择 **文件 → 下载 → 逗号分隔值 (.csv)**。Google 表格导出的是不带 BOM 的 UTF-8，是安全的。

如果你收到的文件在表格中显示为乱码：

1. 不要直接打开，而是通过 **文件 → 导入** 导入。
2. 如果有 SKU 或条形码，请在导入对话框中确认未勾选 **将文本转换为数字、日期和公式**。

---

## 用 VS Code 修复（适用于任何文件的可靠方法）

VS Code 免费，并且可以完全控制编码：

1. 打开 VS Code，把 CSV 文件拖进去。
2. 查看右下角的状态栏，它会显示检测到的编码（例如 `UTF-8`、`Windows 1252`）。
3. 点击编码标签。
4. 选择 **"Reopen with Encoding"**，并选择文件实际保存时使用的编码（常见的有 `Simplified Chinese (GBK)`、`Western (Windows 1252)` 或 `ISO 8859-1`）。
5. 乱码现在应该正常显示了。如果 VS Code 显示 `Windows 1252` 而文字中仍有 `â€™` 之类的字符串，说明文件实际上是 UTF-8：请改为用 **UTF-8** 重新打开。
6. 再次点击编码标签，选择 **"Save with Encoding → UTF-8"**。

这两步操作（先用原始编码重新打开，再保存为 UTF-8）是适用于任何工具的最可靠方法。

---

## 用 Windows 记事本修复

在 Windows 上快速修复（Windows 11 / 10 版本 1903 及以上）：

1. 用记事本打开乱码文件。
2. 选择 **文件 → 另存为**。
3. 在 **编码** 下拉列表中选择 **UTF-8**（不是"带有 BOM 的 UTF-8"）。
4. 保存。

> **注意**：旧版记事本只提供带 BOM 的"UTF-8"，会添加看不见的 BOM 标记。如果你的记事本没有不带 BOM 的"UTF-8"选项，请改用 VS Code。

## 防止重新保存时破坏编码

文件清理干净后，请这样保护它：

- **在 Excel 中始终使用"CSV UTF-8"**，不要用普通 CSV。
- **在 Windows 中不要双击重新打开 UTF-8 CSV。** Windows 把 `.csv` 关联到 Excel，而 Excel 可能用系统语言的编码打开它。请在 Excel 中使用可以选择编码的 **数据 → 从文本/CSV**。
- **每次导出后都检查编码**，在上传前用 StriveFormats 这样的工具或命令行进行检查。
- 如果你的导入平台的导出工具总是生成 Latin-1，请在下载后、编辑前立即用 VS Code 或脚本转换文件。
