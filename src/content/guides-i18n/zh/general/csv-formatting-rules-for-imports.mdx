## 电商平台遵循的 CSV 标准

大多数电商平台（Shopify、WooCommerce、eBay 以及 Etsy 的导出文件）要求文件遵循常见的 CSV 标准 **RFC 4180**。该标准准确规定了行、列、引号和换行符的结构。Amazon 的 Inventory Loader 是例外：它使用制表符分隔的文本（.txt）。

本指南涵盖所有影响导入成败的规则。违反其中任何一条，都会导致解析错误、列映射错误或悄无声息的数据损坏。

---

## 规则 1：分隔符是逗号

用逗号分隔各列。不要使用分号（在使用欧洲地区设置的 Excel 中很常见）、制表符（TSV 格式）或竖线（`|`）。

**正确**：

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
```

**错误（分号）**：

```
Handle;Title;Vendor;Variant Price
blue-shirt;Blue T-Shirt;Acme;19.99
```

如果你的 Excel 默认使用分号（因为系统地区设置把逗号用作小数点），请把系统的列表分隔符改为逗号，或通过 Google 表格导出，它始终生成逗号分隔的文件。

---

## 规则 2：第一行只放表头

第 1 行只能包含列名，不能有其他内容。上方不能有空行、标题行或合并的表头单元格。

**正确**：

```
Handle,Title,Variant Price
```

**错误**：

```
Product Export -- June 2026
Handle,Title,Variant Price
```

平台会把第 1 行当作表头读取。第 1 行中任何不是表头的内容都会被当成列名，导致所有表头都不匹配。

有两个例外：Amazon 类目模板在列名上方有模板行，eBay 模板可能以 `Info` 行开头。请让这些行保持下载的模板中的原样。

---

## 规则 3：表头必须准确

列名必须与平台要求的名称完全一致：

- **大小写一致**：有些导入程序会把 `Handle`、`handle` 和 `HANDLE` 当作不同的列
- **开头和结尾不能有空格**：` Title`（前面有空格）与 `Title` 不匹配
- **表头中不能换行**：表头单元格必须只有一行
- **不能有重复的表头**：如果两列同名，大多数解析器只使用最后一列

---

## 规则 4：含逗号、引号和换行的值必须加引号

只要单元格的值包含逗号、双引号或换行，就要用双引号把整个值括起来。

**正确**：

```
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships free"
```

**转义带引号的值中的引号**：把内部的引号写两遍：

```
"She said ""great product"""
```

这表示：She said "great product"

| 情况 | 正确格式 |
|---|---|
| 含逗号的值 | `"value, with comma"` |
| 含双引号的值 | `"value ""with"" quotes"` |
| 含 HTML 的值 | `"<p>Description here</p>"` |
| 含换行的值 | `"Line one\nLine two"`（在引号内） |
| 普通数字 | `19.99`（不需要引号） |

---

## 规则 5：UTF-8 编码

把文件保存为 **UTF-8**。Excel 的"CSV UTF-8"选项会添加 BOM（字节顺序标记）：Shopify 和 WooCommerce 能正常读取，但如果某个平台无法识别第一列，就把 BOM 去掉。

- UTF-8 可以处理中文、带重音的字母、符号以及所有语言
- 旧编码（GBK、Windows-1252、ISO 8859-1）会在导入时把这些字符变成乱码
- ANSI、Latin-1 和 Windows-1252 文件会让带重音的字母、弯引号和货币符号变成乱码

**检查方法**：在 VS Code 中打开文件，状态栏会显示编码。应该显示 `UTF-8`（或 `UTF-8 with BOM`），而不是 `GBK`、`Windows 1252` 或 `ISO 8859-1`。

---

## 规则 6：换行符保持一致

整个文件统一使用 CRLF（`\r\n`，Windows）或 LF（`\n`，Unix/macOS）。绝不要混用。

混用换行符会让某些解析器在数据行之间看到空行，或在多行的值中数错列数。

**在 VS Code 中检查**：状态栏显示 `CRLF` 或 `LF`。点击即可更改换行符，然后保存。

---

## 规则 7：每条记录一行（多行商品的平台除外）

每一行是一条记录，但在一些平台上，一个商品会占用多行：

- **Shopify**：多属性行和额外图片行会重复商品的 `Handle`
- **WooCommerce**：每个变体都有自己的一行，通过 `Parent` 关联到可变商品
- **eBay**：多属性刊登会在父行下方添加 `Relationship` 行
- **Amazon**：父商品和子商品是不同的行，通过父 SKU 关联

请遵循平台文档描述的结构，不要在此之外合并或拆分行。

---

## 规则 8：不能有空行

数据行之间或之后的空行会让解析器：

- 在导入中插入空记录
- 数错商品数量
- 在第一个空行处停止处理（部分平台）

保存前删除所有空行。在 Excel 中按 `Ctrl+End` 跳到最后一个使用过的单元格。如果它在数据范围之外，就说明存在需要删除的空行。

---

## 规则 9：不能有汇总行或公式行

删除所有不是商品数据的行：

- 底部的合计和小计行
- SUM() 公式行
- 写在数据下方的备注或说明
- 分节用的分隔行

这些行在导入时会被当成商品记录，导致类型错误（需要数字的地方出现文本、缺少必填字段等）。

---

## 规则 10：不能有合并单元格

Excel 中的合并单元格导出时，左上角单元格有值，其余都是空字符串。导入程序会认为第一行之后的每一行都缺少必填字段。

**解决方法**：全选 → 取消单元格合并 → 在保存为 CSV 前，用合适的值填充空单元格。

---

## 快速校验清单

- [ ] 用逗号分隔（不是分号或竖线；Amazon 文件用制表符分隔）
- [ ] 第 1 行只有列标题，上方没有空行
- [ ] 表头与平台要求的列名完全一致（大小写和空格）
- [ ] 没有重复的列名
- [ ] 含逗号或引号的值已用双引号括起来
- [ ] 文件编码为 UTF-8
- [ ] 换行符一致（全部 CRLF 或全部 LF）
- [ ] 文件中任何地方都没有空行
- [ ] 没有汇总行、公式行或合并单元格
- [ ] 文件扩展名为 `.csv`，内容是纯文本（不是改名为 `.csv` 的 `.xlsx`）
