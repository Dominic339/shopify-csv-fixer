## 什么是 CSV 文件？

CSV（Comma-Separated Values，逗号分隔值）文件是一种纯文本文件，每一行是一条记录，列之间用逗号分隔。第一行是列名（表头行），之后的每一行都是数据。

一个最简单的 Shopify 商品 CSV，用纯文本查看是这样的：

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
red-shirt,Red T-Shirt,Acme,21.99
```

CSV 文件看起来很简单，但 Shopify、WooCommerce、Etsy、eBay 和 Amazon 等平台对格式细节要求严格，而电子表格软件可能会在不知不觉中破坏这些细节。本指南逐一说明每条关键规则，让你的导入第一次就顺利通过。

## 表头行

每个 CSV 的第一行都必须是列名（表头）。平台在导入时根据这些名称把数据对应到正确的字段。

### 规则

- **名称要完全一致，包括大小写。** 有些导入程序会区别对待 `Handle`、`handle` 和 `HANDLE`，所以请从平台的模板中复制表头名称。
- **开头和结尾不要有空格。** 表头 `" Title"`（开头有空格）与 `"Title"` 不匹配，该列的数据会被悄悄忽略。
- **不要有重复的表头。** 如果两列同名，大多数解析器只使用最后一列。
- **有些平台要求固定的列顺序。** 部分 eBay 和 Amazon 模板要求各列按模板顺序排列，所以请保留下载的模板中的顺序。Shopify 允许在任意位置添加列。

### 如何检查

用记事本（Windows）、文本编辑（Mac）或 VS Code 等纯文本编辑器打开 CSV，查看第 1 行。它应该是用逗号分隔的名称，上方没有空行：

```
Handle,Title,Body (HTML),Vendor,Type,Tags,...
```

如果第一行在表头名称之前有三个奇怪的字符，说明文件带有 BOM。修复方法见下面的编码部分。

## UTF-8 编码

编码是文本字符在磁盘上以字节形式存储的方式。编码不对就会出现乱码。例如，以 UTF-8 保存的弯撇号被当作 Latin-1 读取时，会变成看起来像乱码的三个字符。

### 为什么用 UTF-8

UTF-8 对所有电商平台来说都是安全的选择。Shopify 和 WooCommerce 都要求使用它，eBay 当前的模板也在 Action 表头中声明了它（`CC=UTF-8`）。保存为 UTF-8 可以确保：

- 中文和带重音的字符正确显示。
- 货币符号和特殊标点不会损坏。
- 平台的导入程序能读取文件而不拒绝。

### 带 BOM 与不带 BOM

带 BOM 的 UTF-8 会在文件最开头加上隐藏的 3 字节序列。Windows 上的 Excel 在使用"另存为 > CSV UTF-8（逗号分隔）"时会写入它。Shopify 和 WooCommerce 能正确读取带 BOM 的文件，但有些工具和脚本会因为这些多出的字节而读错第一个列标题。

判断文件是否带 BOM：在 VS Code 中打开文件，查看右下角的状态栏。如果显示"UTF-8 with BOM"，就说明带有 BOM。

**在 VS Code 中修复**：点击状态栏中的编码指示，选择"Save with Encoding"，然后选择"UTF-8"（不带 BOM）。

**在 Excel 中修复**：Excel 没有保存不带 BOM 的 UTF-8 的选项。不要为了避开 BOM 而改用普通的"CSV（逗号分隔）"：该选项会用系统的旧编码保存（简体中文 Windows 上通常是 GBK），在其他平台上会出现乱码。请保持"CSV UTF-8"，只有当平台读错第一列时，才在 VS Code 中去掉 BOM。

**用 Python 修复**：

```python
# utf-8-sig 在读取时去掉 BOM；普通 utf-8 写入时不带 BOM
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

### 其他工具中的编码

**Google 表格**：文件 > 下载 > 逗号分隔值 会导出不带 BOM 的 UTF-8。

**LibreOffice Calc**：保存为 CSV 时，在对话框中选择"Unicode (UTF-8)"。

**Numbers（Mac）**：文件 > 导出为 > CSV 在新版 macOS 上导出不带 BOM 的 UTF-8。

## 引号规则与值中的逗号

当单元格的值包含逗号时，要用双引号把整个值括起来。这是 CSV 标准（RFC 4180）。

### 基本示例

```
Title,Price,Description
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships in 2 days"
```

没有引号的话，解析器会看到五列而不是三列，并把数据放进错误的字段。

### 带引号的值中的引号

如果值本身包含双引号，就把它写两遍来转义：

```
"She said ""this is great"""
```

这表示文本：She said "this is great"

### 什么时候需要引号？

当值包含以下内容时，需要用双引号括起来：

- 逗号
- 双引号
- 值中的换行
- HTML 标签（有些解析器在没有引号时会误读尖括号）

`29.99` 或 `Active` 这样的简单值不需要引号。给所有值都加上引号也没有坏处，很多工具会自动这样做。

### 常见的引号错误

| 错误 | 错误示例 | 正确写法 |
|---|---|---|
| 值中有逗号但没加引号 | `Wallet, Brown` | `"Wallet, Brown"` |
| HTML 描述没加引号 | `<p>Great item</p>` | `"<p>Great item</p>"` |
| 值中有换行但没加引号 | 两个独立的行 | 一个单元格中的 `"Line1\nLine2"` |
| 内部引号转义错误 | `"She said \"great\""` | `"She said ""great"""` |

## 换行符

换行符告诉解析器一行在哪里结束、下一行从哪里开始。有两种格式：

| 格式 | 字节 | 使用者 |
|---|---|---|
| CRLF | 回车 + 换行 | Windows、Excel |
| LF | 仅换行 | macOS、Linux、大多数网页工具 |

大多数平台两种格式都接受。问题出在换行符混用时，也就是有些行用 CRLF、有些行用 LF。混用的换行符可能让解析器看到多余的空行，或误读多行的值。

### 如何检查和修复

在 VS Code 中打开文件，状态栏会显示"CRLF"或"LF"。点击切换，然后保存。

用 Python：

```python
with open("input.csv", newline="", encoding="utf-8") as f:
    content = f.read()
# 统一为 LF
content = content.replace("\r\n", "\n").replace("\r", "\n")
with open("output.csv", "w", newline="\n", encoding="utf-8") as f:
    f.write(content)
```

## 最常导致导入失败的错误

**1. 多余的空行**

很多电子表格工具会在末尾加一个空行。平台会跳过空行或报错。导出前请删除它们。在 Excel 中按 Ctrl+End 跳到最后一个使用过的单元格。如果它是空的，就删除数据下方的空行。

**2. 汇总行或合计行**

工作表底部的 SUM() 公式会在 CSV 中变成商品行。导出前请删除汇总行。

**3. 合并的单元格**

合并单元格导出时，第一个单元格有值，其余都是空白。导入程序会把这些空白单元格看作未填写的必填字段。导出前请取消所有单元格合并。

**4. 公式单元格**

Excel 保存 CSV 时，会写入每个单元格所显示的内容：公式的当前结果，连同它的数字格式。设置为货币格式的价格公式会写成 `¥29.99` 或 `$29.99`，出错的公式会写成 `#N/A` 或 `#REF!`。请检查公式列中是否有错误，然后在保存为 CSV 前用"选择性粘贴 > 值"把它们变成固定值。

**5. 表头名称末尾的空格**

`"Title "`（末尾有空格）与 `"Title"` 不同，该列的数据在导入时会被悄悄忽略。用查找和替换（Ctrl+H）删除表头末尾的空格。

**6. 扩展名为 .csv 的错误格式文件**

保存为 `.xlsx` 却把文件命名为 `.csv`，得到的并不是真正的 CSV 文件。用文本编辑器打开它，如果看到二进制字符，就不是真正的 CSV。请用正确的保存格式重新导出。

**7. ANSI 或 Latin-1 编码**

旧版 Excel 有时会以 ANSI（简体中文系统上为 GBK）保存。含中文或重音字符的商品名称在导入时会变成乱码。保存时务必明确选择 UTF-8。

## 分隔符：逗号、制表符和分号

"CSV"这个名字指的是逗号，但有些文件使用制表符（TSV）或分号。大多数电商平台要求真正以逗号分隔的文件。把分号分隔的文件当作 CSV 上传，每一行都会显示为单独一列。

### 如何识别分隔符

用纯文本编辑器打开文件，查看第一行：

- 如果列名之间用 `,` 分隔，文件就是逗号分隔（标准 CSV）
- 如果用 `;` 分隔，就是分号分隔（在使用欧洲地区设置的 Excel 中很常见）
- 如果用较宽的空白分隔，就是制表符分隔（TSV）

### 把分号文件转换为逗号分隔

**在 Excel 中**：文件 > 另存为 > CSV UTF-8（逗号分隔）。如果 Excel 仍然用分号保存（因为系统地区设置把分号用作列表分隔符），请在 Windows 的区域设置中更改列表分隔符，或使用下面的 Python 方法。

**在 Python 中**：

```python
import csv

with open("input.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f, delimiter=";")
    rows = list(reader)

with open("output.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f, delimiter=",")
    writer.writerows(rows)
```

## 电子表格自动格式化的风险

Excel 和 Google 表格等电子表格软件在你打开或编辑 CSV 时，会悄悄修改某些值。这些修改可能在你动手编辑之前就已经破坏了数据。

### SKU 和 ID 的前导零被删除

Excel 会删除它认为是数字的值中的前导零。像 `00123` 这样的 SKU 会变成 `123`，像 `02110` 这样的邮政编码会变成 `2110`。

**如何避免**：

- 在 Excel 中：导入 CSV 前使用文本导入向导（数据 > 从文本/CSV），把需要保留前导零的每一列类型设为"文本"。
- 在 Google 表格中：导入后、编辑前，把受影响的列设为"纯文本"格式（格式 > 数字 > 纯文本）。
- 用 Python：如果使用 pandas，读取 SKU 和 ID 列时始终加上 `dtype=str`，或使用从不转换类型的标准 `csv` 模块。

### 数字被转换为科学计数法

较长的数字串（13 位条形码、EAN 码）在 Excel 中可能显示为 `1.23457E+12`。保存为 CSV 时，这种写法会被原样写入，导致导入时条形码校验失败。

**解决方法**：在 Excel 中选中受影响的列，设置为小数位数为 0 的"数值"格式（不是"科学记数"），然后保存。也可以在值前面加一个单引号（强制按文本处理），或在粘贴值之前把该列设为文本格式。

### 日期被转换为地区格式

字段中的 `2024-01-15` 可能会根据系统地区设置被自动转换为 `2024/1/15` 等格式。要求 ISO 格式（`YYYY-MM-DD`）的平台会拒绝被改格式的值。

**解决方法**：打开文件后，选中日期列并设置为文本格式，或使用 Python 的 `csv` 模块在不做任何类型转换的情况下读写。

### 带货币符号的价格

Excel 有时会把设置为货币格式的单元格保存为 `$19.99` 而不是 `19.99`。大多数平台要求不带货币符号的普通小数。

**解决方法**：在保存为 CSV 前，在 Excel 中把价格列设为"数值"格式（不是"货币"或"会计专用"）。如果数据中已经有 `$`、`EUR` 或其他符号，用查找和替换（Ctrl+H）删除它们。

## 空行、行尾逗号和看不见的问题

### 末尾多余的空行

很多工具会在最后一行数据后加一个空行。平台通常会跳过空行，但有些平台会把它当作无效记录拒绝。导出前务必删除底部的空行。

在 Excel 中：按 Ctrl+End 跳到最后一个使用过的单元格。如果它是空的（数据下方的空行），选中这些行并删除（右键 > 删除）。

### 行尾逗号

有些导出工具会在每一行末尾写一个逗号：`value1,value2,`。这会产生一个多余的空列。大多数解析器能妥善处理，但严格的校验工具可能会把它标记为结构问题。

**解决方法**：如果包括表头在内的每一行都以多余的逗号结尾，就从每行末尾删除恰好一个逗号。全部删除的话，行尾真正的空单元格也会被删掉：

```python
with open("input.csv", encoding="utf-8", newline="") as f:
    lines = f.read().splitlines()
with open("output.csv", "w", encoding="utf-8", newline="") as f:
    for line in lines:
        f.write((line[:-1] if line.endswith(",") else line) + "\n")
```

### 不可见字符

有些工具会在单元格的值中插入零宽空格（U+200B）或不换行空格（U+00A0）。它们在电子表格中看不见，但可能在导入时导致表头不匹配或值被拒绝。

**检查方法**：在 VS Code 中打开文件，用正则表达式模式进行查找（Ctrl+F）。搜索 `​` 或 ` ` 即可找到这些字符。

## 各平台的规则

每个平台都在基本的 CSV 标准之上增加了自己的要求：

- **Shopify**：Handle 列把多属性行归为一组。缺少或无效的 Handle 会破坏商品分组。
- **WooCommerce**：使用 Type 列（`simple`、`variable`、`variation`）定义商品结构。
- **Etsy**：没有 CSV 上传功能。商品导出用于编辑、备份和迁移，批量刊登应用会使用自己的列。
- **eBay**：每一行都需要 Action 列（例如 `Add`、`Revise`、`Relist` 或 `End`）。
- **Amazon**：列名因商品类目模板而异；请从卖家平台下载与你的类目完全对应的模板。

## 导入前快速检查清单

- [ ] 第 1 行是表头，上方没有空行
- [ ] 表头与平台要求的列名完全一致，包括大小写
- [ ] 没有重复的列名
- [ ] 表头名称开头和结尾没有空格
- [ ] 文件已保存为 UTF-8
- [ ] 含有逗号、引号或换行的值已用双引号括起来
- [ ] 底部没有多余的空行
- [ ] 没有汇总行或公式单元格
- [ ] 换行符一致（全部 CRLF 或全部 LF）
- [ ] 文件扩展名为 .csv，内容是逗号分隔的纯文本
