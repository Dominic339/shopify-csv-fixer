## 为什么导入前要先校验

CSV 导入失败可能无害（什么都没变），也可能造成破坏（部分更新让商品目录前后不一致）。在 Shopify 上，引号错误通常会让整个导入停止，并指出失败的行。在 WooCommerce 上，列错位的行可能把错误的值写进已有商品。

上传前花五分钟校验，可以省下数小时的清理工作。

---

## 导入前检查清单

### 1. 编码：UTF-8

**检查什么：** 文件必须使用 UTF-8 编码。开头的 BOM（字节顺序标记）对 Shopify 和 WooCommerce 没有影响，但有些工具会把它读成第一列列名的一部分。

**如何检查：**
- 用 VS Code 打开文件。右下角状态栏应显示 `UTF-8`（或 `UTF-8 with BOM`），而不是 `Windows 1252` 或 `ISO 8859-1`。
- 如果显示的是别的编码，先确认文字显示正常（如果是乱码，点击编码标签，选择 **通过编码重新打开**，并选择文件真正的编码）。然后再次点击标签，选择 **通过编码保存 → UTF-8**。

**常见修复：** 在 Excel 中，始终另存为 **CSV UTF-8（逗号分隔）**，而不是普通 CSV。

---

### 2. 表头行：名称正确，没有多余内容

**检查什么：**
- 第一行的列名与平台要求完全一致。
- 列名前后没有空格。
- 没有重复的列名。
- 末尾没有多余的空列。

**如何检查：**
用文本编辑器打开文件，仔细阅读第 1 行。与平台的官方模板对比：

- Shopify：查看 [Shopify 商品 CSV 模板](https://help.shopify.com/en/manual/products/import-export/import-products)。
- WooCommerce：与后台提供的 WooCommerce 示例商品 CSV 对比。
- Amazon：在卖家平台下载 Inventory Loader 或类目模板（**库存 → 批量上传商品**）。

**常见问题：**
- 末尾带空格的 `"Handle "`（在 Excel 中看不见）。
- 写成小写的 `handle`，而不是 `Handle`。
- 完全缺少必填列。

---

### 3. 必填列：全部存在且不为空

**检查什么：**
- 平台的所有必填列都在表头中。
- 任何一行的必填字段都不为空。

**各平台必填字段（最少）：**

| 平台 | 必填列 |
|---|---|
| Shopify | Title（更新已有商品时还需 Handle） |
| WooCommerce | Name、Type（更新已有商品时还需 ID 或 SKU） |
| eBay File Exchange | Action、Title、Category、StartPrice、ConditionID |
| Amazon Inventory Loader | sku、product-id、product-id-type、price、item-condition、quantity、add-delete |
| Etsy | 不支持上传 CSV：Etsy 只能导出 CSV，因此没有需要为导入校验的内容 |

**在 Excel 中检查：**
1. 开启筛选（**数据 → 筛选**）。
2. 对每个必填列筛选空白单元格。
3. 必填字段为空的行都会导入失败。

---

### 4. 行长度一致

**检查什么：** 每一行的列数都必须与表头行相同。列数不同的行说明：
- 描述或标题中有未转义的逗号。
- 字段中含有换行，把一行拆成了多行。
- 复制粘贴时插入了多余的列。

**在 Excel 中检查（过长的行）：**
1. 找到最后一个表头之后的第一列。如果表头在 T 列结束，就是 U 列。
2. 在最右侧很远的一个空列（例如 AAA 列）中输入 `=COUNTA(U2:ZZ2)`。
3. 向下复制到所有行，并筛选大于 0 的值。这些行有多余的字段。

Excel 无法显示过短的行，因为缺失的字段看起来和空字段一样。

**在文本编辑器中检查：**
在安装了 Rainbow CSV 扩展的 VS Code 中，运行 **Rainbow CSV: CSVLint** 命令。它会报告字段数与表头不同的每一行，包括过短的行。

**常见修复：** 凡是含有逗号、引号或换行的字段，都用双引号括起来。如果字段中本身含有双引号，把每个双引号写两次进行转义（`""`）。

---

### 5. 带引号的字段：引号正确并已转义

**检查什么：**
- 含有逗号、双引号或换行的字段都用双引号括起来。
- 带引号字段中的每个双引号都通过写两次来转义（是 `""`，不是 `\"`）。

**正确使用引号的示例：**
```
Handle,Title,Body HTML
blue-shirt,"Blue T-Shirt, Men's","<p>""Premium"" cotton.</p>"
```

**注意事项：**
- 以 `"` 开头的字段，必须在同一逻辑行内以 `"` 结尾。
- 撇号不需要转义：`Men's` 保持原样即可。只有双引号需要写两次。

---

### 6. 关键字段中没有非法字符

**检查什么：**
- Handle/别名只包含小写字母、数字和连字符。
- 价格字段只包含数字和小数点（没有货币符号，没有千位分隔符）。
- 是/否字段（例如 Published、Featured）使用平台要求的值（TRUE/FALSE、yes/no 或 1/0）。

**常见问题：**
- 价格列中写着 `$19.99`（应为 `19.99`）。
- Handle 列中写着带大写字母和空格的 `Blue Shirt`（应为 `blue-shirt`）。
- 价格写成 `19,99`（欧洲小数逗号），而不是 `19.99`。

---

### 7. 图片 URL：可访问且格式正确

**检查什么：**
- 图片 URL 以 `https://` 开头（有些平台会拒绝或跳过 `http://` 图片）。
- URL 中没有空格（空格需编码为 `%20` 或删除）。
- 对于 Shopify：每个商品最多支持 250 个图片 URL。每个 Handle 的第一行 `Image Src` 是主图。
- URL 可以公开访问（不需要登录，不是 localhost）。

---

### 8. 末尾没有空行

**检查什么：** 很多表格软件会在末尾添加空行。平台可能把空行当作无效行并报错。

**在 Excel 中修复：**
1. 按 **Ctrl+End** 跳到最后一个使用过的单元格。
2. 如果最后一行是空的（所有单元格都为空），从这一行起向下选中几行并删除。
3. 保存文件。

---

## 试传策略

不要把 10,000 行的完整商品目录当作第一次测试上传。改为：

1. 复制一份 CSV。
2. 只保留 5–10 行有代表性的数据（如果有多属性商品，至少包含一个）。
3. 把样本上传到测试环境或预发布店铺。
4. 确认每一行都正确导入。
5. 在完整文件中修复错误。
6. 上传完整文件。

对于 Shopify：导入工具会在确认前显示预览，并在导入完成后发送邮件。即使导入看起来已经完成，也请阅读这封邮件，因为可能有部分行被跳过，而其余行照常导入。

## 导入前校验工具

| 工具 | 检查内容 |
|---|---|
| **StriveFormats CSV Fixer** | 各平台专用表头、编码、必填字段、引号、是/否值 |
| **安装 Rainbow CSV 扩展的 VS Code** | 直观查看列是否对齐、错位的行 |
| **csvkit（`csvclean`）** | 字段数不对的行（命令行） |
| **Google 表格 文件 → 导入** | 使用所选分隔符时列如何拆分 |
| **Excel 数据 → 从文本/CSV** | 加载前预览编码和分隔符 |

校验工具发现不了内容上的错误（SKU 错误、类目 ID 错误、已经无法加载的图片 URL）。这些需要通过试传来发现。但校验工具能发现阻止导入完成的结构性错误。
