## CSV 导入为什么会失败

每个电商平台在接受你的 CSV 之前，都会让它经过一系列校验。校验内容包括结构（表头、列数）、数据类型（数字、是/否值、必填字段）、业务规则（有效的类目代码、价格范围）和编码。只要有一项校验不通过，导入就会完全停止，或者只导入一部分行并跳过其余的行。

理解错误信息是实现干净导入的最快途径。本指南解释最常见的错误。

---

## 结构错误

这些错误表示文件的结构本身有问题，平台甚至还没开始看你的数据。

### "Missing required column" / "Column not found"

平台要求的列名不在你的表头行中。常见原因：

- 你给必填列改了名（例如用 `product_title` 代替 `Title`）
- 表头开头或结尾有空格（` Title` 而不是 `Title`）
- 文件带有 BOM，在第一个列名前加了隐藏字节
- 你用的是另一个平台的模板

**解决方法**：把你的表头行与该平台的官方模板进行比较。必须完全一致，包括大小写、拼写和空格。

### "Column count mismatch" / "Wrong number of columns"

某个数据行的字段数比表头行多或少。常见原因：

- 值中有未加引号的逗号：`Wallet, Brown` 应写成 `"Wallet, Brown"`
- 未加引号的 HTML 描述中有逗号（例如在 `style` 属性中）
- 某些行末尾多了一个逗号（会产生一个多余的空列）

**解决方法**：用文本编辑器打开文件，查看有问题的行。数一数它的字段，注意带引号的值中的逗号不会分隔列。所有含逗号的值都必须用双引号括起来。

### "Unexpected header" / "Unrecognized column"

文件中有平台无法识别的列。这通常只是警告，不会阻断导入，因为平台会忽略多余的列。不过更严格的导入程序可能会拒绝未知的列，所以如果文件无缘无故导入失败，请检查平台自己的模板。

**解决方法**：删除官方模板中没有的列，或检查列名是否需要换一种写法。

## 必填字段错误

### "Required field is blank" / "Field cannot be empty"

表头中有某个必填列，但一行或多行的值为空。经常为空的必填字段：

- **Shopify**：每一行的 Handle，以及每个商品第一行的 Title
- **WooCommerce**：新商品的 Name，以及变体行的 Parent
- **Etsy（批量刊登应用）**：该应用模板标为必填的字段，通常是 who_made、when_made 和 is_supply
- **eBay**：Action，以及新增刊登时的 Title、Category、StartPrice 和 ConditionID
- **Amazon（Inventory Loader）**：sku、product-id、product-id-type 和 add-delete，以及新增报价时的 price、item-condition 和 quantity

**解决方法**：筛选或排序文件，找出必填列为空的行，并补全缺失的数据。如果留空是有意的（多属性行继承商品的值），请查看平台规则。例如，Shopify 的多属性行留空 Title 是完全正常的。

### "SKU is required"

有些文件用 SKU 识别每个商品。Amazon 的 Inventory Loader 始终如此，其他平台的更新导入也常常按 SKU 匹配行。在这些情况下，没有 SKU 的行会失败。

**解决方法**：为每个需要 SKU 的行添加 SKU。使用一致的格式：只用字母和数字、不含空格，并且不超过平台的长度限制（Amazon 为 40 个字符）。

## 数据类型和格式错误

### "Invalid price" / "Price must be a number"

价格字段中有非数字的值。常见原因：

- 值中带有货币符号：`$19.99` 而不是 `19.99`
- 用逗号作小数点：`19,99` 而不是 `19.99`（在使用欧洲地区设置时很常见）
- 需要数字的地方是空字符串或短横线
- Excel 把单元格设为货币格式，并连同符号一起导出

**解决方法**：删除货币符号，把小数点逗号改为句点。保存前在 Excel 中把该列设为"数值"格式。

### "Invalid boolean" / "Must be true or false"

是/否字段中有意外的值。各平台对这类格式要求严格：

- **Shopify**：要求 `true` 或 `false`，与 Shopify 自己的模板一致
- **WooCommerce**：使用 `1` / `0`（`Backorders allowed?` 等字段还接受 `notify`）
- **Amazon**：取决于文件。类目模板使用其 Valid Values 选项卡中的值（通常是 `true` / `false`）；Inventory Loader 的 `will-ship-internationally` 接受 `y` / `n` 或 `1` / `2`

**解决方法**：把所有写法（Yes、yes、Y、1、true）替换为各平台要求的格式。使用电子表格中的查找和替换。

### "Invalid date format"

日期字段的格式不对。大多数平台要求 `YYYY-MM-DD`。Excel 经常把日期自动转换为 `2024/1/15` 这样的地区格式。

**解决方法**：编辑前在 Excel 中把日期列设为文本格式，或使用不做类型转换的 Python `csv` 模块。保存前把日期转换为 `YYYY-MM-DD`。

## 业务规则错误

### "Duplicate SKU" / "Handle already exists"

某个唯一标识在文件中出现了不止一次。在 Shopify 中，多属性商品会有意重复使用同一个 Handle，但如果同一个 Handle 出现在两个不相关的商品组中，就是错误。在 WooCommerce 和 Amazon 中，重复的 SKU 一定意味着有问题。

**解决方法**：按标识列对文件排序，查找非预期的重复项。用公式（`COUNTIF`）可以自动找出完全相同的重复项。

### "Invalid category ID" / "Category not recognized"

你使用的类目代码在平台的分类体系中不存在。

- **eBay**：类目 ID 是数字，必须来自 eBay 当前的类目树
- **Amazon**：浏览节点和商品类型必须与卖家平台当前的分类体系一致
- **Etsy（批量刊登应用）**：分类 ID 来自 Etsy 的 API，必须与其当前列表一致

**解决方法**：在平台官方的类目浏览工具或分类下载文件中查找正确的类目 ID。不要使用旧模板中的 ID，因为它们会变化。

## 导入结果中的警告与阻断性错误

大多数平台会区分**阻断性错误**（行或文件被拒绝）和**警告**（行被导入，但带有标记）。了解两者的区别，有助于确定修复的优先顺序：

| 严重程度 | 含义 | 示例 |
|---|---|---|
| 阻断 | 行或文件被跳过 | 缺少必填字段、列数错误 |
| 警告 | 带标记导入 | 无法识别的可选字段、描述过长 |
| 提示 | 仅供参考 | 字段使用了平台的默认值 |

重新上传前修复所有阻断性错误。警告通常可以在第二轮再处理。
