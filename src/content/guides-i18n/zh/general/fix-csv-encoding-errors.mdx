## 什么是 CSV 编码错误？

当 CSV 文件中的字节被用错误的字符集解读时，就会出现编码错误。最常见的症状是**乱码**：商品名称、描述等字段中，本该是撇号、带重音的字母、中文或货币符号的地方，出现了 `â€™`、`Ã©`、`Â£`、`ä¸­æ–‡` 这类奇怪的字符串。

Shopify 和 WooCommerce 要求使用 **UTF-8**，对其他所有平台来说它也是安全的选择。如果文件以其他编码（GBK、Latin-1、Windows-1252 等）保存，导入程序要么直接拒绝文件，要么悄悄破坏字符数据。

### 常见症状

- 撇号和引号显示为由多个字符组成的乱码
- `é`、`ü`、`ñ` 等字母显示为 `Ã©`、`Ã¼`、`Ã±`，中文显示为一串看不懂的字符
- 导入失败，并显示"invalid character"或"encoding error"之类的信息
- 第一列表头前面有奇怪的字符（BOM）

## 确认文件的编码

修复之前，先确认文件当前使用的是哪种编码。

**VS Code**：打开文件，右下角的状态栏会显示编码。如果显示 `UTF-8 with BOM`、`GBK`、`Windows 1252` 或 `ISO 8859-1`，就需要转换。

**Python**：

```python
# pip install chardet
import chardet

with open("products.csv", "rb") as f:
    result = chardet.detect(f.read(10_000))
print(result)
# 例如 {'encoding': 'Windows-1252', 'confidence': 0.73}
```

**命令行（Linux/macOS）**：

```bash
file -i products.csv    # 在 macOS 上：file -I products.csv
# products.csv: text/plain; charset=iso-8859-1
```

## 去除 UTF-8 BOM

**BOM**（字节顺序标记）是位于文件最开头的一段隐藏的 3 字节序列（`EF BB BF`）。Windows 上的 Excel 在你使用"另存为 > CSV UTF-8（逗号分隔）"时会添加它。Shopify 和 WooCommerce 能处理它，但有些导入程序和脚本会把这些多出的字节当作第一个列标题的一部分。这样列名就变成了 `﻿Handle` 而不是 `Handle`，工具无法识别。

**在 VS Code 中修复**：
1. 打开文件
2. 点击右下角状态栏中的编码指示
3. 选择"Save with Encoding"
4. 选择 **UTF-8**（不带 BOM）

**在 Excel 中修复**：
Excel 没有保存不带 BOM 的 UTF-8 的选项。不要为了避开 BOM 而使用普通的 **"CSV（逗号分隔）"**：它会用系统的旧编码（简体中文 Windows 上为 GBK）保存，在其他平台上会出现乱码。请保存为"CSV UTF-8"，只有当某个工具需要时，再在 VS Code 中去掉 BOM。

**用 Python 修复**：

```python
# utf-8-sig 读取时去掉 BOM；写入时使用普通 utf-8（不带 BOM）
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

## 把 ANSI、Latin-1 或 Windows-1252 转换为 UTF-8

这些旧编码只覆盖某一个地区的字符：Windows-1252 和 Latin-1 没有中文，GBK 则缺少许多其他语言的字符和符号。而且，一旦工具按 UTF-8 读取文件，这些字符全都会变成乱码。

**在 VS Code 中**：
1. 点击状态栏中的编码标签
2. 选择"Reopen with Encoding"，并选择文件**当前**的编码（例如 `GBK`）；确认文字现在显示正常
3. 再次点击标签，选择"Save with Encoding"，然后选择 **UTF-8**

**在 Python 中**：

```python
# 使用上面确认的编码（简体中文 Excel 导出的 CSV 通常是 gbk）
with open("input.csv", encoding="windows-1252") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

**在 LibreOffice Calc 中**：
打开文件时，LibreOffice 会询问编码。选择正确的源编码。保存时，在对话框中选择"Unicode (UTF-8)"。

## 修复已经写入数据中的乱码（mojibake）

如果乱码已经写进了单元格的值中（因为读错后又重新保存，乱码被写入了文件），仅仅转换编码是修不好的。你需要把乱码还原。

**常见的乱码模式**：

| 你看到的 | 本应是 | 原因 |
|---|---|---|
| `â€™` | `’`（弯撇号） | UTF-8 被当作 Windows-1252 读取 |
| `â€”` | `—`（破折号） | UTF-8 被当作 Windows-1252 读取 |
| `Ã©` | `é` | UTF-8 被当作 Windows-1252 或 Latin-1 读取 |
| `Â£` | `£` | UTF-8 被当作 Windows-1252 或 Latin-1 读取 |

**用 Python 修复（ftfy 库）**：

```python
# pip install ftfy
import ftfy

with open("input.csv", encoding="utf-8") as f:
    content = f.read()

fixed = ftfy.fix_text(content)

with open("output.csv", "w", encoding="utf-8") as f:
    f.write(fixed)
```

**手动修复已知模式**：
在 VS Code 或支持正则表达式的文本编辑器中使用查找和替换，把乱码字符串替换为正确的字符。

## 预防编码问题

- **从 Google 表格导出时**，始终使用文件 > 下载 > CSV。得到的是干净的 UTF-8
- **在 Windows 版 Excel 中**，保存为"CSV UTF-8（逗号分隔）"，而不是使用旧编码的普通"CSV（逗号分隔）"
- **保存后**在 VS Code 中检查文件，状态栏会显示编码
- **用旧版 Excel 打开并重新保存** UTF-8 CSV 时，一定要在保存时明确选择 UTF-8
- **用脚本导出时**，使用 Python 的 `csv` 模块，或指定 `encoding="utf-8"` 的 pandas
