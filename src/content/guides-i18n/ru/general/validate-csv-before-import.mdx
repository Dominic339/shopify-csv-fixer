## Зачем проверять файл перед импортом

Неудачный импорт CSV может быть безобидным (ничего не меняется) или разрушительным (частичные обновления оставляют каталог в несогласованном состоянии). В Shopify ошибка в кавычках обычно останавливает весь импорт и указывает строку, на которой он прервался. В WooCommerce строка со сдвинутыми столбцами может записать неверные значения в существующий товар.

Пять минут проверки перед загрузкой могут сэкономить часы на исправлениях.

---

## Чек-лист перед импортом

### 1. Кодировка: UTF-8

**Что проверить:** файл должен быть в кодировке UTF-8. BOM (метка порядка байтов) в начале не мешает Shopify и WooCommerce, но некоторые инструменты считают его частью названия первого столбца.

**Как проверить:**
- Откройте файл в VS Code. В строке состояния справа внизу должно быть `UTF-8` (или `UTF-8 with BOM`), а не `Windows 1252` или `ISO 8859-1`.
- Если там что-то другое, сначала убедитесь, что текст выглядит правильно (если нет, щёлкните индикатор кодировки и выберите **Открыть повторно с кодировкой**, указав настоящую кодировку файла). Затем снова щёлкните индикатор и выберите **Сохранить с кодировкой → UTF-8**.

**Обычное решение:** в Excel всегда сохраняйте как **CSV UTF-8 (разделитель — запятая)**, а не как обычный CSV.

---

### 2. Строка заголовков: правильные названия, ничего лишнего

**Что проверить:**
- Первая строка содержит названия столбцов точно в том виде, который ожидает платформа.
- В названиях столбцов нет пробелов в начале и в конце.
- Названия столбцов не повторяются.
- В конце нет лишних пустых столбцов.

**Как проверить:**
Откройте файл в текстовом редакторе и внимательно прочитайте строку 1. Сравните её с официальным шаблоном платформы:

- Shopify: посмотрите [шаблон CSV для товаров Shopify](https://help.shopify.com/en/manual/products/import-export/import-products).
- WooCommerce: сравните с примером CSV товаров WooCommerce из панели администратора.
- Amazon: скачайте Inventory Loader или шаблон категории в Seller Central (**Каталог → Добавить товары через загрузку**).

**Частые проблемы:**
- `"Handle "` с пробелом в конце (в Excel его не видно).
- `handle` (строчными) вместо `Handle`.
- Обязательные столбцы полностью отсутствуют.

---

### 3. Обязательные столбцы: все на месте и заполнены

**Что проверить:**
- Все обязательные столбцы платформы есть в заголовке.
- Обязательные поля не пусты ни в одной строке.

**Обязательные поля по платформам (минимум):**

| Платформа | Обязательные столбцы |
|---|---|
| Shopify | Title (плюс Handle при обновлении существующих товаров) |
| WooCommerce | Name, Type (плюс ID или SKU при обновлении существующих товаров) |
| eBay File Exchange | Action, Title, Category, StartPrice, ConditionID |
| Amazon Inventory Loader | sku, product-id, product-id-type, price, item-condition, quantity, add-delete |
| Etsy | Загрузки CSV нет: Etsy только экспортирует CSV, поэтому проверять для импорта нечего |

**Как проверить в Excel:**
1. Включите фильтры (**Данные → Фильтр**).
2. В каждом обязательном столбце отфильтруйте пустые ячейки.
3. Любой пропуск в обязательном поле приведёт к ошибке этой строки.

---

### 4. Одинаковая длина строк

**Что проверить:** в каждой строке должно быть столько же столбцов, сколько в строке заголовков. Неравные строки указывают на:
- Описание или название с незаэкранированными запятыми.
- Поле с переносами строк внутри, которое разбивает строку на несколько.
- Ошибку копирования и вставки, добавившую лишние столбцы.

**Как проверить в Excel (слишком длинные строки):**
1. Найдите первый столбец после последнего заголовка. Если заголовки заканчиваются в столбце T, это столбец U.
2. В пустом столбце далеко справа (например, AAA) введите `=СЧЁТЗ(U2:ZZ2)`.
3. Скопируйте формулу во все строки и отфильтруйте значения больше 0. В этих строках есть лишние поля.

Слишком короткие строки Excel показать не может: отсутствующее поле выглядит так же, как пустое.

**Как проверить в текстовом редакторе:**
В VS Code с расширением Rainbow CSV выполните команду **Rainbow CSV: CSVLint**. Она сообщает о каждой строке, где число полей отличается от заголовка, в том числе о коротких строках.

**Обычное решение:** заключайте в двойные кавычки любое поле с запятыми, кавычками или переносами строк. Если в поле уже есть двойные кавычки, экранируйте каждую, удваивая её (`""`).

---

### 5. Поля в кавычках: правильные и экранированные кавычки

**Что проверить:**
- Поля с запятыми, двойными кавычками или переносами строк заключены в двойные кавычки.
- Каждая двойная кавычка внутри такого поля экранирована удвоением (`""`, а не `\"`).

**Пример правильных кавычек:**
```
Handle,Title,Body HTML
blue-shirt,"Blue T-Shirt, Men's","<p>""Premium"" cotton.</p>"
```

**На что обратить внимание:**
- Поле, которое начинается с `"`, должно заканчиваться `"` в той же логической строке.
- Апострофы экранировать не нужно: `Men's` остаётся как есть. Удваиваются только двойные кавычки.

---

### 6. Нет недопустимых символов в ключевых полях

**Что проверить:**
- Handle/slug содержат только строчные латинские буквы, цифры и дефисы.
- Поля цены содержат только цифры и десятичную точку (без символов валют и разделителей тысяч).
- Поля «да/нет» (например, Published, Featured) используют ожидаемые значения (TRUE/FALSE, yes/no или 1/0 в зависимости от платформы).

**Частые проблемы:**
- `$19.99` в столбце цены (должно быть `19.99`).
- `Blue Shirt` с заглавными буквами и пробелом в столбце handle (должно быть `blue-shirt`).
- Цены вида `19,99` (европейская десятичная запятая) вместо `19.99`.

---

### 7. URL изображений: доступны и в правильном формате

**Что проверить:**
- URL изображений начинаются с `https://` (некоторые платформы отклоняют или пропускают изображения по `http://`).
- В URL нет пробелов (их нужно закодировать как `%20` или удалить).
- Для Shopify: поддерживается до 250 URL изображений на товар. Первая строка с `Image Src` для каждого Handle — главное изображение.
- URL доступны публично (не за входом в аккаунт, не localhost).

---

### 8. Нет пустых строк в конце

**Что проверить:** многие табличные редакторы добавляют пустые строки в конец. Платформы могут счесть пустую строку недопустимой и выдать ошибку.

**Как исправить в Excel:**
1. Нажмите **Ctrl+End**, чтобы перейти к последней используемой ячейке.
2. Если последняя строка пустая (все ячейки пусты), выделите её и несколько строк ниже и удалите их.
3. Сохраните файл.

---

## Стратегия пробной загрузки

Никогда не загружайте весь каталог на 10 000 строк в качестве первой проверки. Вместо этого:

1. Сделайте копию CSV.
2. Оставьте только 5–10 типичных строк (включите хотя бы один товар с вариантами, если они есть).
3. Загрузите выборку в тестовую среду или тестовый магазин.
4. Проверьте, что каждая строка импортировалась правильно.
5. Исправьте ошибки в полном файле.
6. Загрузите полный файл.

Для Shopify: инструмент импорта показывает предпросмотр перед подтверждением и присылает письмо, когда импорт завершён. Прочитайте это письмо, даже если импорт выглядит законченным: часть строк может быть пропущена, а остальные импортируются.

## Инструменты для проверки перед импортом

| Инструмент | Что проверяет |
|---|---|
| **StriveFormats CSV Fixer** | Заголовки для конкретной платформы, кодировку, обязательные поля, кавычки, значения «да/нет» |
| **VS Code с расширением Rainbow CSV** | Наглядное выравнивание столбцов, несовпадающие строки |
| **csvkit (`csvclean`)** | Строки с неправильным числом полей, в командной строке |
| **Google Таблицы Файл → Импортировать** | Как столбцы делятся при выбранном разделителе |
| **Excel Данные → Из текстового/CSV-файла** | Предпросмотр кодировки и разделителя перед загрузкой |

Валидатор не найдёт смысловых ошибок (неверный SKU, неверный ID категории, URL изображения, которое больше не загружается). Для этого нужна пробная загрузка. Но валидаторы находят структурные ошибки, из-за которых импорт не может завершиться.
