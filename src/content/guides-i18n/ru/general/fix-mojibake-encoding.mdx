## Что такое mojibake?

Mojibake — это визуальный мусор, который появляется, когда файл, сохранённый в одной кодировке, открывают или читают в другой. Слово пришло из японского и означает примерно «непонятные символы». По-русски это обычно называют «кракозябрами».

Если в вашем CSV есть такие последовательности, у вас проблема с кодировкой:

| Что вы видите | Что должно быть |
|---|---|
| `â€™` | `’` (типографский апостроф) |
| `â€”` | `—` (длинное тире) |
| `â€œ` | `“` (открывающая кавычка) |
| `Ã©` | `é` (e с ударением) |
| `ï»¿` в начале поля | BOM (невидимая метка) |

## Почему кодировки не совпадают

Современные платформы вроде Shopify, WooCommerce и Amazon ожидают файлы в **UTF-8**. Но многие инструменты создают файлы в других кодировках:

- **Microsoft Excel (Windows)** сохраняет `.csv` в кодировке языка системы (в русской Windows обычно Windows-1251, в западных — Windows-1252 или Latin-1), если вы явно не выберете UTF-8.
- **Старые инструменты выгрузки** могут по умолчанию использовать ISO-8859-1 / Latin-1.
- **Копирование с сайтов** может принести типографские кавычки и тире в виде многобайтовых символов UTF-8, которые ломаются, когда файл читают как Latin-1.

Когда файл UTF-8 читают как Latin-1 или Windows-1252, каждая многобайтовая последовательность распадается на отдельные однобайтовые символы, и получается mojibake. Если такой испорченный текст потом сохранить, мусор становится частью данных.

## Диагностика проблемы

### Как проверить кодировку файла

**На Mac/Linux:**
```
file -I yourfile.csv
# Пример вывода: yourfile.csv: text/plain; charset=utf-8
```

**В Windows (PowerShell):**
```powershell
# Windows PowerShell 5.1; в PowerShell 7 используйте -AsByteStream вместо -Encoding Byte
Get-Content yourfile.csv -Encoding Byte -TotalCount 3
# Если первые 3 байта — 239 187 191 (0xEF 0xBB 0xBF), в файле есть BOM UTF-8.
```

**Быстрая проверка на глаз:** откройте файл в текстовом редакторе (не в Excel) и посмотрите на первый символ и на буквы с диакритикой или кириллицу. Если первая ячейка начинается с `ï»¿` или в описаниях встречается `â€`, кодировка неверна.

### Как понять, какую кодировку выбрать

- Чаще всего испорченные файлы — это **UTF-8, прочитанный как Latin-1 или Windows-1252** (или наоборот).
- Если сам файл в порядке и неверно только отображение, откройте его заново в той кодировке, в которой он на самом деле сохранён, а затем сохраните как **UTF-8**. Последовательности вроде `â€™` обычно означают, что файл в UTF-8 показан как Windows-1252, поэтому откройте его как UTF-8.
- Если мусор остаётся и при открытии файла как UTF-8, он уже записан в данные. Смена кодировки его не уберёт; используйте средство восстановления, например библиотеку Python `ftfy`, или «Найти и заменить».

## Что такое BOM?

BOM в UTF-8 (Byte Order Mark) — это последовательность из трёх байтов (`EF BB BF`), которую некоторые инструменты ставят в начало файлов UTF-8. Блокнот Windows и Excel иногда добавляют её автоматически.

**Почему это важно:** некоторые инструменты импорта читают BOM как настоящие символы в названии первого столбца, превращают `Handle` в `ï»¿Handle` и потом не узнают этот столбец. Shopify и WooCommerce справляются с BOM, но другие инструменты и скрипты могут и не справиться.

## Исправление в Excel

Excel — самая частая причина проблем с кодировкой. Выполните эти шаги точно.

### Выгрузка из Excel в UTF-8

1. Откройте таблицу в Excel.
2. Нажмите **Файл → Сохранить как**.
3. В списке «Тип файла» выберите **CSV UTF-8 (разделитель — запятая) (.csv)**.
   - Этот вариант есть начиная с Excel 2016 в Windows и на Mac.
   - **Не** выбирайте простой «CSV (разделители — запятые)». Он сохраняет в кодировке языка системы.
4. Нажмите **Сохранить**.

### Как заново открыть в Excel файл с «кракозябрами»

Если испорченный файл у вас уже есть:

1. **Не** открывайте его двойным щелчком. Тогда используется язык системы.
2. Откройте пустую книгу Excel.
3. Перейдите в **Данные → Из текстового/CSV-файла**.
4. Выберите файл.
5. В мастере импорта задайте в поле **Источник файла** настоящую кодировку файла: **65001: Юникод (UTF-8)** для файлов UTF-8.
6. Завершите импорт и сохраните как CSV UTF-8.

## Исправление в Google Таблицах

Google Таблицы внутри всегда работают в UTF-8. Риск возникает при скачивании:

1. **Импорт:** перейдите в **Файл → Импортировать → Загрузить** и выберите CSV. Таблицы сами определяют кодировку.
2. **Выгрузка:** перейдите в **Файл → Скачать → Значения, разделённые запятыми (.csv)**. Google Таблицы выгружают UTF-8 без BOM. Это безопасно.

Если Таблицы неправильно показывают полученный файл:

1. Импортируйте его через **Файл → Импортировать**, а не открывайте напрямую.
2. В окне импорта убедитесь, что флажок **Преобразовывать текст в числа, даты и формулы** снят, если у вас есть SKU или штрихкоды.

## Исправление в VS Code (надёжно для любого файла)

VS Code даёт полный контроль над кодировкой и бесплатен:

1. Откройте VS Code и перетащите в него CSV.
2. Посмотрите на строку состояния справа внизу. Там показана определённая кодировка (например, `UTF-8`, `Windows 1252`).
3. Нажмите на метку кодировки.
4. Выберите **«Reopen with Encoding»** и ту кодировку, в которой файл на самом деле сохранён (часто `Cyrillic (Windows 1251)`, `Western (Windows 1252)` или `ISO 8859-1`).
5. Текст должен отобразиться правильно. Если он показывает последовательности вроде `â€™`, а VS Code пишет `Windows 1252`, файл на самом деле в UTF-8: откройте его заново как **UTF-8**.
6. Снова нажмите на метку и выберите **«Save with Encoding → UTF-8»**.

Эти два шага (заново открыть в исходной кодировке, затем сохранить как UTF-8) — самый надёжный способ для любого инструмента.

## Исправление в Блокноте Windows

Для быстрого исправления в Windows (Windows 11 / 10 версии 1903 и новее):

1. Откройте испорченный файл в Блокноте.
2. Перейдите в **Файл → Сохранить как**.
3. В списке **Кодировка** выберите **UTF-8** (не «UTF-8 с BOM»).
4. Сохраните.

> **Примечание:** старые версии Блокнота предлагали только «UTF-8» с BOM, который добавляет невидимую метку. Если в вашем Блокноте нет варианта «UTF-8» без BOM, используйте VS Code.

## Как не портить кодировку при пересохранении

Когда файл очищен, защитите его:

- **Всегда используйте «CSV UTF-8» в Excel**, никогда не простой CSV.
- **Никогда не открывайте CSV в UTF-8 двойным щелчком в Windows.** Windows связывает `.csv` с Excel, а он может открыть файл в кодировке языка системы. Используйте в Excel **Данные → Из текстового/CSV-файла**, где можно выбрать кодировку.
- **Проверяйте кодировку после каждой выгрузки**, например в StriveFormats или из командной строки, перед загрузкой.
- Если инструмент выгрузки вашей платформы всегда даёт Latin-1, перекодируйте файл сразу после скачивания в VS Code или скриптом, прежде чем его править.
