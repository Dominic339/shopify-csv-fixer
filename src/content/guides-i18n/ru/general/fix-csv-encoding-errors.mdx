## Что такое ошибки кодировки в CSV?

Ошибки кодировки возникают, когда байты вашего CSV читаются в неверном наборе символов. Самый частый симптом — **«кракозябры»**: в названиях товаров, описаниях и других полях вместо апострофов, букв с диакритикой, кириллицы или символов валют стоят странные последовательности вроде `â€™`, `Ã©`, `Â£` или `Ð¢Ð¾Ð²Ð°Ñ€`.

Shopify и WooCommerce ожидают **UTF-8**, и для всех остальных платформ это тоже безопасный выбор. Если файл сохранён в другой кодировке (ANSI, Latin-1, Windows-1251, Windows-1252), импортёры либо отклоняют его, либо молча портят символы.

### Частые симптомы

- Апострофы и кавычки превращаются в бессмысленные последовательности из нескольких символов
- Буквы вроде `é`, `ü`, `ñ` отображаются как `Ã©`, `Ã¼`, `Ã±`, а кириллица — как набор `Ð` и `Ñ`
- Импорт завершается ошибкой вроде «invalid character» или «encoding error»
- Перед заголовком первого столбца стоят странные символы (BOM)

## Как определить кодировку файла

Прежде чем исправлять, выясните, в какой кодировке сейчас файл.

**VS Code:** откройте файл. Кодировка показана справа внизу в строке состояния. Если там `UTF-8 with BOM`, `Windows 1251`, `Windows 1252` или `ISO 8859-1`, файл нужно перекодировать.

**Python:**

```python
# pip install chardet
import chardet

with open("products.csv", "rb") as f:
    result = chardet.detect(f.read(10_000))
print(result)
# например, {'encoding': 'Windows-1252', 'confidence': 0.73}
```

**Командная строка (Linux/macOS):**

```bash
file -i products.csv    # в macOS: file -I products.csv
# products.csv: text/plain; charset=iso-8859-1
```

## Как удалить BOM из UTF-8

**BOM** (Byte Order Mark) — это скрытая последовательность из 3 байтов (`EF BB BF`) в самом начале файла. Excel в Windows добавляет её, когда вы выбираете «Сохранить как > CSV UTF-8 (разделитель — запятая)». Shopify и WooCommerce с этим справляются, но некоторые импортёры и скрипты читают лишние байты как часть заголовка первого столбца. Название столбца превращается в `﻿Handle` вместо `Handle`, и инструмент его не узнаёт.

**Исправление в VS Code:**
1. Откройте файл
2. Нажмите на индикатор кодировки в строке состояния справа внизу
3. Выберите «Save with Encoding»
4. Выберите **UTF-8** (без BOM)

**Исправление в Excel:**
Excel не умеет сохранять UTF-8 без BOM. Не переходите ради этого на простой **«CSV (разделители — запятые)»**: он сохраняет в старой кодировке системы (обычно Windows-1251) и портит символы для других платформ. Сохраняйте в «CSV UTF-8», а BOM удаляйте в VS Code, если он мешает какому-то инструменту.

**Исправление на Python:**

```python
# utf-8-sig читает и убирает BOM; запись идёт в обычном utf-8 (без BOM)
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

## Перевод из ANSI, Latin-1 или Windows-1252 в UTF-8

Эти старые кодировки охватывают символы только одного региона: в Windows-1252 и Latin-1 нет кириллицы, а в Windows-1251 нет, например, польских, турецких или азиатских символов. К тому же их символы превращаются в «кракозябры», когда инструмент читает файл как UTF-8.

**В VS Code:**
1. Нажмите на метку кодировки в строке состояния
2. Выберите «Reopen with Encoding» и **текущую** кодировку файла (например, `Windows 1251`); проверьте, что текст теперь читается
3. Снова нажмите на метку, выберите «Save with Encoding» и **UTF-8**

**На Python:**

```python
# Укажите кодировку, которую вы определили выше (для русских файлов ANSI обычно windows-1251)
with open("input.csv", encoding="windows-1252") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

**В LibreOffice Calc:**
При открытии файла LibreOffice спрашивает кодировку. Выберите правильную исходную кодировку. При сохранении выберите в диалоговом окне «Юникод (UTF-8)».

## Как исправить «кракозябры» (mojibake), которые уже в данных

Если «кракозябры» уже записаны в значения ячеек (они попали в файл после неверного чтения и повторного сохранения), одной перекодировки мало. Нужно обратить искажение.

**Частые шаблоны mojibake:**

| Что вы видите | Что должно быть | Причина |
|---|---|---|
| `â€™` | `’` (типографский апостроф) | UTF-8 прочитан как Windows-1252 |
| `â€”` | `—` (длинное тире) | UTF-8 прочитан как Windows-1252 |
| `Ã©` | `é` | UTF-8 прочитан как Windows-1252 или Latin-1 |
| `Â£` | `£` | UTF-8 прочитан как Windows-1252 или Latin-1 |

**Исправление на Python (библиотека ftfy):**

```python
# pip install ftfy
import ftfy

with open("input.csv", encoding="utf-8") as f:
    content = f.read()

fixed = ftfy.fix_text(content)

with open("output.csv", "w", encoding="utf-8") as f:
    f.write(fixed)
```

**Ручное исправление известных шаблонов:**
Используйте «Найти и заменить» в VS Code или в текстовом редакторе с поддержкой регулярных выражений. Замените искажённую последовательность правильным символом.

## Как избежать проблем с кодировкой

- **Выгружайте из Google Таблиц** всегда через Файл > Скачать > CSV. Получается чистый UTF-8
- **В Excel для Windows** сохраняйте как «CSV UTF-8 (разделитель — запятая)», а не простой «CSV (разделители — запятые)», который использует старую кодировку
- **Проверяйте файл** в VS Code после сохранения. Строка состояния подтверждает кодировку
- **Никогда не открывайте и не пересохраняйте** CSV в UTF-8 в старых версиях Excel, не выбрав UTF-8 явно при сохранении
- **Используйте модуль `csv` в Python** или pandas с `encoding="utf-8"` для выгрузок из скриптов
