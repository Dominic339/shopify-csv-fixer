## Что такое файл CSV?

Файл CSV (Comma-Separated Values, значения через запятую) — это обычный текстовый файл, в котором каждая строка является записью, а колонки разделены запятыми. Первая строка содержит названия колонок (строку заголовков). Каждая следующая строка содержит данные.

Вот как выглядит в виде простого текста минимальный CSV с товарами Shopify:

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
red-shirt,Red T-Shirt,Acme,21.99
```

CSV выглядит просто, но Shopify, WooCommerce, Etsy, eBay и Amazon строго следят за деталями формата, которые табличные редакторы могут незаметно испортить. В этом руководстве разобрано каждое важное правило, чтобы импорт проходил с первого раза.

## Строка заголовков

Первая строка любого CSV должна содержать названия колонок (заголовки). По этим названиям платформа при импорте раскладывает данные по нужным полям.

### Правила

- **Пишите названия точно, включая регистр.** Некоторые импортёры по-разному воспринимают `Handle`, `handle` и `HANDLE`, поэтому копируйте заголовки из шаблона платформы.
- **Без пробелов в начале и в конце.** Заголовок `" Title"` (с пробелом в начале) не совпадает с `"Title"`. Данные в этой колонке молча игнорируются.
- **Без повторяющихся заголовков.** Если у двух колонок одно название, большинство парсеров использует только последнюю.
- **На некоторых платформах важен порядок колонок.** Некоторые шаблоны eBay и Amazon ожидают колонки в порядке шаблона, поэтому сохраняйте порядок скачанного шаблона. Shopify позволяет добавлять колонки в любом месте.

### Как проверить

Откройте CSV в простом текстовом редакторе, например в Блокноте (Windows), TextEdit (Mac) или VS Code. Посмотрите на строку 1. В ней должны быть названия через запятую, без пустой строки над ней:

```
Handle,Title,Body (HTML),Vendor,Type,Tags,...
```

Если первая строка начинается с трёх странных символов перед названиями заголовков, в файле есть BOM. Как это исправить, описано ниже в разделе о кодировке.

## Кодировка UTF-8

Кодировка определяет, как символы текста хранятся на диске в виде байтов. Неверная кодировка превращает текст в «кракозябры». Например, типографский апостроф, сохранённый в UTF-8, но прочитанный как Latin-1, превращается в последовательность из трёх символов, похожую на мусор.

### Почему UTF-8

UTF-8 — безопасный выбор для любой платформы электронной коммерции. Shopify и WooCommerce ожидают именно его, а текущие шаблоны eBay указывают его в заголовке Action (`CC=UTF-8`). Сохранение в UTF-8 гарантирует, что:

- Кириллица и буквы с диакритикой отображаются правильно.
- Символы валют и специальная пунктуация не ломаются.
- Импортёр платформы может прочитать файл и не отклонит его.

### С BOM или без

UTF-8 с BOM добавляет в самое начало файла скрытую последовательность из 3 байтов. Excel в Windows записывает её, когда вы выбираете «Сохранить как > CSV UTF-8 (разделитель — запятая)». Shopify и WooCommerce правильно читают файлы с BOM, но некоторые инструменты и скрипты из-за лишних байтов неверно читают заголовок первой колонки.

Как понять, есть ли в файле BOM: откройте его в VS Code и посмотрите на строку состояния справа внизу. Если там написано «UTF-8 with BOM», он есть.

**Исправление в VS Code:** нажмите на индикатор кодировки в строке состояния, выберите «Save with Encoding», затем «UTF-8» (без BOM).

**Исправление в Excel:** Excel не умеет сохранять UTF-8 без BOM. Не переходите на простой «CSV (разделители — запятые)», чтобы его избежать: этот вариант сохраняет файл в старой кодировке системы (часто Windows-1251 или Windows-1252) и портит кириллицу. Оставайтесь на «CSV UTF-8», а BOM удаляйте в VS Code, только если платформа неверно читает первую колонку.

**Исправление на Python:**

```python
# utf-8-sig убирает BOM при чтении; обычный utf-8 пишет без BOM
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

### Кодировка в других программах

**Google Таблицы:** Файл > Скачать > Значения, разделённые запятыми, экспортирует UTF-8 без BOM.

**LibreOffice Calc:** при сохранении в CSV выберите в диалоговом окне «Юникод (UTF-8)».

**Numbers (Mac):** Файл > Экспортировать в > CSV на современных версиях macOS экспортирует UTF-8 без BOM.

## Правила кавычек и запятые внутри значений

Если значение ячейки содержит запятую, заключите всё значение в двойные кавычки. Это стандарт CSV (RFC 4180).

### Простой пример

```
Title,Price,Description
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships in 2 days"
```

Без кавычек парсер видит пять колонок вместо трёх и раскладывает данные не по тем полям.

### Кавычки внутри значения в кавычках

Если значение само содержит двойную кавычку, экранируйте её, удвоив:

```
"She said ""this is great"""
```

Это означает текст: She said "this is great"

### Когда нужны кавычки?

Значение нужно заключить в двойные кавычки, если в нём есть:

- Запятая
- Двойная кавычка
- Перевод строки внутри значения
- HTML-теги (некоторые парсеры неверно читают угловые скобки без кавычек)

Простым значениям вроде `29.99` или `Active` кавычки не нужны. Заключать в кавычки всё подряд не вредно, и многие инструменты делают это автоматически.

### Частые ошибки с кавычками

| Ошибка | Неверно | Верно |
|---|---|---|
| Запятая в значении без кавычек | `Wallet, Brown` | `"Wallet, Brown"` |
| HTML-описание без кавычек | `<p>Great item</p>` | `"<p>Great item</p>"` |
| Перевод строки в значении без кавычек | Две отдельные строки | `"Line1\nLine2"` в одной ячейке |
| Неверное экранирование кавычки внутри | `"She said \"great\""` | `"She said ""great"""` |

## Переводы строк

Переводы строк показывают парсеру, где заканчивается одна строка и начинается следующая. Есть два формата:

| Формат | Байты | Где используется |
|---|---|---|
| CRLF | возврат каретки + перевод строки | Windows, Excel |
| LF | только перевод строки | macOS, Linux, большинство веб-инструментов |

Большинство платформ принимает оба формата. Проблемы возникают, когда они перемешаны: одни строки с CRLF, другие с LF. Из-за этого парсер может увидеть лишние пустые строки или неверно прочитать многострочные значения.

### Как проверить и исправить

Откройте файл в VS Code. В строке состояния будет «CRLF» или «LF». Нажмите, чтобы переключить, и сохраните.

На Python:

```python
with open("input.csv", newline="", encoding="utf-8") as f:
    content = f.read()
# Привести к LF
content = content.replace("\r\n", "\n").replace("\r", "\n")
with open("output.csv", "w", newline="\n", encoding="utf-8") as f:
    f.write(content)
```

## Ошибки, которые чаще всего ломают импорт

**1. Лишние пустые строки**

Многие табличные программы добавляют в конце пустую строку. Платформы пропускают пустые строки или выдают ошибку. Удалите их перед экспортом. В Excel нажмите Ctrl+End, чтобы перейти к последней использованной ячейке. Если она пустая, удалите пустые строки под данными.

**2. Строки с итогами**

Формулы СУММ() внизу листа попадают в CSV как строки товаров. Удалите итоговые строки перед экспортом.

**3. Объединённые ячейки**

Объединённые ячейки экспортируются как значение в первой ячейке и пустота в остальных. Импортёр видит пустые ячейки как незаполненные обязательные поля. Отмените все объединения перед экспортом.

**4. Ячейки с формулами**

Сохраняя CSV, Excel записывает то, что отображает каждая ячейка: текущий результат формулы с её числовым форматом. Формула цены в денежном формате запишется как `29,99 ₽` или `$29.99`, а сломанная — как `#Н/Д` или `#ССЫЛКА!`. Проверьте колонки с формулами на ошибки, а затем через Специальная вставка > Значения превратите их в постоянные значения перед сохранением в CSV.

**5. Пробелы в конце заголовков**

`"Title "` (с пробелом в конце) — это не то же самое, что `"Title"`. Данные этой колонки при импорте молча игнорируются. Уберите пробелы в конце заголовков через «Найти и заменить» (Ctrl+H).

**6. Неверный формат файла с расширением .csv**

Если сохранить файл как `.xlsx`, но назвать его `.csv`, получится файл, который на самом деле не CSV. Откройте его в текстовом редакторе. Если видите двоичные символы, это не настоящий CSV. Экспортируйте его заново в правильном формате.

**7. Кодировка ANSI или Latin-1**

Старые версии Excel иногда сохраняют в ANSI (Windows-1251 или Windows-1252). Названия товаров с кириллицей или диакритикой при импорте превратятся в «кракозябры». При сохранении всегда явно выбирайте UTF-8.

## Разделители: запятые, табуляции и точки с запятой

Название «CSV» подразумевает запятые, но некоторые файлы используют табуляцию (TSV) или точку с запятой. Большинство платформ ожидает файлы, действительно разделённые запятыми. Если загрузить файл с точками с запятой как CSV, каждая строка окажется в одной колонке.

### Как определить разделитель

Откройте файл в простом текстовом редакторе. Посмотрите на первую строку:

- Если названия колонок разделены `,`, файл разделён запятыми (стандартный CSV)
- Если разделены `;`, файл разделён точками с запятой (обычно для Excel с европейскими и русскими региональными настройками)
- Если разделены широкими промежутками, файл разделён табуляцией (TSV)

### Как перевести файл с точками с запятой на запятые

**В Excel:** Файл > Сохранить как > CSV UTF-8 (разделитель — запятая). Если Excel всё равно сохраняет с точками с запятой (потому что в региональных настройках разделителем списка служит точка с запятой), смените разделитель списка в региональных настройках Windows или используйте способ на Python ниже.

**На Python:**

```python
import csv

with open("input.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f, delimiter=";")
    rows = list(reader)

with open("output.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f, delimiter=",")
    writer.writerows(rows)
```

## Опасности автоформатирования в таблицах

Excel и Google Таблицы молча меняют некоторые значения, когда вы открываете или правите CSV. Эти изменения могут испортить данные ещё до того, как вы что-то отредактировали.

### Ведущие нули пропадают из SKU и ID

Excel удаляет ведущие нули из значений, которые считает числами. SKU `00123` становится `123`. Почтовый индекс `02110` становится `2110`.

**Как этого избежать:**

- В Excel: перед импортом CSV используйте мастер импорта текста (Данные > Из текстового/CSV-файла) и задайте тип «Текст» для каждой колонки, где нужно сохранить ведущие нули.
- В Google Таблицах: после импорта задайте затронутой колонке формат «Обычный текст» (Формат > Числа > Обычный текст) до начала правки.
- На Python: всегда читайте колонки SKU и ID с `dtype=str`, если используете pandas, или используйте стандартный модуль `csv`, который никогда не преобразует типы.

### Числа превращаются в экспоненциальную запись

Длинные числовые строки (13-значные штрихкоды, коды EAN) могут отображаться в Excel как `1,23457E+12`. При сохранении в CSV эта запись попадает в файл буквально, и проверка штрихкодов при импорте не проходит.

**Решение:** выделите колонку в Excel, задайте формат «Числовой» с 0 знаков после запятой (не «Экспоненциальный») и сохраните. Можно также поставить перед значением апостроф (это делает его текстом) или задать колонке текстовый формат до вставки значений.

### Даты переводятся в региональный формат

Поле со значением `2024-01-15` может автоматически превратиться в `15.01.2024` или `15 января 2024 г.` в зависимости от региональных настроек. Платформы, ожидающие формат ISO (`YYYY-MM-DD`), отклонят изменённое значение.

**Решение:** после открытия файла выделите колонки с датами и задайте им текстовый формат или используйте модуль `csv` в Python, который читает и пишет без всякого преобразования типов.

### Цены с символом валюты

Excel иногда сохраняет ячейку в денежном формате как `$19.99` вместо `19.99`. Большинство платформ ожидает простые десятичные числа без символа валюты.

**Решение:** в Excel перед сохранением в CSV задайте колонкам с ценами формат «Числовой» (не «Денежный» и не «Финансовый»). Уберите `$`, `EUR` и другие символы, которые уже есть в данных, через «Найти и заменить» (Ctrl+H).

## Пустые строки, запятые в конце и невидимые проблемы

### Лишние пустые строки в конце

Многие инструменты добавляют пустую строку после последней строки данных. Обычно платформы пропускают пустые строки, но некоторые отклоняют их как неверные записи. Всегда удаляйте пустые строки внизу перед экспортом.

В Excel: нажмите Ctrl+End, чтобы перейти к последней использованной ячейке. Если она пустая (пустая строка под данными), выделите эти строки и удалите их (правый щелчок > Удалить).

### Запятые в конце строк

Некоторые инструменты экспорта пишут запятую в конце каждой строки: `value1,value2,`. Это создаёт лишнюю пустую колонку. Большинство парсеров с этим справляется, но строгие валидаторы могут отметить это как проблему структуры.

**Решение:** если каждая строка, включая заголовки, заканчивается лишней запятой, удалите ровно одну запятую в конце каждой строки. Если удалить все, пропадут и настоящие пустые ячейки в конце строки:

```python
with open("input.csv", encoding="utf-8", newline="") as f:
    lines = f.read().splitlines()
with open("output.csv", "w", encoding="utf-8", newline="") as f:
    for line in lines:
        f.write((line[:-1] if line.endswith(",") else line) + "\n")
```

### Невидимые символы

Некоторые инструменты вставляют в значения пробелы нулевой ширины (U+200B) или неразрывные пробелы (U+00A0). В таблице их не видно, но при импорте из-за них заголовки могут не совпасть, а значения — отклоняться.

**Проверка:** откройте файл в VS Code и используйте поиск (Ctrl+F) в режиме регулярных выражений. Ищите `​` или ` `, чтобы найти эти символы.

## Правила отдельных платформ

Каждая платформа добавляет свои требования поверх базового стандарта CSV:

- **Shopify:** колонка Handle группирует строки вариантов. Отсутствующие или неверные Handle ломают группировку товаров.
- **WooCommerce:** использует колонку Type (`simple`, `variable`, `variation`), чтобы задать структуру товара.
- **Etsy:** не поддерживает загрузку CSV. Выгрузка объявлений нужна для правки, резервных копий и переезда, а приложения массовой публикации задают свои колонки.
- **eBay:** требует колонку Action (например, `Add`, `Revise`, `Relist` или `End`) в каждой строке.
- **Amazon:** названия колонок зависят от шаблона категории; скачайте в Seller Central именно шаблон для вашей категории.

## Короткий чек-лист перед импортом

- [ ] Строка 1 — заголовки, над ней нет пустой строки
- [ ] Заголовки точно совпадают с названиями, которые ожидает платформа, включая регистр
- [ ] Нет повторяющихся названий колонок
- [ ] Нет пробелов в начале и в конце заголовков
- [ ] Файл сохранён в UTF-8
- [ ] Значения с запятыми, кавычками или переводами строк заключены в двойные кавычки
- [ ] Нет лишних пустых строк внизу
- [ ] Нет итоговых строк и ячеек с формулами
- [ ] Переводы строк одинаковые (все CRLF или все LF)
- [ ] Расширение файла .csv, а внутри — простой текст через запятую

## Следующий шаг: проверьте файл перед импортом

Когда файл готов, загрузите его в корректор CSV для автоматической проверки. Он проверяет заголовки, отмечает проблемы с кодировкой, находит ошибки, характерные для каждой платформы, и одним щелчком исправляет то, что можно исправить безопасно.
