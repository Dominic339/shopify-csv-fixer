## Как в WooCommerce устроены вариативные товары

В WooCommerce **вариативный товар** — это товар с вариациями, которые можно купить, например футболка размеров S, M и L. В CSV он описывается двумя типами строк:

1. **Родительская строка** — контейнер товара. Значение Type — `variable`.
2. **Строки вариаций** — каждая описывает одну комбинацию параметров, которую можно купить. Значение Type — `variation`.

Вариации связываются с родительским товаром через его SKU или ID.

Если WordPress работает на русском, при экспорте используются русские названия столбцов (например, «Тип» вместо `Type`); импорт распознаёт оба варианта. В этом руководстве указаны английские названия.

---

## Родительская строка

Родительская строка задаёт поля на уровне товара и объявляет, какие атрибуты он использует.

### Основные столбцы родительских строк

| Столбец | Значение | Примечания |
|---|---|---|
| ID | (пусто или существующий ID) | Для новых товаров оставьте пустым |
| Type | `variable` | Должно быть ровно `variable` |
| SKU | `SHIRT-BLUE` | Уникальный SKU родительского товара |
| Name | `Blue Cotton T-Shirt` | Название товара |
| Published | `1` | 1 = опубликован, 0 = личный, -1 = черновик |
| Attribute 1 name | `Size` | Название параметра |
| Attribute 1 value(s) | `Small, Medium, Large` | Все доступные значения через запятую |
| Attribute 1 visible | `1` | Показывать на странице товара |
| Attribute 1 global | `1` | Использовать глобальный (общий) атрибут |

- Для нескольких атрибутов используются последовательно пронумерованные столбцы: `Attribute 1 name`, `Attribute 2 name` и т. д.
- `Regular price` в родительской строке можно оставить пустым или указать самую низкую цену вариации. Реальные цены вариаций указываются в строках вариаций.

---

## Строки вариаций

Каждая строка вариации описывает одну комбинацию параметров, которую можно купить, и должна ссылаться на родительский товар.

### Основные столбцы строк вариаций

| Столбец | Значение | Примечания |
|---|---|---|
| ID | (пусто или существующий ID вариации) | Для новых вариаций оставьте пустым |
| Type | `variation` | Должно быть ровно `variation` |
| SKU | `SHIRT-BLUE-SM` | Уникален для каждой вариации |
| Name | `Blue Cotton T-Shirt` | Должно совпадать с названием родителя |
| Parent | `id:123` или `SHIRT-BLUE` | Связь с родительским товаром по ID или SKU |
| Regular price | `19.99` | Обязательно для каждой вариации |
| Attribute 1 name | `Size` | Должно совпадать с названием атрибута у родителя |
| Attribute 1 value(s) | `Small` | Одно значение для этой конкретной вариации |
| Stock | `50` | Остаток по вариации |
| Weight | `0.3` | В единицах, настроенных в магазине |

### Связь вариаций с родительским товаром

Столбец `Parent` принимает два формата:
- **По ID в базе данных:** `id:123` — если вы знаете ID товара в WooCommerce.
- **По SKU:** `SHIRT-BLUE`, то есть SKU родительского товара как есть. Так удобнее переносить данные; используйте этот вариант для новых товаров, у которых ещё нет ID.

Создавая новые вариативные товары с нуля, укажите в `Parent` SKU родительского товара. Поместите родительскую строку в тот же файл над её вариациями или импортируйте её первой.

## Полный пример: вариативная футболка

```
ID,Type,SKU,Name,Published,Regular price,Parent,Attribute 1 name,Attribute 1 value(s),Attribute 1 visible,Stock
,variable,SHIRT-BLUE,Blue Cotton T-Shirt,1,,,Size,"Small, Medium, Large",1,
,variation,SHIRT-BLUE-SM,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Small,,30
,variation,SHIRT-BLUE-MD,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Medium,,25
,variation,SHIRT-BLUE-LG,Blue Cotton T-Shirt,1,21.99,SHIRT-BLUE,Size,Large,,15
```

> Примечание: `Parent` содержит SKU родительского товара, `SHIRT-BLUE`. Список значений в родительской строке содержит запятые, поэтому он заключён в двойные кавычки.

## Вариации по двум параметрам (размер И цвет)

Чтобы добавить второй атрибут (цвет), добавьте в родительскую строку столбцы Attribute 2, а в каждой вариации заполните оба столбца атрибутов:

**Родитель:**
```
Attribute 1 name: Size
Attribute 1 value(s): Small, Medium
Attribute 2 name: Color
Attribute 2 value(s): Blue, Red
```

**Вариация (Small, Blue):**
```
Attribute 1 name: Size
Attribute 1 value(s): Small
Attribute 2 name: Color
Attribute 2 value(s): Blue
```

Для 2 размеров × 2 цветов нужно 4 строки вариаций.

## Частые ошибки

### Ошибка 1: Type родителя — `simple` вместо `variable`

**Симптом:** вариации создаются, но не отображаются на странице товара. Товар показывается как простой.

**Решение:** в столбце Type родительской строки должно быть `variable` (строчными буквами). Без правильного типа WooCommerce при импорте не превращает простой товар в вариативный.

### Ошибка 2: вариация не связана с родителем

**Симптом:** вариации создаются как отдельные простые товары, а не привязываются к родителю.

**Решение:** убедитесь, что в каждой строке вариации заполнено `Parent`: SKU родительского товара (например, `SHIRT-BLUE`) или его ID в виде `id:123`. Отсутствующие или неверные ссылки создают осиротевшие вариации.

### Ошибка 3: значения атрибутов разделены вертикальной чертой

**Признак:** на странице товара видна одна опция вроде «Small | Medium | Large» вместо отдельных вариантов, или вариации не совпадают ни с одной опцией.

**Решение:** в родительской строке разделите значения запятыми: `Small, Medium, Large`. Вертикальную черту `|` использует панель администратора WooCommerce, а импорт CSV делит значения по запятым. StriveFormats заменит черты на запятые за вас.

### Ошибка 4: название атрибута у родителя и вариации не совпадает

**Симптом:** импорт проходит, но вариации не соответствуют своим атрибутам или появляются не те варианты.

**Решение:** значение `Attribute 1 name` должно быть одинаковым в родительской строке и в каждой строке вариации. `Size` и ` Size` (с пробелом) считаются разными атрибутами.

### Ошибка 5: в строках вариаций нет Regular price

**Симптом:** вариации создаются без цены, и товар отображается как недоступный для покупки.

**Решение:** `Regular price` обязателен в каждой строке вариации. Он не наследуется от родителя.

### Ошибка 6: вариации импортируются раньше родителя

**Симптом:** вариации создаются как осиротевшие товары, потому что ID или SKU родителя ещё не существует.

**Решение:** убедитесь, что в CSV родительская строка стоит перед своими строками вариаций. WooCommerce обрабатывает строки сверху вниз.

## Поведение при обновлении

При повторном импорте уже существующего вариативного товара:

- **Сопоставление по ID:** самый надёжный способ обновления. WooCommerce обновляет существующий товар, если ID совпадает.
- **Сопоставление по SKU:** WooCommerce также может сопоставлять по SKU. Оставьте ID пустым и укажите SKU.
- **Добавление новых вариаций:** включите в файл импорта существующие вариации вместе с новыми. Вариации, которые есть в админке, но отсутствуют в файле, **не** удаляются, хотя это может зависеть от версии WooCommerce и настроек плагина импорта.

Всегда проверяйте обновления на тестовом магазине или с резервной копией, прежде чем импортировать в рабочий магазин.
