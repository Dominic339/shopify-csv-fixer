## Jak WooCommerce modeluje produkty zmienne

W WooCommerce **produkt zmienny** to produkt z wariantami, które można kupić, na przykład koszulka sprzedawana w rozmiarach S, M i L. W pliku CSV zapisuje się go za pomocą dwóch rodzajów wierszy:

1. **Wiersz nadrzędny**: reprezentuje kontener produktu. Type ma wartość `variable`.
2. **Wiersze wariantów**: każdy reprezentuje jedną kombinację opcji, którą można kupić. Type ma wartość `variation`.

Warianty są powiązane z produktem nadrzędnym przez jego SKU lub ID.

Jeśli WordPress działa po polsku, eksport używa polskich nazw kolumn (np. „Typ” zamiast `Type`); importer rozpoznaje obie wersje. W tym przewodniku używamy nazw angielskich.

---

## Wiersz nadrzędny

Wiersz nadrzędny określa pola na poziomie produktu i deklaruje, jakich atrybutów produkt używa.

### Najważniejsze kolumny wierszy nadrzędnych

| Kolumna | Wartość | Uwagi |
|---|---|---|
| ID | (puste lub istniejące ID) | Zostaw puste dla nowych produktów |
| Type | `variable` | Musi mieć dokładnie wartość `variable` |
| SKU | `SHIRT-BLUE` | Unikalny SKU produktu nadrzędnego |
| Name | `Blue Cotton T-Shirt` | Nazwa produktu |
| Published | `1` | 1 = opublikowany, 0 = prywatny, -1 = szkic |
| Attribute 1 name | `Size` | Nazwa wymiaru |
| Attribute 1 value(s) | `Small, Medium, Large` | Wszystkie dostępne wartości, rozdzielone przecinkami |
| Attribute 1 visible | `1` | Pokazuj na stronie produktu |
| Attribute 1 global | `1` | Użyj atrybutu globalnego (wspólnego) |

- Kolejne atrybuty mają kolumny numerowane po kolei: `Attribute 1 name`, `Attribute 2 name` itd.
- `Regular price` wiersza nadrzędnego może zostać pusty albo zawierać najniższą cenę wariantu. Właściwe ceny poszczególnych wariantów znajdują się w wierszach wariantów.

---

## Wiersze wariantów

Każdy wiersz wariantu reprezentuje jedną kombinację opcji, którą można kupić, i musi wskazywać produkt nadrzędny.

### Najważniejsze kolumny wierszy wariantów

| Kolumna | Wartość | Uwagi |
|---|---|---|
| ID | (puste lub istniejące ID wariantu) | Zostaw puste dla nowych wariantów |
| Type | `variation` | Musi mieć dokładnie wartość `variation` |
| SKU | `SHIRT-BLUE-SM` | Unikalny dla każdego wariantu |
| Name | `Blue Cotton T-Shirt` | Powinna być taka sama jak nazwa produktu nadrzędnego |
| Parent | `id:123` lub `SHIRT-BLUE` | Łączy z produktem nadrzędnym przez ID lub SKU |
| Regular price | `19.99` | Wymagana dla każdego wariantu |
| Attribute 1 name | `Size` | Musi być taka sama jak nazwa atrybutu produktu nadrzędnego |
| Attribute 1 value(s) | `Small` | Jedna wartość dla tego konkretnego wariantu |
| Stock | `50` | Stan magazynowy wariantu |
| Weight | `0.3` | W jednostce ustawionej w sklepie |

### Łączenie wariantów z produktem nadrzędnym

Kolumna `Parent` przyjmuje dwa formaty:
- **Przez ID w bazie danych:** `id:123`, gdy znasz ID produktu w WooCommerce.
- **Przez SKU:** `SHIRT-BLUE`, czyli SKU produktu nadrzędnego dokładnie w tej postaci. Jest bardziej przenośne; używaj go przy imporcie nowych produktów, które nie mają jeszcze ID.

Tworząc nowe produkty zmienne od zera, wpisz SKU produktu nadrzędnego w `Parent`. Umieść wiersz nadrzędny w tym samym pliku nad jego wariantami albo zaimportuj go najpierw.

## Pełny przykład: koszulka jako produkt zmienny

```
ID,Type,SKU,Name,Published,Regular price,Parent,Attribute 1 name,Attribute 1 value(s),Attribute 1 visible,Stock
,variable,SHIRT-BLUE,Blue Cotton T-Shirt,1,,,Size,"Small, Medium, Large",1,
,variation,SHIRT-BLUE-SM,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Small,,30
,variation,SHIRT-BLUE-MD,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Medium,,25
,variation,SHIRT-BLUE-LG,Blue Cotton T-Shirt,1,21.99,SHIRT-BLUE,Size,Large,,15
```

> Uwaga: `Parent` zawiera SKU produktu nadrzędnego, `SHIRT-BLUE`. Lista wartości w wierszu nadrzędnym zawiera przecinki, więc jest ujęta w podwójny cudzysłów.

## Warianty dwuwymiarowe (rozmiar ORAZ kolor)

Aby dodać drugi atrybut (kolor), dodaj kolumny Attribute 2 do wiersza nadrzędnego, a w każdym wariancie wypełnij obie kolumny atrybutów:

**Wiersz nadrzędny:**
```
Attribute 1 name: Size
Attribute 1 value(s): Small, Medium
Attribute 2 name: Color
Attribute 2 value(s): Blue, Red
```

**Wariant (Small, Blue):**
```
Attribute 1 name: Size
Attribute 1 value(s): Small
Attribute 2 name: Color
Attribute 2 value(s): Blue
```

Dla 2 rozmiarów × 2 kolorów potrzebujesz 4 wierszy wariantów.

## Częste błędy

### Błąd 1: Type wiersza nadrzędnego to `simple` zamiast `variable`

**Objaw:** warianty powstają, ale nie pojawiają się na stronie produktu. Produkt wyświetla się jako produkt prosty.

**Rozwiązanie:** kolumna Type wiersza nadrzędnego musi mieć wartość `variable` (małymi literami). Bez właściwego typu WooCommerce nie zamieni podczas importu produktu prostego na zmienny.

### Błąd 2: wariant niepowiązany z produktem nadrzędnym

**Objaw:** warianty powstają jako osobne produkty proste zamiast zostać przypisane do produktu nadrzędnego.

**Rozwiązanie:** upewnij się, że każdy wiersz wariantu ma wartość w `Parent`: SKU produktu nadrzędnego (na przykład `SHIRT-BLUE`) albo jego ID zapisane jako `id:123`. Brakujące lub błędne odwołania tworzą osierocone warianty.

### Błąd 3: wartości atrybutów rozdzielone pionowymi kreskami

**Objaw:** strona produktu pokazuje jedną opcję w rodzaju „Small | Medium | Large” zamiast osobnych wyborów albo warianty nie pasują do żadnej opcji.

**Rozwiązanie:** w wierszu nadrzędnym rozdziel wartości przecinkami: `Small, Medium, Large`. Pionowej kreski `|` używa panel WooCommerce, ale importer CSV dzieli wartości na przecinkach. StriveFormats zamienia kreski na przecinki za ciebie.

### Błąd 4: różne nazwy atrybutu w wierszu nadrzędnym i w wariancie

**Objaw:** import się udaje, ale warianty nie pasują do swoich atrybutów albo pojawiają się złe opcje.

**Rozwiązanie:** wartość `Attribute 1 name` musi być identyczna w wierszu nadrzędnym i w każdym wierszu wariantu. `Size` i ` Size` (ze spacją) są traktowane jako różne atrybuty.

### Błąd 5: brak Regular price w wierszach wariantów

**Objaw:** warianty powstają bez ceny, więc produkt wyświetla się jako niedostępny do kupienia.

**Rozwiązanie:** `Regular price` jest wymagana w każdym wierszu wariantu. Nie jest dziedziczona z produktu nadrzędnego.

### Błąd 6: import wariantów przed produktem nadrzędnym

**Objaw:** warianty powstają jako osierocone produkty, bo ID lub SKU produktu nadrzędnego jeszcze nie istnieje.

**Rozwiązanie:** upewnij się, że wiersz nadrzędny znajduje się w pliku CSV przed swoimi wierszami wariantów. WooCommerce przetwarza wiersze od góry do dołu.

## Zachowanie przy aktualizacji

Gdy ponownie importujesz istniejący już produkt zmienny:

- **Dopasowanie po ID:** najbezpieczniejsza metoda. WooCommerce aktualizuje istniejący produkt, jeśli ID się zgadza.
- **Dopasowanie po SKU:** WooCommerce może też dopasowywać po SKU. Zostaw ID puste i podaj SKU.
- **Dodawanie nowych wariantów:** umieść w pliku importu istniejące warianty razem z nowymi. Warianty obecne w panelu, ale nieobecne w pliku, **nie** są usuwane, choć może to zależeć od wersji WooCommerce i ustawień wtyczki importu.

Zawsze testuj aktualizacje w sklepie testowym lub z kopią zapasową, zanim zaimportujesz dane do sklepu produkcyjnego.
