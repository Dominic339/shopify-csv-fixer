## mojibake란?

mojibake는 한 문자 인코딩으로 저장한 파일을 다른 인코딩으로 열거나 읽을 때 나타나는 의미 없는 글자들입니다. 일본어에서 온 말로, 대략 "알아볼 수 없는 문자"라는 뜻입니다. 우리말로는 흔히 "글자 깨짐"이라고 합니다.

CSV에 다음과 같은 문자열이 있다면 인코딩 문제입니다.

| 보이는 글자 | 원래 글자 |
|---|---|
| `â€™` | `’`(오른쪽 작은따옴표) |
| `â€”` | `—`(대시) |
| `â€œ` | `“`(왼쪽 큰따옴표) |
| `Ã©` | `é`(악센트가 있는 e) |
| 필드 맨 앞의 `ï»¿` | BOM(보이지 않는 표시) |

## 인코딩이 어긋나는 이유

Shopify, WooCommerce, Amazon 같은 최신 플랫폼은 **UTF-8** 파일을 기대합니다. 하지만 많은 도구가 다른 인코딩으로 파일을 만듭니다.

- **Microsoft Excel(Windows)은** UTF-8을 직접 고르지 않으면 `.csv`를 시스템 언어의 인코딩(한국어 Windows에서는 CP949, 서구권에서는 Windows-1252나 Latin-1)으로 저장합니다.
- **오래된 내보내기 도구**는 기본으로 ISO-8859-1 / Latin-1을 쓰기도 합니다.
- **웹사이트에서 복사해 붙여 넣으면** 여러 바이트로 된 UTF-8 문자인 둥근 따옴표와 대시가 섞여 들어오고, 파일을 Latin-1로 다루면 이 문자들이 깨집니다.

UTF-8 파일을 Latin-1이나 Windows-1252로 읽으면 여러 바이트로 된 문자열이 1바이트짜리 글자들로 쪼개지면서 mojibake가 생깁니다. 깨진 텍스트를 그대로 저장하면 그 쓰레기 글자가 데이터의 일부가 됩니다.

## 문제 진단하기

### 파일의 인코딩 확인하기

**Mac/Linux:**
```
file -I yourfile.csv
# 출력 예: yourfile.csv: text/plain; charset=utf-8
```

**Windows(PowerShell):**
```powershell
# Windows PowerShell 5.1 기준. PowerShell 7에서는 -Encoding Byte 대신 -AsByteStream 사용
Get-Content yourfile.csv -Encoding Byte -TotalCount 3
# 처음 3바이트가 239 187 191(0xEF 0xBB 0xBF)이면 UTF-8 BOM이 있음
```

**눈으로 빠르게 확인하기:** 파일을 Excel이 아닌 텍스트 편집기로 열고 첫 글자와 악센트가 있는 글자나 한글을 보세요. 첫 셀이 `ï»¿`로 시작하거나 설명에 `â€`가 있다면 인코딩이 잘못된 것입니다.

### 어떤 인코딩을 써야 할지 알아내기

- 깨진 파일의 대부분은 **UTF-8을 Latin-1이나 Windows-1252로 읽은 것**(또는 그 반대)입니다. 한글이라면 UTF-8과 CP949를 혼동한 경우도 흔합니다.
- 파일 자체는 멀쩡하고 표시만 잘못되었다면, 실제로 저장된 인코딩으로 다시 연 다음 **UTF-8**로 저장하세요. `â€™` 같은 문자열은 대개 UTF-8 파일이 Windows-1252로 표시되고 있다는 뜻이므로 UTF-8로 다시 여세요.
- UTF-8로 열어도 쓰레기 글자가 남아 있다면 데이터에 저장된 것입니다. 인코딩을 바꿔도 사라지지 않으니 Python의 `ftfy` 라이브러리 같은 복구 도구나 찾기 및 바꾸기를 쓰세요.

## BOM이란?

UTF-8 BOM(바이트 순서 표시)은 일부 도구가 UTF-8 파일 맨 앞에 붙이는 3바이트 문자열(`EF BB BF`)입니다. Windows 메모장과 Excel이 자동으로 붙이기도 합니다.

**왜 중요한가:** 일부 가져오기 도구는 BOM을 첫 열 이름 안의 실제 글자로 읽어 `Handle`을 `ï»¿Handle`로 만들고, 그 열을 인식하지 못합니다. Shopify와 WooCommerce는 BOM을 처리하지만 다른 도구나 스크립트는 못 할 수도 있습니다.

## Excel에서 고치기

Excel은 인코딩 문제의 가장 흔한 원인입니다. 다음 단계를 정확히 따르세요.

### Excel에서 UTF-8로 내보내기

1. Excel에서 스프레드시트를 엽니다.
2. **파일 → 다른 이름으로 저장**을 클릭합니다.
3. "파일 형식" 목록에서 **CSV UTF-8(쉼표로 분리)(.csv)을** 고릅니다.
   - 이 옵션은 Windows와 Mac의 Excel 2016 이후 버전에 있습니다.
   - 일반 "CSV(쉼표로 분리)"는 고르지 **마세요**. 시스템 언어의 인코딩으로 저장됩니다.
4. **저장**을 클릭합니다.

### 글자가 깨진 파일을 Excel에서 다시 열기

이미 깨진 파일이 있다면:

1. 파일을 두 번 클릭해 열지 **마세요**. 시스템 언어의 인코딩이 쓰입니다.
2. Excel에서 빈 통합 문서를 엽니다.
3. **데이터 → 텍스트/CSV에서**로 갑니다.
4. 파일을 고릅니다.
5. 가져오기 창에서 **파일 원본**을 파일의 실제 인코딩으로 설정합니다(UTF-8 파일은 **65001: 유니코드(UTF-8)**, CP949 파일은 **949: 한국어**).
6. 가져오기를 마친 뒤 CSV UTF-8로 저장합니다.

## Google 스프레드시트에서 고치기

Google 스프레드시트는 내부적으로 항상 UTF-8로 작동합니다. 위험은 다운로드할 때 생깁니다.

1. **가져오기:** **파일 → 가져오기 → 업로드**로 CSV를 고릅니다. 스프레드시트가 인코딩을 자동으로 알아냅니다.
2. **내보내기:** **파일 → 다운로드 → 쉼표로 구분된 값(.csv)으로** 갑니다. Google 스프레드시트는 BOM 없는 UTF-8로 내보내므로 안전합니다.

받은 파일이 스프레드시트에서 깨져 보인다면:

1. 바로 열지 말고 **파일 → 가져오기**로 가져오세요.
2. SKU나 바코드가 있다면 가져오기 창에서 **텍스트를 숫자, 날짜, 수식으로 변환** 옵션이 꺼져 있는지 확인하세요.

## VS Code로 고치기(어떤 파일에도 믿을 만한 방법)

VS Code는 무료이며 인코딩을 완전히 제어할 수 있습니다.

1. VS Code를 열고 CSV 파일을 끌어다 놓습니다.
2. 오른쪽 아래 상태 표시줄을 보세요. 감지된 인코딩(예: `UTF-8`, `Windows 1252`)이 표시됩니다.
3. 인코딩 표시를 클릭합니다.
4. **"Reopen with Encoding"을** 고르고 파일이 실제로 저장된 인코딩(흔히 `Korean (EUC-KR)`, `Western (Windows 1252)`, `ISO 8859-1`)을 선택합니다.
5. 이제 깨진 글자가 제대로 보여야 합니다. VS Code가 `Windows 1252`라고 표시하는데 `â€™` 같은 문자열이 보인다면 파일은 실제로 UTF-8입니다. 이럴 때는 **UTF-8**로 다시 여세요.
6. 표시를 다시 클릭하고 **"Save with Encoding → UTF-8"을** 고릅니다.

이 두 단계(원래 인코딩으로 다시 연 뒤 UTF-8로 저장)는 어떤 도구에서든 가장 믿을 만한 방법입니다.

## Windows 메모장으로 고치기

Windows에서 빠르게 고치려면(Windows 11 / 10 버전 1903 이상):

1. 깨진 파일을 메모장으로 엽니다.
2. **파일 → 다른 이름으로 저장**으로 갑니다.
3. **인코딩** 목록에서 **UTF-8**을 고릅니다("BOM 있는 UTF-8"이 아님).
4. 저장합니다.

> **참고:** 예전 메모장에는 보이지 않는 BOM 표시를 붙이는 BOM 있는 "UTF-8"만 있었습니다. 메모장에 BOM 없는 "UTF-8" 옵션이 없다면 VS Code를 쓰세요.

## 다시 저장할 때 인코딩이 깨지지 않게 하기

파일이 깨끗해졌다면 앞으로는 이렇게 지키세요.

- **Excel에서는 항상 "CSV UTF-8"을 쓰고**, 일반 CSV는 쓰지 마세요.
- **Windows에서 UTF-8 CSV를 두 번 클릭해 다시 열지 마세요.** Windows는 `.csv`를 Excel과 연결하는데, Excel은 시스템 언어의 인코딩으로 열 수 있습니다. 인코딩을 고를 수 있는 Excel의 **데이터 → 텍스트/CSV에서**를 쓰세요.
- **내보낼 때마다 인코딩을 확인하세요.** 업로드하기 전에 StriveFormats 같은 도구나 명령줄로 확인하세요.
- 가져오기 플랫폼의 내보내기 도구가 늘 Latin-1을 만든다면, 다운로드 직후 편집하기 전에 VS Code나 스크립트로 변환하세요.
