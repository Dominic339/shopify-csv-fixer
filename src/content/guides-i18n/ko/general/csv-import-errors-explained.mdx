## CSV 가져오기가 실패하는 이유

모든 쇼핑몰 플랫폼은 CSV를 받기 전에 검증 과정을 거칩니다. 이 과정은 구조(머리글, 열 수), 데이터 유형(숫자, 예/아니요 값, 필수 필드), 업무 규칙(유효한 카테고리 코드, 가격 범위), 인코딩을 확인합니다. 하나라도 통과하지 못하면 가져오기가 완전히 멈추거나 일부 행만 가져오고 나머지는 건너뜁니다.

오류 메시지를 이해하는 것이 깨끗한 가져오기로 가는 가장 빠른 길입니다. 이 가이드는 가장 흔한 오류를 설명합니다.

---

## 구조 오류

이 오류들은 플랫폼이 데이터를 보기도 전에 파일의 형태가 잘못되었다는 뜻입니다.

### "Missing required column" / "Column not found"

플랫폼이 기대한 열 이름이 머리글 행에 없습니다. 흔한 원인:

- 필수 열의 이름을 바꿈(예: `Title` 대신 `product_title`)
- 머리글 앞뒤에 공백이 있음(`Title` 대신 ` Title`)
- 파일에 BOM이 있어 첫 열 이름 앞에 숨은 바이트가 붙음
- 다른 플랫폼의 템플릿을 쓰고 있음

**해결 방법:** 머리글 행을 해당 플랫폼의 공식 템플릿과 비교하세요. 대소문자, 철자, 공백까지 정확히 일치해야 합니다.

### "Column count mismatch" / "Wrong number of columns"

데이터 행의 필드 수가 머리글 행보다 많거나 적습니다. 흔한 원인:

- 값에 따옴표 없는 쉼표가 있음: `Wallet, Brown`은 `"Wallet, Brown"`이어야 합니다
- 따옴표로 감싸지 않은 HTML 설명에 쉼표가 있음(예: `style` 속성 안)
- 일부 행 끝에 쉼표가 하나 더 있음(유령 열이 생김)

**해결 방법:** 텍스트 편집기로 파일을 열고 문제가 있는 행을 보세요. 따옴표로 감싼 값 안의 쉼표는 열을 나누지 않는다는 점을 기억하며 필드 수를 세세요. 쉼표가 있는 값은 모두 큰따옴표로 감싸야 합니다.

### "Unexpected header" / "Unrecognized column"

플랫폼이 인식하지 못하는 열이 파일에 있습니다. 플랫폼은 여분의 열을 무시하므로 대개 막는 오류가 아니라 경고입니다. 다만 더 엄격한 가져오기 도구는 모르는 열을 거부할 수 있으니, 뚜렷한 이유 없이 파일이 실패하면 플랫폼의 템플릿을 확인하세요.

**해결 방법:** 공식 템플릿에 없는 열을 지우거나, 열 이름을 다르게 써야 하는지 확인하세요.

## 필수 필드 오류

### "Required field is blank" / "Field cannot be empty"

필수 열이 머리글에는 있지만 하나 이상의 행에서 값이 비어 있습니다. 자주 비는 필수 필드:

- **Shopify:** 모든 행의 Handle과 각 상품 첫 행의 Title
- **WooCommerce:** 새 상품의 Name과 변형 행의 Parent
- **Etsy(대량 등록 앱):** 앱 템플릿이 필수로 표시한 항목, 흔히 who_made, when_made, is_supply
- **eBay:** Action, 그리고 상품을 추가할 때 Title, Category, StartPrice, ConditionID
- **Amazon(Inventory Loader):** sku, product-id, product-id-type, add-delete, 그리고 오퍼를 추가할 때 price, item-condition, quantity

**해결 방법:** 파일을 필터링하거나 정렬해 필수 열이 빈 행을 찾고 빠진 데이터를 채우세요. 빈칸이 의도된 것이라면(옵션 행이 상품의 값을 이어받는 경우) 플랫폼 규칙을 확인하세요. 예를 들어 Shopify 옵션 행은 Title을 비워 두는 것이 정상입니다.

### "SKU is required"

어떤 파일은 모든 상품을 SKU로 식별합니다. Amazon의 Inventory Loader는 항상 그렇고, 다른 플랫폼의 업데이트 가져오기도 SKU로 행을 연결하는 경우가 많습니다. 그런 곳에서는 SKU 없는 행이 실패합니다.

**해결 방법:** SKU가 필요한 모든 행에 SKU를 넣으세요. 영문자와 숫자만, 공백 없이, 플랫폼 한도 이내(Amazon은 40자)라는 일관된 형식을 쓰세요.

## 데이터 유형과 형식 오류

### "Invalid price" / "Price must be a number"

가격 필드에 숫자가 아닌 값이 있습니다. 흔한 원인:

- 값에 통화 기호가 있음: `19.99` 대신 `$19.99`
- 소수점 구분 기호로 쉼표를 씀: `19.99` 대신 `19,99`(유럽 지역 설정에서 흔함)
- 숫자가 와야 할 곳에 빈 문자열이나 대시가 있음
- Excel이 셀을 통화 형식으로 지정하고 기호까지 내보냄

**해결 방법:** 통화 기호를 지우고 소수점 쉼표를 마침표로 바꾸세요. 저장하기 전에 Excel에서 열 형식을 "숫자"로 지정하세요.

### "Invalid boolean" / "Must be true or false"

예/아니요 필드에 예상치 못한 값이 있습니다. 플랫폼은 이 형식에 엄격합니다.

- **Shopify:** Shopify 자체 템플릿처럼 `true` 또는 `false`를 기대합니다
- **WooCommerce:** `1` / `0`을 씁니다(`Backorders allowed?` 같은 필드는 `notify`도 받습니다)
- **Amazon:** 파일에 따라 다릅니다. 카테고리 템플릿은 Valid Values 탭의 값(대개 `true` / `false`)을 쓰고, Inventory Loader의 `will-ship-internationally`는 `y` / `n` 또는 `1` / `2`를 받습니다

**해결 방법:** 모든 표기(Yes, yes, Y, 1, true)를 각 플랫폼이 기대하는 형식으로 바꾸세요. 스프레드시트의 찾기 및 바꾸기를 쓰세요.

### "Invalid date format"

날짜 필드의 형식이 잘못되었습니다. 대부분의 플랫폼은 `YYYY-MM-DD`를 기대합니다. Excel은 날짜를 `2024. 1. 15.` 같은 지역 형식으로 자동 변환하는 경우가 많습니다.

**해결 방법:** 편집하기 전에 Excel에서 날짜 열을 텍스트 형식으로 지정하거나, 형식을 바꾸지 않는 Python `csv` 모듈을 쓰세요. 저장하기 전에 날짜를 `YYYY-MM-DD`로 바꾸세요.

## 업무 규칙 오류

### "Duplicate SKU" / "Handle already exists"

고유해야 할 식별자가 파일에 두 번 이상 나옵니다. Shopify에서는 옵션을 위해 같은 Handle을 일부러 반복하지만, 관련 없는 두 상품 그룹에 같은 Handle이 있으면 오류입니다. WooCommerce와 Amazon에서 SKU 중복은 항상 문제를 뜻합니다.

**해결 방법:** 식별자 열로 파일을 정렬하고 의도하지 않은 중복을 찾으세요. 수식(`COUNTIF`)으로 정확한 중복을 자동으로 찾을 수 있습니다.

### "Invalid category ID" / "Category not recognized"

사용한 카테고리 코드가 플랫폼의 분류 체계에 없습니다.

- **eBay:** 카테고리 ID는 숫자이며 eBay의 현재 카테고리 트리에 있어야 합니다
- **Amazon:** 브라우즈 노드와 상품 유형은 셀러 센트럴의 현재 분류 체계와 맞아야 합니다
- **Etsy(대량 등록 앱):** 분류 ID는 Etsy API에서 오며 현재 목록과 맞아야 합니다

**해결 방법:** 플랫폼의 공식 카테고리 탐색기나 분류 체계 다운로드에서 올바른 카테고리 ID를 찾으세요. ID는 바뀌므로 오래된 템플릿의 ID는 쓰지 마세요.

## 가져오기 결과의 경고와 막는 오류

대부분의 플랫폼은 **막는 오류**(행이나 파일이 거부됨)와 **경고**(행은 가져오지만 표시됨)를 구분합니다. 차이를 알면 무엇부터 고칠지 정하기 쉽습니다.

| 심각도 | 의미 | 예 |
|---|---|---|
| 막음 | 행이나 파일을 건너뜀 | 필수 필드 누락, 잘못된 열 수 |
| 경고 | 표시와 함께 가져옴 | 인식되지 않는 선택 필드, 긴 설명 |
| 정보 | 안내용 | 필드에 플랫폼 기본값이 들어감 |

다시 업로드하기 전에 막는 오류는 모두 고치세요. 경고는 두 번째 작업에서 다뤄도 되는 경우가 많습니다.
