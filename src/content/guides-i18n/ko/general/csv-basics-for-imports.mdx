## CSV 파일이란?

CSV(Comma-Separated Values, 쉼표로 구분된 값) 파일은 각 행이 하나의 레코드이고 열이 쉼표로 구분된 일반 텍스트 파일입니다. 첫 행에는 열 이름(머리글 행)이 들어가고, 그다음 행마다 데이터가 들어갑니다.

가장 간단한 Shopify 상품 CSV를 텍스트로 보면 다음과 같습니다.

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
red-shirt,Red T-Shirt,Acme,21.99
```

CSV는 단순해 보이지만 Shopify, WooCommerce, Etsy, eBay, Amazon 같은 플랫폼은 스프레드시트가 몰래 망가뜨릴 수 있는 서식 세부 사항에 엄격합니다. 이 가이드는 첫 가져오기에서 문제없이 통과하도록 중요한 규칙을 하나씩 설명합니다.

---

## 머리글 행

모든 CSV의 첫 행에는 열 이름(머리글)이 있어야 합니다. 플랫폼은 가져오기 중에 이 이름을 보고 데이터를 올바른 필드에 연결합니다.

### 규칙

- **대소문자까지 정확히 쓰세요.** 일부 가져오기 도구는 `Handle`, `handle`, `HANDLE`을 다르게 처리하므로 머리글 이름은 플랫폼 템플릿에서 복사하세요.
- **앞뒤에 공백을 넣지 마세요.** `" Title"`(앞에 공백)은 `"Title"`과 일치하지 않습니다. 그 열의 데이터는 아무 경고 없이 무시됩니다.
- **머리글을 중복하지 마세요.** 두 열의 이름이 같으면 대부분의 파서는 마지막 열만 씁니다.
- **열 순서가 중요한 플랫폼도 있습니다.** 일부 eBay와 Amazon 템플릿은 템플릿 순서대로 열이 오기를 기대하므로 다운로드한 템플릿의 순서를 유지하세요. Shopify는 열을 어디에 추가해도 됩니다.

### 확인 방법

CSV를 메모장(Windows), 텍스트 편집기(Mac), VS Code 같은 일반 텍스트 편집기로 열고 1행을 보세요. 위에 빈 행 없이 쉼표로 구분된 이름이 있어야 합니다.

```
Handle,Title,Body (HTML),Vendor,Type,Tags,...
```

첫 줄이 머리글 이름 앞에 이상한 문자 세 개로 시작한다면 파일에 BOM이 있습니다. 고치는 방법은 아래 인코딩 섹션을 참고하세요.

## UTF-8 인코딩

인코딩은 텍스트 문자를 디스크에 바이트로 저장하는 방식입니다. 인코딩이 틀리면 글자가 깨집니다. 예를 들어 UTF-8로 저장한 둥근 아포스트로피를 Latin-1로 읽으면 쓰레기처럼 보이는 세 글자로 바뀝니다.

### UTF-8을 쓰는 이유

UTF-8은 모든 쇼핑몰 플랫폼에서 안전한 선택입니다. Shopify와 WooCommerce는 UTF-8을 기대하며, eBay의 현재 템플릿은 Action 머리글에 이를 표시합니다(`CC=UTF-8`). UTF-8로 저장하면 다음이 보장됩니다.

- 한글과 악센트가 있는 문자가 올바르게 표시됩니다.
- 통화 기호와 특수 문장 부호가 깨지지 않습니다.
- 플랫폼의 가져오기 도구가 파일을 거부하지 않고 읽을 수 있습니다.

### BOM 있음과 없음

BOM이 있는 UTF-8은 파일 맨 앞에 숨겨진 3바이트를 추가합니다. Windows의 Excel에서 "다른 이름으로 저장 > CSV UTF-8(쉼표로 분리)"을 쓰면 이것이 기록됩니다. Shopify와 WooCommerce는 BOM이 있는 파일을 올바르게 읽지만, 일부 도구와 스크립트는 이 추가 바이트 때문에 첫 번째 열 머리글을 잘못 읽습니다.

파일에 BOM이 있는지 확인하는 방법: VS Code에서 파일을 열고 오른쪽 아래 상태 표시줄을 보세요. "UTF-8 with BOM"이라고 나오면 BOM이 있습니다.

**VS Code에서 고치기:** 상태 표시줄의 인코딩 표시를 클릭하고 "Save with Encoding"을 고른 뒤 "UTF-8"(BOM 없음)을 선택하세요.

**Excel에서 고치기:** Excel에는 BOM 없이 UTF-8로 저장하는 옵션이 없습니다. BOM을 피하려고 일반 "CSV(쉼표로 분리)"로 바꾸지 마세요. 이 옵션은 시스템의 예전 인코딩(한국어 Windows에서는 대개 CP949/EUC-KR)으로 저장하므로 다른 플랫폼에서 한글이 깨집니다. "CSV UTF-8"을 유지하고, 플랫폼이 첫 열을 잘못 읽을 때만 VS Code에서 BOM을 제거하세요.

**Python으로 고치기:**

```python
# utf-8-sig는 읽을 때 BOM을 제거하고, 일반 utf-8은 BOM 없이 저장합니다
with open("input.csv", encoding="utf-8-sig") as f:
    content = f.read()
with open("output.csv", "w", encoding="utf-8") as f:
    f.write(content)
```

### 다른 도구의 인코딩

**Google 스프레드시트:** 파일 > 다운로드 > 쉼표로 구분된 값은 BOM 없는 UTF-8로 내보냅니다.

**LibreOffice Calc:** CSV로 저장할 때 대화 상자에서 "유니코드(UTF-8)"를 고르세요.

**Numbers(Mac):** 파일 > 다음으로 내보내기 > CSV는 최신 macOS에서 BOM 없는 UTF-8로 내보냅니다.

## 따옴표 규칙과 값 안의 쉼표

셀 값에 쉼표가 있으면 값 전체를 큰따옴표로 감싸세요. 이것이 CSV 표준(RFC 4180)입니다.

### 기본 예시

```
Title,Price,Description
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships in 2 days"
```

따옴표가 없으면 파서는 세 열이 아니라 다섯 열로 보고 데이터를 엉뚱한 필드에 넣습니다.

### 따옴표로 감싼 값 안의 따옴표

값 안에 큰따옴표가 있으면 따옴표를 두 번 써서 이스케이프하세요.

```
"She said ""this is great"""
```

이것은 She said "this is great"라는 문자열을 나타냅니다.

### 따옴표가 필요한 경우는?

값에 다음이 들어 있으면 큰따옴표로 감싸야 합니다.

- 쉼표
- 큰따옴표
- 값 안의 줄바꿈
- HTML 태그(따옴표가 없으면 꺾쇠괄호를 잘못 읽는 파서도 있습니다)

`29.99`나 `Active` 같은 단순한 값에는 따옴표가 필요 없습니다. 모든 값을 따옴표로 감싸도 해가 없으며 많은 도구가 자동으로 그렇게 합니다.

### 따옴표 관련 흔한 실수

| 실수 | 잘못된 예 | 올바른 예 |
|---|---|---|
| 값에 쉼표, 따옴표 없음 | `Wallet, Brown` | `"Wallet, Brown"` |
| 따옴표 없는 HTML 설명 | `<p>Great item</p>` | `"<p>Great item</p>"` |
| 값에 줄바꿈, 따옴표 없음 | 두 개의 별도 행 | 한 셀에 `"Line1\nLine2"` |
| 안쪽 따옴표를 잘못 이스케이프 | `"She said \"great\""` | `"She said ""great"""` |

## 줄바꿈

줄바꿈은 파서에게 한 행이 어디서 끝나고 다음 행이 어디서 시작하는지 알려 줍니다. 형식은 두 가지입니다.

| 형식 | 바이트 | 사용하는 곳 |
|---|---|---|
| CRLF | 캐리지 리턴 + 라인 피드 | Windows, Excel |
| LF | 라인 피드만 | macOS, Linux, 대부분의 웹 도구 |

대부분의 플랫폼은 두 형식을 모두 받습니다. 문제는 일부 행은 CRLF, 일부 행은 LF처럼 섞여 있을 때 생깁니다. 줄바꿈이 섞이면 파서가 빈 행을 더 보거나 여러 줄 값을 잘못 읽을 수 있습니다.

### 확인하고 고치는 방법

VS Code에서 파일을 열면 상태 표시줄에 "CRLF" 또는 "LF"가 보입니다. 클릭해 바꾼 뒤 저장하세요.

Python으로:

```python
with open("input.csv", newline="", encoding="utf-8") as f:
    content = f.read()
# LF로 통일
content = content.replace("\r\n", "\n").replace("\r", "\n")
with open("output.csv", "w", newline="\n", encoding="utf-8") as f:
    f.write(content)
```

## 가져오기를 망가뜨리는 가장 흔한 실수

**1. 여분의 빈 행**

많은 스프레드시트 도구가 끝에 빈 행을 추가합니다. 플랫폼은 빈 행을 건너뛰거나 오류를 냅니다. 내보내기 전에 지우세요. Excel에서는 Ctrl+End를 눌러 마지막으로 사용한 셀로 이동하세요. 그 셀이 비어 있으면 데이터 아래의 빈 행을 삭제하세요.

**2. 요약 행이나 합계 행**

시트 아래쪽의 SUM() 수식은 CSV에서 상품 행으로 나타납니다. 내보내기 전에 요약 행을 지우세요.

**3. 병합된 셀**

병합된 셀은 첫 셀에 값이 있고 나머지는 빈 칸으로 내보내집니다. 가져오기 도구는 빈 셀을 비어 있는 필수 필드로 봅니다. 내보내기 전에 모든 셀 병합을 해제하세요.

**4. 수식 셀**

Excel은 CSV를 저장할 때 각 셀에 표시된 내용, 즉 수식의 현재 결과를 그 표시 형식 그대로 기록합니다. 통화 형식인 가격 수식은 `₩29,990`이나 `$29.99`처럼, 깨진 수식은 `#N/A`나 `#REF!`로 기록됩니다. 수식 열에 오류가 없는지 확인하고, CSV로 저장하기 전에 선택하여 붙여넣기 > 값으로 고정 값으로 바꾸세요.

**5. 머리글 이름 끝의 공백**

`"Title "`(끝에 공백)은 `"Title"`과 다릅니다. 그 열의 데이터는 가져올 때 경고 없이 무시됩니다. 찾기 및 바꾸기(Ctrl+H)로 머리글 끝의 공백을 지우세요.

**6. 확장자만 .csv인 다른 형식의 파일**

`.xlsx`로 저장하고 이름만 `.csv`로 바꾸면 실제로는 CSV가 아닌 파일이 됩니다. 텍스트 편집기로 열어 보세요. 바이너리 문자가 보이면 진짜 CSV가 아닙니다. 올바른 저장 형식으로 다시 내보내세요.

**7. ANSI 또는 Latin-1 인코딩**

예전 Excel은 가끔 ANSI(한국어 Windows에서는 CP949)로 저장합니다. 한글이나 악센트가 있는 상품명은 가져올 때 깨집니다. 저장할 때는 항상 UTF-8을 명시적으로 고르세요.

## 구분 기호: 쉼표, 탭, 세미콜론

"CSV"라는 이름은 쉼표를 뜻하지만, 탭(TSV)이나 세미콜론을 쓰는 파일도 있습니다. 대부분의 쇼핑몰 플랫폼은 실제로 쉼표로 구분된 파일을 기대합니다. 세미콜론으로 구분된 파일을 CSV처럼 업로드하면 각 행이 한 열로 나타납니다.

### 구분 기호 알아내기

일반 텍스트 편집기로 파일을 열고 첫 행을 보세요.

- 열 이름이 `,`로 구분되어 있으면 쉼표로 구분된 파일(표준 CSV)입니다
- `;`로 구분되어 있으면 세미콜론으로 구분된 파일입니다(유럽 지역 설정의 Excel에서 흔합니다)
- 넓은 간격으로 구분되어 있으면 탭으로 구분된 파일(TSV)입니다

### 세미콜론 파일을 쉼표 구분으로 바꾸기

**Excel에서:** 파일 > 다른 이름으로 저장 > CSV UTF-8(쉼표로 분리). 그래도 Excel이 세미콜론으로 저장한다면(시스템 지역 설정이 목록 구분 기호로 세미콜론을 쓰기 때문), Windows 지역 설정에서 목록 구분 기호를 바꾸거나 아래 Python 방법을 쓰세요.

**Python으로:**

```python
import csv

with open("input.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f, delimiter=";")
    rows = list(reader)

with open("output.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f, delimiter=",")
    writer.writerows(rows)
```

## 스프레드시트 자동 서식의 위험

Excel과 Google 스프레드시트 같은 프로그램은 CSV를 열거나 편집할 때 일부 값을 몰래 바꿉니다. 아무것도 편집하기 전에 데이터가 망가질 수 있습니다.

### SKU와 ID의 앞자리 0이 사라짐

Excel은 숫자로 해석한 값에서 앞자리 0을 지웁니다. `00123` 같은 SKU는 `123`이 되고, `02110` 같은 우편번호는 `2110`이 됩니다.

**막는 방법:**

- Excel: CSV를 가져오기 전에 텍스트 가져오기(데이터 > 텍스트/CSV에서)를 쓰고, 앞자리 0을 유지해야 하는 열의 형식을 "텍스트"로 설정하세요.
- Google 스프레드시트: 가져온 뒤 편집하기 전에 해당 열을 "일반 텍스트"로 지정하세요(서식 > 숫자 > 일반 텍스트).
- Python: pandas를 쓴다면 SKU와 ID 열은 항상 `dtype=str`로 읽거나, 형식을 바꾸지 않는 표준 `csv` 모듈을 쓰세요.

### 숫자가 지수 표기로 바뀜

긴 숫자열(13자리 바코드, EAN 코드)은 Excel에서 `1.23457E+12`로 보일 수 있습니다. CSV로 저장하면 이 표기가 그대로 기록되어 가져올 때 바코드 검증에 실패합니다.

**해결 방법:** Excel에서 해당 열을 선택해 소수 자릿수 0인 "숫자" 형식("지수"가 아님)으로 지정한 뒤 저장하세요. 또는 값 앞에 작은따옴표를 붙이거나(텍스트로 처리됨) 값을 붙여 넣기 전에 열을 텍스트 형식으로 지정하세요.

### 날짜가 지역 형식으로 바뀜

`2024-01-15` 값이 지역 설정에 따라 `2024-01-15`가 아닌 `2024. 1. 15.` 같은 형식으로 자동 변환될 수 있습니다. ISO 형식(`YYYY-MM-DD`)을 기대하는 플랫폼은 바뀐 값을 거부합니다.

**해결 방법:** 파일을 연 뒤 날짜 열을 선택해 텍스트 형식으로 지정하거나, 형식 변환 없이 읽고 쓰는 Python `csv` 모듈을 쓰세요.

### 통화 기호가 붙은 가격

Excel은 통화 형식의 셀을 `19.99`가 아니라 `$19.99`로 저장하기도 합니다. 대부분의 플랫폼은 통화 기호 없는 단순한 소수를 기대합니다.

**해결 방법:** CSV로 저장하기 전에 Excel에서 가격 열을 "숫자" 형식("통화"나 "회계"가 아님)으로 지정하세요. 데이터에 이미 `$`, `EUR` 같은 기호가 있다면 찾기 및 바꾸기(Ctrl+H)로 지우세요.

## 빈 행, 줄 끝 쉼표, 보이지 않는 문제

### 끝의 여분 빈 행

많은 도구가 마지막 데이터 행 뒤에 빈 행을 추가합니다. 플랫폼은 대개 빈 행을 건너뛰지만, 잘못된 레코드로 거부하는 곳도 있습니다. 내보내기 전에 아래쪽 빈 행은 항상 지우세요.

Excel에서: Ctrl+End를 눌러 마지막으로 사용한 셀로 이동하세요. 그 셀이 비어 있다면(데이터 아래의 빈 행) 해당 행을 선택해 삭제하세요(마우스 오른쪽 클릭 > 삭제).

### 줄 끝 쉼표

일부 내보내기 도구는 모든 행 끝에 쉼표를 씁니다(`value1,value2,`). 그러면 비어 있는 여분의 열이 생깁니다. 대부분의 파서는 문제없이 처리하지만, 엄격한 검증 도구는 구조 문제로 표시할 수 있습니다.

**해결 방법:** 머리글을 포함한 모든 행이 여분의 쉼표로 끝난다면 각 줄 끝에서 쉼표를 정확히 하나만 지우세요. 모두 지우면 행 끝에 있는 실제 빈 셀까지 사라집니다.

```python
with open("input.csv", encoding="utf-8", newline="") as f:
    lines = f.read().splitlines()
with open("output.csv", "w", encoding="utf-8", newline="") as f:
    for line in lines:
        f.write((line[:-1] if line.endswith(",") else line) + "\n")
```

### 보이지 않는 문자

일부 도구는 셀 값 안에 폭 없는 공백(U+200B)이나 줄 바꿈 없는 공백(U+00A0)을 넣습니다. 스프레드시트에서는 보이지 않지만 가져올 때 머리글이 일치하지 않거나 값이 거부되는 원인이 됩니다.

**확인:** VS Code에서 파일을 열고 정규식 모드로 찾기(Ctrl+F)를 쓰세요. `​` 또는 ` `를 검색하면 이런 문자를 찾을 수 있습니다.

## 플랫폼별 규칙

각 플랫폼은 기본 CSV 표준 위에 자체 요구 사항을 더합니다.

- **Shopify:** Handle 열이 옵션 행을 묶습니다. Handle이 없거나 잘못되면 상품 묶음이 깨집니다.
- **WooCommerce:** Type 열(`simple`, `variable`, `variation`)로 상품 구조를 정합니다.
- **Etsy:** CSV 업로드가 없습니다. 상품 내보내기는 편집, 백업, 이전용이며 대량 등록 앱은 자체 열을 씁니다.
- **eBay:** 모든 행에 Action 열(`Add`, `Revise`, `Relist`, `End` 등)이 필요합니다.
- **Amazon:** 열 이름이 상품 카테고리 템플릿마다 다릅니다. 셀러 센트럴에서 내 카테고리에 맞는 템플릿을 그대로 다운로드하세요.

## 가져오기 전 빠른 체크리스트

- [ ] 1행이 머리글이고 그 위에 빈 행이 없음
- [ ] 머리글이 플랫폼이 기대하는 열 이름과 대소문자까지 정확히 일치함
- [ ] 열 이름이 중복되지 않음
- [ ] 머리글 이름 앞뒤에 공백이 없음
- [ ] 파일을 UTF-8로 저장함
- [ ] 쉼표, 따옴표, 줄바꿈이 있는 값을 큰따옴표로 감쌈
- [ ] 아래쪽에 여분의 빈 행이 없음
- [ ] 요약 행이나 수식 셀이 없음
- [ ] 줄바꿈이 일관됨(모두 CRLF 또는 모두 LF)
- [ ] 확장자가 .csv이고 파일이 쉼표로 구분된 일반 텍스트임
