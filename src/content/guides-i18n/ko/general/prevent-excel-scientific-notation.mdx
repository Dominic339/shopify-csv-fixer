## 왜 이런 일이 생기나요

Excel은 재무 데이터를 위해 만들어졌습니다. 셀 값이 숫자처럼 보이면 숫자 형식으로 바꿉니다. 이 때문에 쇼핑몰 CSV 파일에서 두 가지 문제가 생깁니다.

1. **지수 표기:** `4006381333931` 같은 13자리 EAN 바코드가 `4.00638E+12`가 됩니다. CSV로 내보내면 `4.00638E+12`가 그대로 기록되어 바코드로서 쓸 수 없게 됩니다.
2. **사라진 앞자리 0:** `00714` 같은 SKU가 `714`가 되고, `01234565` 같은 8자리 EAN-8이 `1234565`가 됩니다. 가져오기 플랫폼은 잘못된 값을 받습니다.

이런 변환은 조용히 일어납니다. 가져오기가 실패하거나 재고 수량이 맞지 않을 때까지 모를 수도 있습니다.

---

## 영향을 받는 필드

긴 숫자열이나 앞자리 0이 있는 필드는 모두 위험합니다.

- **바코드:** EAN-13, UPC-A, EAN-8, ISBN-13, ASIN
- 앞자리에 0이 있는 **SKU**(의류나 공구 카탈로그에서 흔함)
- 제조사 품번을 그대로 쓴 **옵션 SKU**
- Shopify의 **Variant Barcode** 열
- **Amazon ASIN / FNSKU**(영숫자지만 일부는 숫자만 있음)
- WooCommerce의 **SKU** 열

## 예방: 데이터를 입력하기 전에 열을 텍스트로 지정하기

가장 안전한 방법은 무엇이든 입력하거나 붙여 넣기 전에 열을 **텍스트**로 지정하는 것입니다.

### Excel에서(새 시트)

1. 바코드나 SKU가 들어갈 열 전체를 선택합니다(예: 열 문자 `C`를 클릭해 C열 선택).
2. 마우스 오른쪽 클릭 → **셀 서식**.
3. **범주** 목록에서 **텍스트**를 고릅니다.
4. **확인**을 클릭합니다.
5. 이제 값을 입력하거나 붙여 넣습니다. Excel은 값을 텍스트로 다루고 그대로 유지합니다.

> **중요:** 숫자를 입력한 *다음에* 셀을 텍스트로 지정해도 변환은 되돌려지지 않습니다. 먼저 서식을 지정하고 그다음에 데이터를 입력해야 합니다. 미리 서식을 지정한 열에 붙여 넣을 때는 원본의 숫자 서식이 따라오지 않도록 **값만** 붙여 넣으세요(Ctrl+Shift+V 또는 선택하여 붙여넣기 → 값).

### Excel에서(앞에 작은따옴표 붙이기)

셀 몇 개만 빠르게 처리하려면 숫자 앞에 작은따옴표(`'`)를 입력하세요.

```
'4006381333931
```

Excel은 `'`로 시작하는 모든 값을 텍스트로 다룹니다. 작은따옴표는 셀 값에 저장되지 않고 숫자만 저장됩니다. 셀 단위로는 쓸 만하지만 데이터가 많으면 번거롭습니다.

## 기존 파일 고치기: 가져오기 마법사로 CSV 열기

Excel이 이미 바코드를 망가뜨린 CSV가 있다면 두 번 클릭해 열지 말고 가져오기 마법사를 쓰세요.

### Excel 2016 이상(가져오기 및 변환)

1. 빈 통합 문서를 엽니다.
2. **데이터 → 텍스트/CSV에서**로 갑니다.
3. CSV 파일을 고릅니다.
4. 미리 보기 창이 열립니다. 바코드나 SKU 열을 보세요. 지수 표기로 보인다면 형식이 자동으로 "정수"로 감지된 것입니다.
5. **데이터 변환**을 클릭합니다(Power Query 편집기가 열림).
6. 문제가 있는 열을 선택합니다.
7. **홈** 탭의 **데이터 형식** 목록에서 **텍스트**를 고릅니다. Power Query가 물으면 **현재 항목 바꾸기**를 클릭하세요. 그러면 형식 변경이 자동 숫자 변환을 대신하고 원래 숫자가 유지됩니다.
8. 닫기 및 로드.
9. **파일 → 다른 이름으로 저장 → CSV UTF-8**로 다시 CSV로 내보냅니다.

### Excel(예전 텍스트 가져오기 마법사)

예전 마법사를 쓸 수 있다면:

1. **데이터 → 텍스트에서**로 가거나, 파일 확장자를 `.csv`에서 `.txt`로 바꾼 뒤 **파일 → 열기**로 엽니다. 그러면 마법사가 시작됩니다.
2. 마법사의 **3단계**에서 열을 선택하고 데이터 형식을 **텍스트**로 지정합니다.
3. 가져오기를 마칩니다.

## 저장된 CSV의 지수 표기 고치기

이미 `4.00638E+12` 같은 값이 든 CSV 파일이 있다면:

### 방법 A: 값을 다시 입력하기(작은 파일)

CSV 파일 자체에 `4.00638E+12`가 들어가면 빠진 자릿수는 파일에 더 이상 없으므로 텍스트 편집기로는 되살릴 수 없습니다. 가진 기록을 보고 올바른 값을 다시 입력하는 수밖에 없으며, 이는 많아야 몇 행 정도에서만 현실적입니다.

### 방법 B: 원본에서 다시 만들기

원래 데이터가 데이터베이스, PIM, 공급업체 파일에 있다면 Excel로 열지 말고 다시 내보내세요. 많은 공급업체 포털은 `.xlsx`로 다운로드할 수 있습니다. 그 파일을 열어 열을 텍스트로 지정한 다음 CSV로 저장하세요.

### 방법 C: 수식으로 되돌리기

통합 문서가 아직 Excel에서 열려 있다면(또는 .xlsx로 저장했다면) Excel이 `4006381333931` 같은 전체 숫자를 아직 갖고 있고 지수 표기로만 보여 주는 것일 수 있습니다.

1. 보조 열을 추가합니다.
2. `=TEXT(A2, "0")`로 숫자를 지수 표기가 없는 텍스트로 바꿉니다.
3. 보조 열을 복사해 원래 열에 **값**으로 붙여 넣습니다.
4. 보조 열을 지웁니다.
5. CSV로 저장합니다.

> 이 방법은 Excel이 아직 전체 숫자를 저장하고 있을 때만 통합니다. 값이 잘렸다면(유효 숫자 15자리 초과) 정밀도는 영영 사라졌으므로 원본에서 데이터를 다시 받아야 합니다.

## Google 스프레드시트에서는

Google 스프레드시트에도 같은 숫자 변환 문제가 있습니다.

- **붙여 넣기 전에 일반 텍스트로 지정:** 열 선택 → **서식 → 숫자 → 일반 텍스트**.
- **파일 → 가져오기로 가져오기:** 가져오기 창에서 **텍스트를 숫자, 날짜, 수식으로 변환** 옵션을 꺼서 코드가 텍스트로 남게 하고, 가져온 뒤 바코드가 맞는지 확인하세요.
- **기존 값 고치기:** Excel과 마찬가지로 `=TEXT(A2, "0")`를 쓰세요.

---

## Excel에서 CSV로 안전하게 내보내기

열을 고치거나 올바르게 서식을 지정했다면:

1. **파일 → 다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)(.csv)**.
2. 이 형식은 여러 시트를 지원하지 않는다는 경고가 나올 수 있습니다. **예/현재 형식 유지**를 클릭하세요.
3. **확인하려고 CSV를 Excel에서 다시 열지 마세요**: 텍스트 편집기(VS Code, Notepad++)로 바코드가 지수 표기가 아니라 일반 숫자인지 확인하세요.
