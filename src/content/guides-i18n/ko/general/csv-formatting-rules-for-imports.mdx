## 쇼핑몰 플랫폼이 따르는 CSV 표준

대부분의 쇼핑몰 플랫폼(Shopify, WooCommerce, eBay, Etsy의 내보내기)은 일반적인 CSV 표준인 **RFC 4180**을 따르는 파일을 기대합니다. 이 표준은 행, 열, 따옴표, 줄바꿈의 구조를 정확히 정의합니다. 예외는 Amazon의 Inventory Loader로, 탭으로 구분된 텍스트(.txt)를 받습니다.

이 가이드는 가져오기 성공에 영향을 주는 모든 규칙을 다룹니다. 하나라도 어기면 구문 분석 오류, 잘못된 열 연결, 눈에 띄지 않는 데이터 손상이 생깁니다.

---

## 규칙 1: 구분자는 쉼표

열은 쉼표로 구분하세요. 세미콜론(유럽 지역 설정의 Excel에서 흔함), 탭(TSV 형식), 세로 막대(`|`)는 쓰지 마세요.

**올바름:**

```
Handle,Title,Vendor,Variant Price
blue-shirt,Blue T-Shirt,Acme,19.99
```

**잘못됨(세미콜론):**

```
Handle;Title;Vendor;Variant Price
blue-shirt;Blue T-Shirt;Acme;19.99
```

Excel이 기본으로 세미콜론을 쓴다면(지역 설정이 소수점 구분 기호로 쉼표를 쓰기 때문) 시스템의 목록 구분 기호를 쉼표로 바꾸거나, 항상 쉼표로 구분된 파일을 만드는 Google 스프레드시트에서 내보내세요.

---

## 규칙 2: 첫 행은 머리글만

1행에는 열 이름만 있어야 하고 다른 것은 없어야 합니다. 위에 빈 행, 제목 행, 병합된 머리글 셀이 없어야 합니다.

**올바름:**

```
Handle,Title,Variant Price
```

**잘못됨:**

```
Product Export -- June 2026
Handle,Title,Variant Price
```

플랫폼은 1행을 머리글로 읽습니다. 1행에 머리글이 아닌 내용이 있으면 그것이 열 이름으로 처리되어 모든 머리글이 맞지 않게 됩니다.

예외가 두 가지 있습니다. Amazon 카테고리 템플릿에는 열 이름 위에 템플릿 행이 있고, eBay 템플릿은 `Info` 행으로 시작할 수 있습니다. 이 행들은 다운로드한 템플릿 그대로 두세요.

---

## 규칙 3: 머리글은 정확해야 함

열 이름은 플랫폼이 기대하는 이름과 정확히 일치해야 합니다.

- **대소문자를 맞추세요:** 일부 가져오기 도구는 `Handle`, `handle`, `HANDLE`을 서로 다른 열로 봅니다
- **앞뒤 공백 금지:** ` Title`(앞에 공백)은 `Title`과 일치하지 않습니다
- **머리글 안의 줄바꿈 금지:** 머리글 셀은 한 줄이어야 합니다
- **머리글 중복 금지:** 두 열의 이름이 같으면 대부분의 파서는 마지막 열만 씁니다

---

## 규칙 4: 쉼표, 따옴표, 줄바꿈에는 따옴표가 필수

셀 값에 쉼표, 큰따옴표, 줄바꿈이 있으면 값 전체를 큰따옴표로 감싸세요.

**올바름:**

```
"Leather Wallet, Brown",29.99,"Handmade in the USA, ships free"
```

**따옴표로 감싼 값 안의 따옴표 이스케이프:** 안쪽 따옴표를 두 번 쓰세요.

```
"She said ""great product"""
```

이것은 She said "great product"를 나타냅니다.

| 상황 | 올바른 형식 |
|---|---|
| 쉼표가 있는 값 | `"value, with comma"` |
| 큰따옴표가 있는 값 | `"value ""with"" quotes"` |
| HTML이 있는 값 | `"<p>Description here</p>"` |
| 줄바꿈이 있는 값 | `"Line one\nLine two"`(따옴표 안) |
| 단순한 숫자 | `19.99`(따옴표 필요 없음) |

---

## 규칙 5: UTF-8 인코딩

파일은 **UTF-8**로 저장하세요. Excel의 "CSV UTF-8" 옵션은 BOM(바이트 순서 표시)을 추가합니다. Shopify와 WooCommerce는 문제없이 읽지만, 플랫폼이 첫 열을 인식하지 못하면 BOM을 제거하세요.

- UTF-8은 한글, 악센트가 있는 문자, 기호, 모든 언어를 처리합니다
- 예전 인코딩(CP949, Windows-1252, ISO 8859-1)은 가져올 때 이런 문자를 깨뜨립니다
- ANSI, Latin-1, Windows-1252 파일은 악센트가 있는 문자, 둥근 따옴표, 통화 기호를 깨진 글자로 만듭니다

**확인:** VS Code에서 파일을 열면 상태 표시줄에 인코딩이 보입니다. `EUC-KR`, `Windows 1252`, `ISO 8859-1`이 아니라 `UTF-8`(또는 `UTF-8 with BOM`)이어야 합니다.

---

## 규칙 6: 일관된 줄바꿈

파일 전체에서 CRLF(`\r\n`, Windows)나 LF(`\n`, Unix/macOS) 중 하나만 쓰세요. 절대 섞지 마세요.

줄바꿈이 섞이면 일부 파서가 데이터 행 사이에 빈 행이 있다고 보거나 여러 줄 값에서 열 수를 잘못 셉니다.

**VS Code에서 확인:** 상태 표시줄에 `CRLF` 또는 `LF`가 보입니다. 클릭해 줄바꿈을 바꾼 뒤 저장하세요.

---

## 규칙 7: 레코드당 한 행(여러 행 상품이 있는 플랫폼 제외)

각 행은 하나의 레코드지만, 여러 플랫폼에서 상품 하나가 여러 행에 걸칩니다.

- **Shopify:** 옵션 행과 추가 이미지 행은 상품의 `Handle`을 반복합니다
- **WooCommerce:** 변형마다 자체 행이 있으며 `Parent`로 가변 상품에 연결됩니다
- **eBay:** 옵션이 있는 상품은 부모 행 아래에 `Relationship` 행을 더합니다
- **Amazon:** 부모 상품과 자식 상품은 별도의 행이며 부모 SKU로 연결됩니다

플랫폼 문서가 설명하는 구조를 따르고, 그 밖에서는 행을 합치거나 나누지 마세요.

---

## 규칙 8: 빈 행 금지

데이터 행 사이나 뒤의 빈 행은 파서가 다음과 같이 동작하게 만듭니다.

- 가져오기에 빈 레코드를 넣음
- 상품 수를 잘못 셈
- 첫 번째 빈 행에서 처리를 멈춤(일부 플랫폼)

저장하기 전에 모든 빈 행을 지우세요. Excel에서 `Ctrl+End`를 누르면 마지막으로 사용한 셀로 이동합니다. 그 셀이 데이터보다 뒤에 있다면 지워야 할 빈 행이 있다는 뜻입니다.

---

## 규칙 9: 요약 행이나 수식 행 금지

상품 데이터가 아닌 행은 모두 제거하세요.

- 아래쪽의 합계·소계 행
- SUM() 수식 행
- 데이터 아래에 적은 메모나 안내
- 구역 구분선

이런 행은 가져올 때 상품 레코드로 나타나 형식 오류(숫자가 와야 할 곳에 텍스트, 빠진 필수 필드 등)를 일으킵니다.

---

## 규칙 10: 병합된 셀 금지

Excel의 병합된 셀은 왼쪽 위 셀에 값이 있고 나머지는 빈 문자열로 내보내집니다. 가져오기 도구는 첫 행 이후의 모든 행에서 필수 필드가 빠졌다고 봅니다.

**해결 방법:** 모두 선택 → 셀 병합 해제 → CSV로 저장하기 전에 빈 셀을 알맞은 값으로 채우세요.

---

## 빠른 검증 체크리스트

- [ ] 쉼표로 구분됨(세미콜론이나 세로 막대가 아님. Amazon 파일은 탭으로 구분됨)
- [ ] 1행에는 열 머리글만 있고 위에 빈 행이 없음
- [ ] 머리글이 플랫폼이 기대하는 열 이름과 정확히 일치함(대소문자와 공백)
- [ ] 열 이름이 중복되지 않음
- [ ] 쉼표나 따옴표가 있는 값을 큰따옴표로 감쌈
- [ ] 파일 인코딩이 UTF-8임
- [ ] 줄바꿈이 일관됨(모두 CRLF 또는 모두 LF)
- [ ] 파일 어디에도 빈 행이 없음
- [ ] 요약 행, 수식 행, 병합된 셀이 없음
- [ ] 파일 확장자가 `.csv`이고 일반 텍스트임(`.xlsx`를 `.csv`로 이름만 바꾼 것이 아님)
