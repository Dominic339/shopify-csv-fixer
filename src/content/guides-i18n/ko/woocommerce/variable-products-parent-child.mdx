## WooCommerce가 가변 상품을 표현하는 방식

WooCommerce에서 **가변 상품**은 구매할 수 있는 변형이 있는 상품입니다. 예를 들어 S, M, L 사이즈로 판매하는 티셔츠가 그렇습니다. CSV에서는 두 종류의 행으로 표현합니다.

1. **상위 행**: 상품 컨테이너를 나타냅니다. Type은 `variable`입니다.
2. **변형 행**: 각 행이 구매할 수 있는 옵션 조합 하나를 나타냅니다. Type은 `variation`입니다.

변형은 상위 상품의 SKU 또는 ID로 상위 상품과 연결됩니다.

WordPress를 한국어로 쓰고 있다면 내보내기 파일의 열 이름이 한국어로 나옵니다(예: `Type` 대신 "유형"). 가져오기 도구는 두 가지 이름을 모두 인식합니다. 이 가이드에서는 영어 열 이름을 사용합니다.

---

## 상위 행

상위 행은 상품 수준의 필드를 정하고, 상품이 어떤 속성을 쓰는지 선언합니다.

### 상위 행의 주요 열

| 열 | 값 | 참고 |
|---|---|---|
| ID | (비워 두거나 기존 ID) | 새 상품은 비워 두세요 |
| Type | `variable` | 정확히 `variable`이어야 합니다 |
| SKU | `SHIRT-BLUE` | 고유한 상위 SKU |
| Name | `Blue Cotton T-Shirt` | 상품명 |
| Published | `1` | 1 = 게시됨, 0 = 비공개, -1 = 임시글 |
| Attribute 1 name | `Size` | 옵션 축의 이름 |
| Attribute 1 value(s) | `Small, Medium, Large` | 사용 가능한 모든 값, 쉼표로 구분 |
| Attribute 1 visible | `1` | 상품 페이지에 표시 |
| Attribute 1 global | `1` | 전역(공유) 속성 사용 |

- 속성이 여러 개면 차례로 번호를 매긴 열을 씁니다: `Attribute 1 name`, `Attribute 2 name` 등.
- 상위 행의 `Regular price`는 비워 두거나 변형 중 가장 낮은 가격을 넣을 수 있습니다. 실제 변형별 가격은 변형 행에 넣습니다.

---

## 변형 행

각 변형 행은 구매할 수 있는 옵션 조합 하나를 나타내며, 반드시 상위 상품과 연결되어야 합니다.

### 변형 행의 주요 열

| 열 | 값 | 참고 |
|---|---|---|
| ID | (비워 두거나 기존 변형 ID) | 새 변형은 비워 두세요 |
| Type | `variation` | 정확히 `variation`이어야 합니다 |
| SKU | `SHIRT-BLUE-SM` | 변형마다 고유 |
| Name | `Blue Cotton T-Shirt` | 상위 상품명과 같아야 합니다 |
| Parent | `id:123` 또는 `SHIRT-BLUE` | ID 또는 SKU로 부모 상품에 연결 |
| Regular price | `19.99` | 변형마다 필수 |
| Attribute 1 name | `Size` | 상위 상품의 속성 이름과 같아야 합니다 |
| Attribute 1 value(s) | `Small` | 이 변형에 해당하는 값 하나 |
| Stock | `50` | 변형별 재고 수량 |
| Weight | `0.3` | 스토어에 설정된 단위 |

### 변형을 상위 상품과 연결하기

`Parent` 열에는 두 가지 형식을 쓸 수 있습니다.
- **데이터베이스 ID로:** `id:123`. WooCommerce 상품 ID를 알고 있을 때 씁니다.
- **SKU로:** `SHIRT-BLUE`, 즉 부모 상품의 SKU를 그대로 씁니다. 옮기기 쉬워서 아직 ID가 없는 새 상품을 가져올 때 쓰면 좋습니다.

새 변형 상품을 처음부터 만들 때는 `Parent`에 부모 상품의 SKU를 넣으세요. 부모 행은 같은 파일에서 변형들보다 위에 두거나 먼저 가져오세요.

## 전체 예시: 가변 티셔츠

```
ID,Type,SKU,Name,Published,Regular price,Parent,Attribute 1 name,Attribute 1 value(s),Attribute 1 visible,Stock
,variable,SHIRT-BLUE,Blue Cotton T-Shirt,1,,,Size,"Small, Medium, Large",1,
,variation,SHIRT-BLUE-SM,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Small,,30
,variation,SHIRT-BLUE-MD,Blue Cotton T-Shirt,1,19.99,SHIRT-BLUE,Size,Medium,,25
,variation,SHIRT-BLUE-LG,Blue Cotton T-Shirt,1,21.99,SHIRT-BLUE,Size,Large,,15
```

> 참고: `Parent`에는 부모 상품의 SKU인 `SHIRT-BLUE`가 들어갑니다. 부모의 값 목록에 쉼표가 있으므로 큰따옴표로 감쌉니다.

## 2차원 변형(사이즈와 색상)

두 번째 속성(색상)을 추가하려면 상위 행에 Attribute 2 열을 넣고, 각 변형에는 두 속성의 열을 모두 넣으세요.

**상위 행:**
```
Attribute 1 name: Size
Attribute 1 value(s): Small, Medium
Attribute 2 name: Color
Attribute 2 value(s): Blue, Red
```

**변형(Small, Blue):**
```
Attribute 1 name: Size
Attribute 1 value(s): Small
Attribute 2 name: Color
Attribute 2 value(s): Blue
```

사이즈 2개 × 색상 2개라면 변형 행이 4개 필요합니다.

## 흔한 실수

### 실수 1: 상위 행의 Type이 `variable`이 아니라 `simple`

**증상:** 변형은 만들어지지만 상품 페이지에 나타나지 않습니다. 상품이 단순 상품으로 표시됩니다.

**해결 방법:** 상위 행의 Type 열은 `variable`(소문자)이어야 합니다. 올바른 유형이 아니면 WooCommerce는 가져오기 중에 단순 상품을 가변 상품으로 바꾸지 않습니다.

### 실수 2: 변형이 상위 상품과 연결되지 않음

**증상:** 변형이 상위 상품에 붙지 않고 독립된 단순 상품으로 만들어집니다.

**해결 방법:** 모든 변형 행의 `Parent`에 값이 있는지 확인하세요. 부모 상품의 SKU(예: `SHIRT-BLUE`) 또는 `id:123` 형식의 ID입니다. 참조가 없거나 잘못되면 부모 없는 변형이 생깁니다.

### 실수 3: 속성 값을 세로 막대로 구분

**증상:** 상품 페이지에 개별 선택지 대신 "Small | Medium | Large" 같은 선택지 하나만 보이거나, 변형이 어떤 선택지와도 맞지 않습니다.

**해결 방법:** 부모 행에서 값을 쉼표로 구분하세요: `Small, Medium, Large`. 세로 막대 `|`는 WooCommerce 관리 화면에서 쓰는 구분자이지만, CSV 가져오기는 쉼표로 값을 나눕니다. StriveFormats가 세로 막대를 쉼표로 바꿔 줍니다.

### 실수 4: 상위 행과 변형의 속성 이름이 다름

**증상:** 가져오기는 성공하지만 변형이 속성과 맞지 않거나 엉뚱한 옵션이 나타납니다.

**해결 방법:** `Attribute 1 name` 값은 상위 행과 모든 변형 행에서 똑같아야 합니다. `Size`와 ` Size`(앞에 공백)는 서로 다른 속성으로 처리됩니다.

### 실수 5: 변형 행에 Regular price가 없음

**증상:** 변형이 가격 없이 만들어져 상품을 구매할 수 없는 상태로 표시됩니다.

**해결 방법:** `Regular price`는 모든 변형 행에서 필수입니다. 상위 상품에서 물려받을 수 없습니다.

### 실수 6: 상위 상품보다 변형을 먼저 가져옴

**증상:** 상위 상품의 ID나 SKU가 아직 없어서 변형이 상위 없는 상품으로 만들어집니다.

**해결 방법:** CSV에서 상위 행이 해당 변형 행보다 앞에 오도록 하세요. WooCommerce는 행을 위에서 아래로 처리합니다.

## 업데이트 시 동작

이미 있는 가변 상품을 다시 가져올 때:

- **ID로 매칭:** 가장 안전한 업데이트 방법입니다. ID가 일치하면 WooCommerce가 기존 상품을 업데이트합니다.
- **SKU로 매칭:** WooCommerce는 SKU로도 매칭할 수 있습니다. ID는 비워 두고 SKU를 넣으세요.
- **새 변형 추가:** 기존 변형을 새 변형과 함께 가져오기 파일에 넣으세요. 관리자 화면에는 있지만 가져오기 파일에 없는 변형은 삭제되지 **않습니다**. 다만 WooCommerce 버전과 가져오기 플러그인 설정에 따라 다를 수 있습니다.

운영 스토어에 가져오기 전에 항상 스테이징 스토어나 백업이 있는 상태에서 업데이트를 테스트하세요.
