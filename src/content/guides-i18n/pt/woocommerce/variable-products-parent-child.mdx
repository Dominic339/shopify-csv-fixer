## Como o WooCommerce modela produtos variáveis

No WooCommerce, um **produto variável** é um produto com variações que podem ser compradas, por exemplo uma camiseta vendida nos tamanhos P, M e G. No CSV, ele é representado por dois tipos de linha:

1. **Linha principal**: representa o contêiner do produto. O Type é `variable`.
2. **Linhas de variação**: cada uma representa uma combinação de opções que pode ser comprada. O Type é `variation`.

As variações são ligadas ao produto principal pelo SKU ou pelo ID dele.

Se o seu WordPress está em português, a exportação usa nomes de coluna em português (por exemplo, "Tipo" em vez de `Type`); o importador reconhece os dois. Este guia usa os nomes em inglês.

---

## A linha principal

A linha principal define os campos do produto e declara quais atributos ele usa.

### Colunas principais das linhas principais

| Coluna | Valor | Observações |
|---|---|---|
| ID | (vazio ou ID existente) | Deixe vazio para produtos novos |
| Type | `variable` | Deve ser exatamente `variable` |
| SKU | `SHIRT-BLUE` | SKU principal único |
| Name | `Blue Cotton T-Shirt` | Nome do produto |
| Published | `1` | 1 = publicado, 0 = rascunho |
| Attribute 1 name | `Size` | Nome da dimensão |
| Attribute 1 value(s) | `Small \| Medium \| Large` | Lista de todos os valores disponíveis separados por barras verticais |
| Attribute 1 visible | `1` | Mostrar na página do produto |
| Attribute 1 global | `1` | Usar atributo global (compartilhado) |

- Vários atributos usam colunas numeradas em sequência: `Attribute 1 name`, `Attribute 2 name` etc.
- O `Regular price` da linha principal pode ficar vazio ou receber o menor preço entre as variantes. Os preços reais de cada variação ficam nas linhas de variação.

---

## Linhas de variação

Cada linha de variação representa uma combinação de opções que pode ser comprada e precisa estar ligada ao produto principal.

### Colunas principais das linhas de variação

| Coluna | Valor | Observações |
|---|---|---|
| ID | (vazio ou ID de variação existente) | Deixe vazio para variações novas |
| Type | `variation` | Deve ser exatamente `variation` |
| SKU | `SHIRT-BLUE-SM` | Único para cada variação |
| Name | `Blue Cotton T-Shirt` | Deve ser igual ao nome do principal |
| Parent | `id:123` ou `sku:SHIRT-BLUE` | Liga ao principal por ID ou SKU |
| Regular price | `19.99` | Obrigatório em cada variação |
| Attribute 1 name | `Size` | Deve ser igual ao nome do atributo no principal |
| Attribute 1 value(s) | `Small` | Um único valor para esta variação específica |
| Stock | `50` | Estoque de cada variação |
| Weight | `0.3` | Na unidade configurada na loja |

### Ligar variações ao produto principal

A coluna `Parent` aceita dois formatos:
- **Por ID do banco de dados:** `id:123`. Use quando souber o ID do produto no WooCommerce.
- **Por SKU:** `sku:SHIRT-BLUE`. É mais portátil; use ao importar produtos novos que ainda não têm ID.

Ao criar produtos variáveis do zero, use o formato `sku:PARENT_SKU`. Importe primeiro a linha principal (ou inclua-a no mesmo arquivo, acima das variações).

## Exemplo completo: camiseta variável

```
ID,Type,SKU,Name,Published,Regular price,Attribute 1 name,Attribute 1 value(s),Attribute 1 visible,Stock
,variable,SHIRT-BLUE,Blue Cotton T-Shirt,1,,Size,Small | Medium | Large,1,
,variation,SHIRT-BLUE-SM,Blue Cotton T-Shirt,1,19.99,Size,Small,,30
,variation,SHIRT-BLUE-MD,Blue Cotton T-Shirt,1,19.99,Size,Medium,,25
,variation,SHIRT-BLUE-LG,Blue Cotton T-Shirt,1,21.99,Size,Large,,15
```

> Observação: a coluna `Parent` foi omitida aqui para simplificar. Na prática, as linhas de variação devem incluir `Parent: sku:SHIRT-BLUE`.

## Variações em duas dimensões (tamanho E cor)

Para adicionar um segundo atributo (cor), inclua as colunas de Attribute 2 na linha principal e as duas colunas de atributo em cada variação:

**Principal:**
```
Attribute 1 name: Size
Attribute 1 value(s): Small | Medium
Attribute 2 name: Color
Attribute 2 value(s): Blue | Red
```

**Variação (Small, Blue):**
```
Attribute 1 name: Size
Attribute 1 value(s): Small
Attribute 2 name: Color
Attribute 2 value(s): Blue
```

São necessárias 4 linhas de variação para 2 tamanhos × 2 cores.

## Erros comuns

### Erro 1: o Type do principal é `simple` em vez de `variable`

**Sintoma:** as variações são criadas, mas não aparecem na página do produto. O produto é exibido como produto simples.

**Solução:** a coluna Type da linha principal deve ser `variable` (em minúsculas). Sem o tipo correto, o WooCommerce não converte um produto simples em variável na importação.

### Erro 2: variação não ligada ao principal

**Sintoma:** as variações são criadas como produtos simples independentes, em vez de ficarem vinculadas ao principal.

**Solução:** garanta que toda linha de variação tenha um valor na coluna `Parent` no formato `sku:PARENT_SKU` ou `id:123`. Referências ao principal ausentes ou malformadas criam variações órfãs.

### Erro 3: valores do atributo não separados por barras verticais na linha principal

**Sintoma:** a página do produto mostra só uma opção no menu suspenso, ou o botão "Adicionar ao carrinho" não aparece.

**Solução:** na linha principal, liste todos os valores possíveis do atributo separados por ` | ` (espaço, barra vertical, espaço): `Small | Medium | Large`. O WooCommerce usa essa lista para preencher o menu suspenso.

### Erro 4: nome do atributo diferente entre principal e variação

**Sintoma:** a importação termina, mas as variações não correspondem aos atributos, ou aparecem opções erradas.

**Solução:** o valor de `Attribute 1 name` deve ser idêntico na linha principal e em todas as linhas de variação. `Size` e ` Size` (com espaço) são tratados como atributos diferentes.

### Erro 5: Regular price ausente nas linhas de variação

**Sintoma:** as variações são criadas sem preço, e o produto aparece como indisponível para compra.

**Solução:** `Regular price` é obrigatório em todas as linhas de variação. Ele não é herdado do principal.

### Erro 6: importar as variações antes do principal

**Sintoma:** as variações são criadas como produtos órfãos porque o ID ou SKU do principal ainda não existe.

**Solução:** garanta que a linha principal apareça antes das linhas de variação no CSV. O WooCommerce processa as linhas de cima para baixo.

## Comportamento na atualização

Ao reimportar um produto variável que já existe:

- **Correspondência por ID:** o método de atualização mais seguro. O WooCommerce atualiza o produto existente se o ID corresponder.
- **Correspondência por SKU:** o WooCommerce também pode buscar por SKU. Deixe o ID vazio e informe o SKU.
- **Adicionar variações novas:** inclua as variações existentes no arquivo de importação junto com as novas. Variações que estão no painel mas não no arquivo **não** são excluídas, mas isso pode variar conforme a versão do WooCommerce e as configurações do plugin de importação.

Sempre teste as atualizações em uma loja de testes ou com um backup antes de importar em produção.
