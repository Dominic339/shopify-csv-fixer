## Why Pre-Import Validation Matters

A failed CSV import can range from harmless (nothing changes) to destructive (partial updates leave your catalog in an inconsistent state). On Shopify, a quoting error usually stops the whole import and names the line it failed on. On WooCommerce, a row whose columns have shifted can write the wrong values into an existing product.

A five-minute validation check before uploading can save hours of cleanup.

---

## The Pre-Import Checklist

### 1. Encoding: UTF-8

**What to check:** The file must be encoded in UTF-8. A BOM (Byte Order Mark) at the start is fine for Shopify and WooCommerce, but some tools read it as part of the first column name.

**How to check:**
- Open the file in VS Code. The bottom-right status bar should say `UTF-8` (or `UTF-8 with BOM`), not `Windows 1252` or `ISO 8859-1`.
- If it shows anything else, first make sure the text looks right (if it doesn't, click the encoding label and choose **Reopen with Encoding** with the file's real encoding). Then click the label again and choose **Save with Encoding → UTF-8**.

**Common fix:** In Excel, always save as **CSV UTF-8 (Comma delimited)**, not plain CSV.

---

### 2. Header row: correct names, no extras

**What to check:**
- The first row contains column names exactly as the platform expects.
- No leading or trailing spaces in column names.
- No duplicate column names.
- No extra blank columns at the end.

**How to check:**
Open the file in a text editor and read line 1 carefully. Compare against the platform's official template:

- Shopify: check the [Shopify product CSV template](https://help.shopify.com/en/manual/products/import-export/import-products).
- WooCommerce: compare against the WooCommerce sample product CSV from your admin.
- Amazon: download the Inventory Loader or category template from Seller Central (**Catalog → Add Products via Upload**).

**Common issues:**
- `"Handle "` with a trailing space (invisible in Excel).
- `handle` (lowercase) instead of `Handle`.
- Missing required columns entirely.

---

### 3. Required columns: all present and non-empty

**What to check:**
- All required columns for the platform are present in the header.
- Required fields are not empty for any row.

**Platform required fields (minimal set):**

| Platform | Required columns |
|---|---|
| Shopify | Title (plus Handle when updating existing products) |
| WooCommerce | Name, Type (plus ID or SKU when updating existing products) |
| eBay File Exchange | Action, Title, Category, StartPrice, ConditionID |
| Amazon Inventory Loader | sku, product-id, product-id-type, price, item-condition, quantity, add-delete |
| Etsy | No CSV upload: Etsy only exports CSV, so there is nothing to validate for import |

**How to check in Excel:**
1. Apply filters (**Data → Filter**).
2. For each required column, filter for blank cells.
3. Any blanks in required fields will cause that row to fail.

---

### 4. Row length consistency

**What to check:** Every row must have the same number of columns as the header row. Unequal rows indicate:
- A description or title with unescaped commas.
- A field with embedded newlines that breaks the row into multiple lines.
- A copy-paste error that inserted extra columns.

**How to check in Excel (rows that are too long):**
1. Find the first column after your last header. If your headers end in column T, that is column U.
2. In an empty column far to the right (for example AAA), add `=COUNTA(U2:ZZ2)`.
3. Copy it down to all rows and filter for values above 0. Those rows have extra fields.

Excel can't show rows that are too short, because a missing field looks the same as an empty one.

**How to check in a text editor:**
In VS Code with the Rainbow CSV extension, run the **Rainbow CSV: CSVLint** command. It reports every row whose field count differs from the header, including short rows.

**Common fix:** Wrap any field that contains commas, quotes, or newlines in double quotes. If the field already contains double quotes, escape each one by doubling it (`""`).

---

### 5. Quoted fields: correct quoting and escaped quotes

**What to check:**
- Fields containing commas, double quotes, or newlines are wrapped in double quotes.
- Any double quote inside a quoted field is escaped by doubling it (`""` not `\"`).

**Example of correct quoting:**
```
Handle,Title,Body HTML
blue-shirt,"Blue T-Shirt, Men's","<p>""Premium"" cotton.</p>"
```

**What to look for:**
- Fields that start with `"` must end with `"` on the same logical line.
- Apostrophes need no escaping: `Men's` is fine as it is. Only double quotes are doubled.

---

### 6. No illegal characters in key fields

**What to check:**
- Handles/slugs contain only lowercase letters, numbers, and hyphens.
- Price fields contain only numbers and a decimal point (no currency symbols, no thousands separators).
- Boolean fields (e.g., Published, Featured) use the expected values (TRUE/FALSE, yes/no, or 1/0, depending on your platform).

**Common problems:**
- `$19.99` in a price column (should be `19.99`).
- `Blue Shirt` with capitals and a space in a handle column (should be `blue-shirt`).
- Prices like `19,99` (European decimal convention) instead of `19.99`.

---

### 7. Image URLs: reachable and correct format

**What to check:**
- Image URLs start with `https://` (some platforms reject or skip `http://` images).
- URLs do not contain spaces (spaces must be URL-encoded as `%20` or removed).
- For Shopify: up to 250 image URLs are supported per product. The first `Image Src` row per Handle is the primary image.
- URLs are publicly accessible (not behind login, not localhost).

---

### 8. No trailing blank rows

**What to check:** Many spreadsheet tools add blank rows at the end. Platforms may treat a blank row as an invalid row and generate an error.

**How to fix in Excel:**
1. Press **Ctrl+End** to go to the last used cell.
2. If the last row is blank (all empty cells), select from that row to a few rows below and delete them.
3. Save the file.

## Sample Upload Strategy

Never upload your full 10,000-row catalog as a first test. Instead:

1. Make a copy of your CSV.
2. Keep only 5–10 representative rows (include at least one variant product if applicable).
3. Upload the sample to a test environment or a staging store.
4. Verify each row was imported correctly.
5. Fix any errors in the full file.
6. Upload the full file.

For Shopify: the importer shows a preview before you confirm and emails you when the import finishes. Read that email even if the import looks done, because some rows can be skipped while the rest import.

## Tools for Pre-Import Validation

| Tool | What it checks |
|---|---|
| **StriveFormats CSV Fixer** | Platform-specific headers, encoding, required fields, quoting, boolean values |
| **VS Code with Rainbow CSV extension** | Visual column alignment, mismatched rows |
| **csvkit (`csvclean`)** | Rows with the wrong number of fields, on the command line |
| **Google Sheets File → Import** | How the columns split with a chosen separator |
| **Excel Data → From Text/CSV** | Encoding and delimiter preview before loading |

A validator cannot catch semantic errors (wrong SKU, wrong category ID, an image URL that no longer loads). Those require a sample upload. But validators do catch the structural errors that stop an import from completing.
